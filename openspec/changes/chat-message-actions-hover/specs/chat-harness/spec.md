## ADDED Requirements

### Requirement: UI 走查消息操作行显隐
`make ui-walk` SHALL 在真实浏览器里以计算样式证明 chat-web「消息线程」操作行的显隐规则；「可见」的判据 SHALL 是该行计算样式的 `opacity`（`0` 或 `1`），不以元素是否可见、可点或可聚焦作判据（不透明度为 0 的元素在这些判据下仍算可见）。

- **既有步骤的悬停前置**：走查里凡点击消息操作行按钮的既有步骤（对话步骤里的 `重新生成` 与 `从此处分叉`，临时空间步骤里的 `撤回`）SHALL 在点击之前先把鼠标移到所有消息之外（焦点不在该行内）并断言该行 `opacity` 为 `0`，再把鼠标移到该消息的根元素上并断言该行 `opacity` 为 `1`，然后点击；步骤其余断言不变。
- **显隐一步**：在一个已完成、至少含一条文本非空的用户消息与一条正文非空的助手消息的会话上，两个 project 各走一遍：鼠标移开且焦点不在行内时两行都为 `0` 且行的包围盒高度大于 0；悬停每条消息时只有该消息的行为 `1`，悬停前后两条消息根元素的包围盒不变；从固定起点经键盘（Tab / Shift+Tab）到达用户消息的一个操作按钮（先断言 `document.activeElement` 是它）时该行为 `1`；剪贴板写入被页面脚本替换成必定 reject 后悬停并点击**末条**用户消息的 `复制`，出现 `复制失败`，随后把鼠标移出、把焦点移到输入框，该行仍为 `1`；再把剪贴板写入换成必定 resolve 的桩并点一次该 `复制` 以清除 `复制失败`，还原剪贴板写入、鼠标移出且焦点在输入框后该行回到 `0`（不给后续步骤留下常显的行）；不减少动态效果时该行计算 `transition-duration` 不为 `0s`，在 `prefers-reduced-motion: reduce` 下为 `0s`，步骤结束前恢复。
- **触屏上下文**：同一步里另开一个 `hasTouch` 的浏览器上下文（已登录，打开同一会话），先断言该上下文里 `(hover: none)` 成立（前提自证），再在不移动鼠标的情况下断言两条消息的操作行都为 `1`；上下文在 `finally` 里关闭。
- 这一步 SHALL NOT 新建 make target，SHALL NOT 改变既有 project 的设备参数（不给既有 project 加 `hasTouch` 或 `isMobile`）；它用到的会话按「冒烟与走查不留会话与临时空间」清理。

#### Scenario: 既有步骤先悬停
- **WHEN** 走查执行对话步骤里的 `重新生成` 与 `从此处分叉`，以及临时空间步骤里的 `撤回`
- **THEN** 每次点击之前，该按钮所在操作行的计算 `opacity` 先为 `0`，鼠标移到该消息上之后为 `1`；把实现里的悬停显现规则去掉（行恒为 `0`）时这些断言判红

#### Scenario: 显隐、键盘与复制失败
- **WHEN** 走查在已完成会话上执行显隐一步
- **THEN** 鼠标移开、悬停用户消息、悬停助手消息、键盘聚焦、`复制失败` 后移开五个时刻的计算 `opacity` 依次符合本要求；悬停前后根元素包围盒不变；`复制失败` 清除后该行回到 `0`；不减少动态效果时 `transition-duration` 不为 `0s`、减少动态效果下为 `0s`；剪贴板写入与减少动态效果的模拟在步骤结束前恢复

#### Scenario: 触屏上下文常显
- **WHEN** 走查在 `hasTouch` 的浏览器上下文里打开同一会话
- **THEN** 该上下文里 `matchMedia("(hover: none)").matches` 为 `true`，不移动鼠标时两条消息的操作行计算 `opacity` 都为 `1`；把隐藏改成不论能否悬停都生效时这条断言判红
