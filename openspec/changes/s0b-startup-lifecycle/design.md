## Decisions
1. Call existing deriveProxyBaseUrl/writeManagedModelsYml exactly once for successful startup after listen returns a real AddressInfo; target join(config.ompStateDir,'agent'). The success record remains the existing exact schema and is emitted only after the write settles. Reuse the writer's JSON-quoted YAML/env-name credential behavior; no duplicate serializer, secret injection, startup sandbox/bin directory or lazy session directory creation.
2. Distinguish pending bind from already-bound listener during signal handling. Abort the existing per-entry controller only to cancel pending acquisition; do not abort a bound listener ahead of native cleanup. Repeated/mixed signals must join the same owned shutdown and must not re-abort after the app handle has been cleared during cleanup. Preserve cancellation before/around listen and do not create a delayed successor bind or success record.
3. Reuse app.close and registerSessions preClose for runtime→store ordering; do not reimplement process TERM/KILL or close caller DB in feature code. Entry closes DB after app close, including reported cleanup errors. Observe actual native exit and listener-close event, not merely invoking shutdown callbacks. Post-bind signal with active/hang-eof child must keep listener-close after native exit; all signals/cleanup are idempotent.
4. Own in-flight model publication explicitly so a signal during its await cannot orphan IO, publish a success after shutdown or dereference a cleared app. Cleanup may join the finite publication operation, but must never await an enclosing startup task that itself awaits cleanup (cycle). Gate each post-await continuation by cancellation state. A real mkdir/write/listen/output failure remains a sticky nonzero generic failure even when a signal races cleanup; a clean cancellation alone emits no startup/failure record. No retries or failure suppression.
5. Use existing managed stdout/stderr writer, preserve generic failure/no-raw-stack/EPIPE behavior and truthful cleanup failure status. Runtime callbacks stay synchronous; no extra logs containing config, raw Error, password, cookie, upstream key or bearer. Same-uid caveat remains; declared child env whitelist is unchanged.
6. Recreate server-startup-order.test.ts as real executable integration, not source scans. Compile tracked server sources using declared TypeScript into a test-owned temporary ESM tree, copy the actual migration assets, resolve installed dependencies and run the real main entry. Reuse existing fake-omp call-proxy plus recording local upstream/SSE helpers; executable test wrapper may capture the actual token into private scratch and delegate the original fake script without changing production env policy. No jiti/undeclared loader, no mocked SUT, no reliance on prior dist or session /tmp evidence.
7. Observe listener/native/DB order using call-through dependency instrumentation at real events (including stdout/stderr capture), never substitute resource cleanup or synthesize success/exit. Deterministic barriers may pause a real write/bind path and deliver signals; deadlines are fail-stop backstops, not timing assumptions. Always reclaim owned process trees, ports, DB handles and scratch in finally, even when the assertion fails.
