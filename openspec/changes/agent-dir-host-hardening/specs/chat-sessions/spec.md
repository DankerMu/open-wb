## MODIFIED Requirements

### Requirement: Slash 命令白名单与命令目录
`server/src/sessions/slash-commands.ts` SHALL export the builtin whitelist `BUILTIN_COMMANDS` in this fixed order: `compact` (label `整理上下文`, description `压缩较长对话的上下文，保留要点`, hint `可选：想保留的重点`) and `todo` (label `任务清单`, description `查看或修改助手的任务清单`, hint `可选：append <任务>`); no other omp builtin SHALL be whitelisted by this change (`retry` is deliberately excluded: turn-control's regenerate already covers it and its `agentInvoked:true` receipt would add a second local-command completion mode). It SHALL export `listSkills(agentDir)`: synchronously enumerate the entries of `<agentDir>/skills` whose name does not start with `.`, keep at most the first 256 of them in code-point order of their SKILL.md path (further entries are ignored without any filesystem access), and read `<entry>/SKILL.md` for each kept entry without branching on the entry type (a plain file simply fails the read). A symlink is followed only inside the skills directory — a deliberate host restriction; omp itself follows any symlinked directory (`discovery/helpers.ts:428-431`): the host resolves the real path of `<entry>/SKILL.md` and skips the entry unless that real path lies inside the real path of `<agentDir>/skills`, then opens the resolved path with `O_NOFOLLOW`, so file content outside `skills/` never reaches the catalogue through a link; the read SHALL be bounded and non-blocking because the directory is group-writable by the omp uid (ADR-0010): SKILL.md is opened with `O_NONBLOCK | O_NOCTTY` (a terminal device placed there cannot become the server's controlling terminal), and only a regular file of at most 262144 bytes is read — a FIFO, device, directory or larger file is skipped like an unreadable one; normalise `\r\n?` to `\n` and read only the leading frontmatter block — the content starts with `---` and the block ends before the first later line starting with `---`; an unclosed block is no frontmatter — taking, without a YAML library, the top-level (unindented) `key: value` lines for `name`, `description` and `enabled`: a value is trimmed and loses one pair of surrounding quotes; a value that is exactly a block-scalar indicator (`>` or `|`, optionally followed by `+` or `-`) takes the following more-indented lines, each trimmed, joined with one U+0020 (`>`) or `\n` (`|`); `name` defaults to the entry name when missing or empty. An entry is skipped when SKILL.md is missing or unreadable, when `description` is missing or empty, or when the unquoted `enabled` value is `false` (omp's own drop rules for a user-level skill: `discovery/builtin.ts:295-300`, `discovery/helpers.ts:397-403`), and — a host rule; omp does not validate names — when `name` does not match `^[^\s/]+$` (such a name cannot be selected through `/skill:<name>`, whose name ends at the first U+0020). Entries sharing a `name` collapse to the one whose SKILL.md path is smallest in code-point order (omp is first-wins over the same order, `extensibility/skills.ts:220-221`). Any failure to enumerate `skills` (absent, not a directory, unreadable) yields `[]`, as omp's scan does (`discovery/helpers.ts:384-392`); the result is sorted by `name` in code-point order and is recomputed on every call (no cache). It SHALL export `classifyPrompt(text, skills)` for already-trimmed text: text not starting with `/` → `{kind:"text"}`; otherwise the name is the characters after `/` up to the first whitespace or `:`; a name equal to a `BUILTIN_COMMANDS` name → `{kind:"builtin", name}`, except `todo` with the subcommand `import` or `export`, which is `{kind:"text"}`: the subcommand is taken as omp takes it (`slash-commands/helpers/parse.ts:22-36,58-64`) — the text after the name's terminating whitespace or `:` is trimmed, cut at its first whitespace and lower-cased — because omp resolves the path argument of these two subcommands with `resolveToCwd`, which honours absolute paths, `~` and `..` (`tools/path-utils.ts:565-579`), reads or writes that file with no tool frame, no step row and no `files.changed`, and echoes parse errors of an imported file as the reply; the host does not parse or validate the path, it simply does not whitelist the two subcommands, so the text reaches the model escaped like any other non-whitelisted `/` text; text starting with `/skill:` whose skill name — the characters up to the first U+0020, exactly omp's split (`extensibility/skills.ts:456-459`), so a newline is part of the name — equals an installed skill `name` → `{kind:"skill", name}`; every other `/`-prefixed text (different case, non-whitelisted builtin, unknown skill, a skill name broken by a newline, pasted paths) → `{kind:"text"}`. It SHALL export `toWireText(text, skills)`: `builtin`/`skill` → the text unchanged; `text` starting with `/` → one U+0020 followed by the text; anything else unchanged. Arguments of whitelisted commands (`/todo append 买菜`, `/compact:focus 保留结论`, `/skill:<name> 写周报`) SHALL pass through unchanged. A `/skill:<installed>` token in the middle of a prompt is `text` for the host and is left to omp (which executes the skill exactly as in its TUI).
`GET /api/commands` (`server/src/sessions/rest-commands.ts`, registered by registerSessions next to the session routes) SHALL require the cookie guard (401 with no-store otherwise, decided before the body/query check: an unauthenticated request carrying either is 401), carry Cache-Control:no-store, accept no body and no query string (an authenticated request with either SHALL return400 bad_request) and return200 `{commands:[{name,label,description,hint,source}]}`: the two builtins first in whitelist order with `name` equal to the builtin name and `source:"builtin"`, then every installed skill with `name` `skill:<skill name>`, `label` the skill name, `description` the frontmatter description as stored (possibly English), `hint` `可选参数` and `source:"skill"`; `hint` SHALL be a string or null; the route SHALL NOT be a content-parser owner and SHALL NOT touch any session, process or SQLite row.
**Branch alignment** (used by regenerate and fork instead of a plain equality on stored content). The *wire candidates* of a stored user content `c` are `c` itself and, when `c` starts with `/`, one U+0020 followed by `c` (the escaped form; a message persisted before the prompt route escaped was sent verbatim). Candidates depend only on the stored text — alignment never classifies history by the current skill set, so installing or removing a skill later does not move it. Regenerate SHALL return400 bad_request, with no spawn, no frame and no row change and after the 409 busy check, when `classifyPrompt` of the stored last user message yields `builtin` or `skill` (such a turn left no omp `user` entry); otherwise it SHALL require the text of the last branch entry to be a wire candidate of the stored last user message (any other outcome, including an empty list → 502 agent_unavailable with no row change, as before; only this pair is compared, earlier entries are not read). Fork SHALL return400 the same way when the chosen `messageId`'s content classifies `builtin` or `skill`; otherwise, with the source's stored `user` messages U1…Un in id order and the branch entries E1…Em in list order, it SHALL align them first-fit from the front: Ui is aligned to the current Ej when `Ej.text` is a wire candidate of `Ui.content`, consuming both; a Ui that does not match the current Ej is skipped and consumes no entry (it left no omp `user` entry: a whitelisted builtin, a skill invocation — leading or mid-prompt, which omp stores as a `custom` message — or any other local-only turn); an entry whose `entryId` or `text` is not a string matches nothing. Fork SHALL use the entry aligned to the chosen message (no aligned entry → 502 agent_unavailable and no new session row, as before). Fork's `draft` SHALL be the stored content of the chosen user message (identical to the branch text for every message that does not start with `/`; never carries the escape space).

#### Scenario: Whitelist classification and wire form
- **WHEN** `classifyPrompt`/`toWireText` are applied, with skills `[{name:"weekly-report"}]`, to `/todo`, `/todo append 买菜`, `/compact:focus 保留结论`, `/skill:weekly-report 写周报`, `/retry`, `/TODO`, `/session delete`, `/skill:weekly-reportx`, `/skill:`, `/skill:weekly-report\n写周报`, `/etc/hosts 是什么`, `/` and `今天 /skill:weekly-report 帮我`
- **THEN** the first four classify `builtin`/`builtin`/`builtin`/`skill` and are returned unchanged; the next eight (including `/retry` and the newline-broken skill name) classify `text` and gain exactly one leading U+0020; the last classifies `text` and is returned unchanged (no leading `/`)

#### Scenario: todo import and export are not whitelisted
- **WHEN** `classifyPrompt`/`toWireText` are applied to `/todo export /abs/x.md`, `/todo import ../x`, `/todo export`, `/todo EXPORT ~/x`, `/todo  import x` (two spaces), `/todo:export /abs/x.md`, `/todo\nimport x` (newline separator), `/todo export\n/abs/x.md` (newline after the subcommand), and to `/todo`, `/todo append 买菜`, `/todo exported`, `/todo done import`
- **THEN** the first eight classify `text` and gain exactly one leading U+0020; the last four classify `builtin` and are returned unchanged (`exported` is not the subcommand `export`; `import` is not the first word); through `POST /api/sessions/:id/prompt` the stored user content of `/todo export /abs/x.md` is the original text and the supervisor receives it with the leading space; regenerate and fork anchored on such a message align it as ordinary text (wire candidates) instead of answering 400

#### Scenario: Skills are read from the platform directory under omp's rules
- **WHEN** `<agentDir>/skills` holds `weekly-report/SKILL.md` (`name: weekly-report`, `description: "写周报"`), `noname/SKILL.md` (a frontmatter with `description: x` and no `name`), `nodesc/SKILL.md` (a `name` but no `description`), `off/SKILL.md` (`description: y`, `enabled: false`), `bad name/SKILL.md` (`name: has space`, `description: z`), `.hidden/SKILL.md` (valid frontmatter), an `empty/` directory without SKILL.md, `folded/SKILL.md` (`description: >` followed by the indented lines `第一行` and `第二行`), `linked` (a symlink to a directory elsewhere whose SKILL.md has `description: l` and no `name`) and `zz-copy/SKILL.md` (`name: weekly-report`, `description: other`), and separately the `skills` path does not exist or is a regular file
- **THEN** `listSkills` returns `[{name:"folded",description:"第一行 第二行"},{name:"noname",description:"x"},{name:"weekly-report",description:"写周报"}]` in that order (`linked` is skipped by the host restriction on links leaving `skills/` — omp would load it; `nodesc`, `off`, `.hidden` and `empty` are skipped for the same reasons omp would not load them, `bad name` by the host's name rule, `zz-copy` as the later duplicate) and `[]` in both separate cases; two consecutive calls after adding a skill differ (no cache)

#### Scenario: Command directory
- **WHEN** an authenticated account GETs `/api/commands` on an app created through createApp whose `<OMP_STATE_DIR>/agent/skills` holds two loadable skills, an unauthenticated client GETs it, and the owner GETs it with a query string or a JSON body
- **THEN** the first receives200 no-store with exactly four entries — `compact`/`整理上下文`/`压缩较长对话的上下文，保留要点`/`可选：想保留的重点`/`builtin`, `todo`/`任务清单`/`查看或修改助手的任务清单`/`可选：append <任务>`/`builtin`, then the two skills as `skill:<name>`/`<name>`/`<description>`/`可选参数`/`skill` in name order — each with exactly the five keys, proving the injected `agentDir` is the directory the spawn exports as `PI_CODING_AGENT_DIR`; the second receives401 no-store, also when it carries a query string or a body; the third and fourth receive400 bad_request; with no skills directory the response holds exactly the two builtins

#### Scenario: Command-anchored regenerate and fork
- **WHEN** the owner posts regenerate on a done session whose last user message is `/todo` (its assistant body `No todos. Use /todo append <task> to start one.`), posts fork at a `/skill:weekly-report 写周报` user message while `weekly-report` is installed, and separately posts regenerate on a done session whose stored user messages are `/todo` then `/help 这是什么` (escaped plain text) backed by the real fake (`branch --branch-entry " /help 这是什么"`) whose last entry text is ` /help 这是什么`
- **THEN** the first two return400 bad_request with no control claim left, no spawn, no frame and no row change; the third returns202 because the last entry is the wire form of the last stored user message, and the new turn is dispatched with the branch text ` /help 这是什么`
- **WHEN** the owner forks at the plain message `继续` of a session whose stored user messages are `first question`, `second question`, `/todo`, `继续`, backed by the real fake (`branch --branch-entry "继续"`) whose entries are the fixed list (`first question`, `second question`) followed by `继续`, separately forks at a message stored as `/legacy` (sent verbatim before the prompt route escaped) whose aligned entry text is `/legacy`, and separately forks at an escaped message stored as `/help 这是什么` whose aligned entry text is ` /help 这是什么`
- **THEN** all three return201: the `/todo` message consumed no entry so `继续` aligns to the `继续` entry and `draft` equals `继续`; the legacy message aligns by verbatim equality and `draft` equals `/legacy`; the escaped message aligns by its wire form and `draft` equals `/help 这是什么` (no leading space)
- **WHEN** the owner forks at a stored message that left no entry and is not a whitelisted command (a mid-prompt skill invocation `今天 /skill:weekly-report 帮我` after the two fixed-list messages), or — on a `running` session whose last user message is `/todo` — regenerates, or forks at that message
- **THEN** the fork returns502 agent_unavailable with no `branch` frame and no new session row, and both requests on the running session return409 session_busy (the busy check precedes the command check)

#### Scenario: Skill links leaving the skills directory and the entry cap
- **WHEN** `<agentDir>/skills` holds `inside/SKILL.md` (a regular file), `alias` → a symlink to the sibling directory `inside`, `escape` → a symlink to a directory outside `skills/` that contains a valid SKILL.md, and `leak/SKILL.md` → a symlink to a valid skill file outside `skills/`
- **THEN** `listSkills` returns the skill of `inside` (once: `alias` resolves to the same file and collapses by name) and nothing from `escape` or `leak`; `GET /api/commands` contains neither outside description
- **WHEN** `skills` holds 300 valid entries
- **THEN** exactly the first 256 in code-point order of their SKILL.md path are listed, and no file of the other 44 is opened
