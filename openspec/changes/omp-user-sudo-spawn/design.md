## Context
agent-config.ts:20-47 owns AgentSettings parsing; server.ts:174-184 builds assembly.runtime; app forwards it to sessions; supervisor.ts:180-195 constructs SessionRuntimeOpts; runtime.ts:307-320 constructs OmpProcess, which calls spawnOmp. ## Goals / Non-Goals
Goal: configured user reaches cold/reopened generations with exact sudo args and unchanged env/cwd/stdio/shell. Non-goals: real privilege change, proc/PAM isolation, permissions/chown/umask/sudoers, module-count change, retries/fallback, new tokens or RPC design.
## Decisions
1. Extend canonical AgentSettings with optional ompUser. Missing/undefined stays absent. Validate present OMP_USER as exactly1..32 ASCII characters [a-z_][a-z0-9_-]{0,31}, no trim/coercion. Empty, uppercase, space, semicolon, newline/CR, nonASCII,33characters reject synchronously before startup mkdir/DB/listen/models effects. Use full-string matching without multiline mode; Main Node24 probe confirms the anchored /u regex rejects final newline (the initial claim that JS $ always accepts one was incorrect). Existing entry emits one fixed generic application server_start_failed stderr line and exit1, no rawvalue/stack; Node SQLite experimental warnings may precede it and must be reported separately, not presented as application log lines. Preserve source/dist identity and unknown-key policy.
2. Forward through ServerConfig -> assembly.runtime -> SessionSupervisorRuntime -> SessionRuntimeOpts -> OmpProcessOpts/SpawnOmpOpts using existing exactOptionalPropertyTypes conditional spreading. No second parser or feature-to-entry import. Store immutable option in SessionRuntime for reopen/resume. app/index already forwards runtime objects and need not change if types suffice. No shim or dual implementation.
3. spawnOmp builds existing omp args/env once. Missing user calls spawnImpl(opts.bin,args,{cwd,env,stdio:[pipe,pipe,pipe],shell:false}) unchanged. Present command is 'sudo', argv ['-n','-u',user,'--preserve-env=PATH,LANG,TMPDIR,HOME,PI_CODING_AGENT_DIR,WORKBUDDY_MODEL_TOKEN','--',opts.bin,...args]. Preserve cold/resume and spaced paths. No shell/string-command construction or credential KEY=value args. Preserve-env contains only keynames and is the documented '=' exception; existing legitimate model/path args are not arbitrarily rejected for '='.
4. Env remains exactly PATH,HOME,PI_CODING_AGENT_DIR,WORKBUDDY_MODEL_TOKEN plus LANG/TMPDIR only when present, values unchanged. Never inject OMP_USER, upstream/canary secrets or mutate process.env. Fixed preserve-key list does not invent missing optional env values. This proves sudo-process input, not sudo/PAM target environment or uid isolation.
5. Sudo spawn failure/nonzero/immediate-before-ready exit uses existing AgentUnavailableError/agent_unavailable and native cleanup/token revocation, no retry as direct omp. Exercise injected SpawnImpl/controlled transport or harmless exit executable, never host sudo. At least one real configuration -> createApp -> authenticated session prompt -> captured spawn must prove all forwarding, not mere field copies. Main compiled production-entry smoke may intercept child_process.spawn before imports, capture sudo call and launch harmless exit child; explicitly not real privilege proof.
6. Vertical tests: config rejection, dual cold/resume capture, production forwarding, immediate-exit failure. Four named invalid values also run the real compiled entry, proving exact generic stderr/empty app stdout/exit1/no DBparent/sandbox/state/models/listen effects. Reuse compileServerEntry/startCompiledServer helpers. Public stderr exact bytes are contract; private parser wording is not. Main owns independent compiled smoke.
## Risks / Trade-offs
Missing forwarding silently defeats configuration; prompt-to-capture oracle catches it. Default mkdir stays unchanged until #126; do not prematurely claim2770. Startup modules stay five until #128. Validated server configuration is the trust boundary for low-level spawn options; no duplicated process-level parser.
