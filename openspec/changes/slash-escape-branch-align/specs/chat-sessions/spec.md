## MODIFIED Requirements

### Requirement: Slash 命令白名单与命令目录
`server/src/sessions/slash-commands.ts` SHALL export the builtin whitelist `BUILTIN_COMMANDS` in this fixed order: `compact` (label `整理上下文`, description `压缩较长对话的上下文，保留要点`, hint `可选：想保留的重点`) and `todo` (label `任务清单`, description `查看或修改助手的任务清单`, hint `可选：append <任务>`); no other omp builtin SHALL be whitelisted by this change (`retry` is deliberately excluded: turn-control's regenerate already covers it and its `agentInvoked:true` receipt would add a second local-command completion mode). It SHALL export `listSkills(agentDir)`: synchronously enumerate the entries of `<agentDir>/skills` whose name does not start with `.` and read `<entry>/SKILL.md` for each without branching on the entry type (a symlink to a directory is followed, as omp does — `discovery/helpers.ts:428-431` — and a plain file simply fails the read); the read SHALL be bounded and non-blocking because the directory is group-writable by the omp uid (ADR-0010): SKILL.md is opened with `O_NONBLOCK`, and only a regular file (after following symlinks) of at most 262144 bytes is read — a FIFO, device, directory or larger file is skipped like an unreadable one; normalise `\r\n?` to `\n` and read only the leading frontmatter block — the content starts with `---` and the block ends before the first later line starting with `---`; an unclosed block is no frontmatter — taking, without a YAML library, the top-level (unindented) `key: value` lines for `name`, `description` and `enabled`: a value is trimmed and loses one pair of surrounding quotes; a value that is exactly a block-scalar indicator (`>` or `|`, optionally followed by `+` or `-`) takes the following more-indented lines, each trimmed, joined with one U+0020 (`>`) or `\n` (`|`); `name` defaults to the entry name when missing or empty. An entry is skipped when SKILL.md is missing or unreadable, when `description` is missing or empty, or when the unquoted `enabled` value is `false` (omp's own drop rules for a user-level skill: `discovery/builtin.ts:295-300`, `discovery/helpers.ts:397-403`), and — a host rule; omp does not validate names — when `name` does not match `^[^\s/]+$` (such a name cannot be selected through `/skill:<name>`, whose name ends at the first U+0020). Entries sharing a `name` collapse to the one whose SKILL.md path is smallest in code-point order (omp is first-wins over the same order, `extensibility/skills.ts:220-221`). Any failure to enumerate `skills` (absent, not a directory, unreadable) yields `[]`, as omp's scan does (`discovery/helpers.ts:384-392`); the result is sorted by `name` in code-point order and is recomputed on every call (no cache). It SHALL export `classifyPrompt(text, skills)` for already-trimmed text: text not starting with `/` → `{kind:"text"}`; otherwise the name is the characters after `/` up to the first whitespace or `:`; a name equal to a `BUILTIN_COMMANDS` name → `{kind:"builtin", name}`; text starting with `/skill:` whose skill name — the characters up to the first U+0020, exactly omp's split (`extensibility/skills.ts:456-459`), so a newline is part of the name — equals an installed skill `name` → `{kind:"skill", name}`; every other `/`-prefixed text (different case, non-whitelisted builtin, unknown skill, a skill name broken by a newline, pasted paths) → `{kind:"text"}`. It SHALL export `toWireText(text, skills)`: `builtin`/`skill` → the text unchanged; `text` starting with `/` → one U+0020 followed by the text; anything else unchanged. Arguments of whitelisted commands (`/todo append 买菜`, `/compact:focus 保留结论`, `/skill:<name> 写周报`) SHALL pass through unchanged. A `/skill:<installed>` token in the middle of a prompt is `text` for the host and is left to omp (which executes the skill exactly as in its TUI).
`GET /api/commands` (`server/src/sessions/rest-commands.ts`, registered by registerSessions next to the session routes) SHALL require the cookie guard (401 with no-store otherwise, decided before the body/query check: an unauthenticated request carrying either is 401), carry Cache-Control:no-store, accept no body and no query string (an authenticated request with either SHALL return400 bad_request) and return200 `{commands:[{name,label,description,hint,source}]}`: the two builtins first in whitelist order with `name` equal to the builtin name and `source:"builtin"`, then every installed skill with `name` `skill:<skill name>`, `label` the skill name, `description` the frontmatter description as stored (possibly English), `hint` `可选参数` and `source:"skill"`; `hint` SHALL be a string or null; the route SHALL NOT be a content-parser owner and SHALL NOT touch any session, process or SQLite row.
**Branch alignment** (used by regenerate and fork instead of a plain equality on stored content). The *wire candidates* of a stored user content `c` are `c` itself and, when `c` starts with `/`, one U+0020 followed by `c` (the escaped form; a message persisted before the prompt route escaped was sent verbatim). Candidates depend only on the stored text — alignment never classifies history by the current skill set, so installing or removing a skill later does not move it. Regenerate SHALL return400 bad_request, with no spawn, no frame and no row change and after the 409 busy check, when `classifyPrompt` of the stored last user message yields `builtin` or `skill` (such a turn left no omp `user` entry); otherwise it SHALL require the text of the last branch entry to be a wire candidate of the stored last user message (any other outcome, including an empty list → 502 agent_unavailable with no row change, as before; only this pair is compared, earlier entries are not read). Fork SHALL return400 the same way when the chosen `messageId`'s content classifies `builtin` or `skill`; otherwise, with the source's stored `user` messages U1…Un in id order and the branch entries E1…Em in list order, it SHALL align them first-fit from the front: Ui is aligned to the current Ej when `Ej.text` is a wire candidate of `Ui.content`, consuming both; a Ui that does not match the current Ej is skipped and consumes no entry (it left no omp `user` entry: a whitelisted builtin, a skill invocation — leading or mid-prompt, which omp stores as a `custom` message — or any other local-only turn); an entry whose `entryId` or `text` is not a string matches nothing. Fork SHALL use the entry aligned to the chosen message (no aligned entry → 502 agent_unavailable and no new session row, as before). Fork's `draft` SHALL be the stored content of the chosen user message (identical to the branch text for every message that does not start with `/`; never carries the escape space).

### Requirement: REST prompt 受理与补偿
The prompt route SHALL accept only application/json and an object with exactly message:string. It SHALL trim the string once and require nonempty text of at most32768 UTF-8 bytes. Invalid shape, media, malformed JSON or oversized parser envelope SHALL return400 bad_request; decoded valid escape-heavy text SHALL NOT be rejected merely because its wire JSON exceeds32768 bytes. The existing bounded parser envelope remains distinct from the semantic message limit. A trimmed text that starts with `/` SHALL NOT be rejected for that reason: Requirement「Slash 命令白名单与命令目录」 decides whether it reaches omp as a command or as plain text.
The route SHALL use store.acceptPrompt(sessionId,principal.id,text) with the trimmed original text for the atomic admission (persisted user content and the title rule are unchanged) and then await supervisor.prompt(sessionId, toWireText(text, listSkills(agentDir))) where `toWireText`/`listSkills` are those of Requirement「Slash 命令白名单与命令目录」 (identity for every text that does not start with `/` and for whitelisted commands; a leading U+0020 otherwise) and `agentDir` is the registerSessionRoutes dependency of Requirement「会话 REST」. The owned SessionSupervisorPort SHALL expose prompt(sessionId:string,text:string):Promise<void>; resolution means dispatch accepted, not turn finished. Successful admission SHALL return202 {userMessageId,assistantMessageId} from that exact store admission. Running sessions SHALL return409 session_busy without added rows or dispatch; so SHALL a session whose supervisor control claim is held by an in-progress regenerate, fork or stop — the claim check and admission SHALL run without an intervening await; idle/done/failed/stopped SHALL be eligible.
Supervisor rejection SHALL compensate the unprogressed accepted pair through store.rollbackPrompt before returning the canonical error. HttpError agent_unavailable SHALL produce502, HttpError session_busy SHALL produce409, HttpError agent_capacity SHALL produce503; unknown failures SHALL remain generic5xx. Compensation failure SHALL propagate as generic5xx, not be masked as502/409/503. The supervisor SHALL NOT reject after publishing/persisting progress; post-dispatch failures belong to supervisor lifecycle. No retries or real runtime/SSE implementation are part of this boundary.

### Requirement: 会话 REST
registerSessionRoutes(app,{store,supervisor,agentDir}) SHALL register GET/POST /api/sessions, GET /api/sessions/:id/messages, POST /api/sessions/:id/prompt, POST /api/sessions/:id/stop, POST /api/sessions/:id/regenerate, POST /api/sessions/:id/fork, POST /api/sessions/:id/approvals/:approvalId, PATCH /api/sessions/:id and DELETE /api/sessions/:id (ten routes). All SHALL use the existing cookie guard and authenticated principal.id; all matched responses SHALL carry Cache-Control:no-store without changing sibling routes. Unauthenticated requests SHALL return401 before body parsing. Unknown or foreign session ids SHALL return identical404 not_found before body parsing, with no writes or supervisor dispatch.
Id-scoped authorization SHALL use the existing owner-scoped store.getMessages(sessionId,principal.id) null result before parsing; acceptPrompt SHALL independently recheck ownership on admission. REST SHALL NOT use the trusted-supervisor-only runtimeState accessor for authorization.
registerSessions SHALL additionally register the session-independent `GET /api/commands` (`rest-commands.ts`) whose contract is Requirement「Slash 命令白名单与命令目录」 (it is not one of the ten session routes and is not a content-parser owner); `agentDir` is passed to registerSessionRoutes for the prompt route's `toWireText`. POST /api/sessions SHALL accept an optional body `{workspaceId?,scene?}` whose validation, binding and audit rules are session-metadata「会话创建与空间绑定」, and SHALL return201 {id,title:null,status:"idle",createdAt,updatedAt,scene,workspaceId,pinnedAt:null} with `scene`/`workspaceId` equal to the accepted values or null when absent (a bodyless request yields both null). GET /api/sessions SHALL return200 {sessions:[...]} restricted to the owner and ordered updatedAt descending with the store's stable tie-break. PATCH /api/sessions/:id and DELETE /api/sessions/:id follow session-metadata「会话元数据修改」 and「会话删除」. GET messages SHALL return200 {session,messages:[{id,role,content,thinking,status,createdAt,approvals,steps:[{id,ordinal,name,detail,output,changes,status}]}],streamCursor:{epoch,seq}}, ordered createdAt/id and step ordinal; step output SHALL be a string, empty for a running step or a stored NULL. `thinking` SHALL be present on every message as `string | null` (a stored NULL, including every user message, reads null; content rules belong to thinking-fold). `changes` SHALL be present on every step as `Change[] | null`, a stored NULL reading null and a stored value reading the array of `{path,added,removed,kind}` whose element rules belong to turn-artifacts. `approvals` SHALL be present on every message as an array of all `chat_approvals` rows of that message in ascending id order, each `{id,tool,title,requestedAt,expiresAt,decision}` with `decision` ∈ `allow|deny|timeout|null`; it SHALL be `[]` for a user message and for an assistant message without approval rows. Several pending (`decision:null`) entries MAY coexist on one message (parallel tool calls); a later approval request never replaces an earlier entry. Session views (list entries, create/PATCH responses, the snapshot `session`, the fork response `session`) SHALL contain exactly the eight keys id,title,status,createdAt,updatedAt,scene,workspaceId,pinnedAt, where `scene` ∈ `office|code|design|null`, `workspaceId` is the bound workspace id or null and `pinnedAt` is epoch milliseconds or null (`parent_session_id` and `omp_session_file` SHALL NOT be exposed); Only the declared streamCursor boundary SHALL expose the generation epoch; other internal ownership/runtime fields and step timing fields SHALL NOT leak. The complete owner-scoped tree and synchronous supervisor.streamCursor(sessionId) SHALL be captured together in the same preParsing stack before done, with no await between them; the handler SHALL serialize only that cached pair. streamCursor SHALL NOT replace owner authorization.
POST /api/sessions/:id/stop and POST /api/sessions/:id/regenerate SHALL be bodyless content-parser owners (the logout precedent): any parsed body (including `{}`), empty-or-malformed JSON, unsupported media or an envelope above their minimal body limit SHALL return400 bad_request after authorization and before any supervisor call, frame or write. When the session is `running`, stop SHALL call supervisor.stop(sessionId) — which holds the session's control claim for the call, first settles every pending approval of that turn, if any exist (the pending set is the snapshot read on entry; it is not re-read before the `abort` frame), as `deny` (per approval: persist decision/decided_at and its `session.approval` audit row in one transaction → answer `Deny` → publish `approval.resolved`) and then writes the `abort` frame; when the turn's prompt frame is not yet written, stop instead records a stop intent and the supervisor writes `abort` right after that prompt's dispatch receipt resolves (after the stop call has returned), so stop neither cancels the dispatch nor compensates the accepted rows and the prompt request still returns its normal202 body (a failed acquisition or dispatch still follows the ordinary prompt compensation, and the intent never rewrites a terminal status another path reached first) — and return202 with body exactly `{}` without waiting for the turn to end; for any other status it SHALL return204 with no writes and no supervisor call. The stopped turn ends with `turn.end{status:"stopped"}` and session/assistant/running steps read `stopped`.
POST /api/sessions/:id/regenerate: a `running` session, or a session whose control claim is held by another regenerate, fork or stop, SHALL return409 session_busy. A session whose history does not end with an assistant message immediately preceded by a user message, or whose last user message classifies as a whitelisted command (`classifyPrompt` → `builtin|skill`, Requirement「Slash 命令白名单与命令目录」), SHALL return400 bad_request (checked after the 409 busy check, with no spawn, frame or row change). Otherwise it SHALL call supervisor.regenerate(sessionId), which registers the session's control claim with the last assistant message id read by the precheck and releases it once dispatch completes or the response returns: acquire the session's process — reusing a live one, or through the same lazy acquisition as prompt (a normal new generation, stream_epoch+1 with a fresh ring) when it has been reclaimed — through the process cap (`agent_capacity` → 503), `get_branch_messages`, require the last entry's `text` to be a wire candidate of the stored last user message (Requirement「Slash 命令白名单与命令目录」 Branch alignment; any other outcome, including an empty list → 502 agent_unavailable with no row change), `branch{entryId}`, `get_state`, then in one SQLite transaction — which SHALL first recheck that the session status is not `running` and its last assistant message id still equals the precheck's, otherwise write nothing, retire the process and return409 session_busy — delete the old assistant row (steps and approvals cascade), insert a new empty `running` assistant row, set `omp_session_file` to the new file and session status `running`, and dispatch the branch-returned text as the prompt; it SHALL return202 {assistantMessageId} of the new row. Runtime failure before the transaction SHALL leave every row unchanged and map to502 agent_unavailable; dispatch failure after the transaction SHALL settle the new assistant row and session as `failed`, return502 agent_unavailable (rows are already terminal, nothing is compensated) and SHALL NOT resurrect the deleted row.
POST /api/sessions/:id/fork SHALL accept only application/json and an object with exactly messageId:number; any other shape, a messageId that is not a `user` message of this session, a messageId whose stored content classifies as a whitelisted command (`classifyPrompt` → `builtin|skill`), or wrong media/malformed JSON SHALL return400 bad_request (the command check runs after the 409 busy check, with no spawn, frame or row change). A `running` source session, or one whose control claim is held by another regenerate, fork or stop, SHALL return409 session_busy. Otherwise the supervisor SHALL register the source session's control claim (with the last assistant message id read by the precheck), retire the source session's live idle process if one exists (its history is in the file, so this is lossless), then run a temporary runtime through the process cap (`agent_capacity` → 503) with `--resume <source omp_session_file>`, `get_branch_messages`, align the stored user messages to the entries (Branch alignment) and take the entry aligned to the chosen message (no aligned entry → 502 agent_unavailable; no new session row exists), `branch{entryId}`, `get_state`, shut the temporary process down, then in one transaction — which SHALL first recheck that the source status is not `running` and its last assistant message id still equals the precheck's, otherwise write nothing and return409 session_busy — insert the new session row (same owner, copied title, copied `workspace_id` and `scene`, `pinned_at` NULL, `parent_session_id` = source id, `omp_session_file` = the new file, `stream_epoch` 0). No new session row exists before this transaction commits, so every failure leaves none behind. The temporary runtime is not a session generation: it SHALL NOT bump either session's `stream_epoch`, owns no ring, publishes no events, is bound to no slot and counts only against the process cap. The transaction SHALL also copy every chat_messages/chat_steps row of the source that precedes the fork-point user message (new ids, same order, content, thinking, status, timestamps and step detail/output/changes, each copied verbatim including NULL), copy every `chat_approvals` row of those copied messages onto the new message ids (new approval ids; request_id, tool, title, requested_at, expires_at, decision and decided_at preserved), and set the new session's status to the status of the last copied assistant message (`done`, `failed` or `stopped`), leaving it `idle` only when nothing is copied. The source session's rows, status and file SHALL be unchanged; its live process, if any, receives no frame and is retired before the temporary process starts. It SHALL return201 {session,draft} where `session` is the new session's eight-key public view and `draft` is the stored content of the chosen user message (equal to the branch text for every message not starting with `/`; never carries the escape space).
POST /api/sessions/:id/approvals/:approvalId SHALL accept only application/json and an object with exactly decision:"allow"|"deny"; other shapes/media/malformed JSON SHALL return400 bad_request. `approvalId` SHALL be a canonical positive decimal integer naming a `chat_approvals` row whose message belongs to this session, otherwise404 not_found identical to a missing session; a non-canonical approvalId SHALL be rejected before body parsing, and an approvalId not owned by this session SHALL be rejected after body parsing but before any write, answer frame or publish. A row whose `decision` is already set SHALL return409 approval_settled with no writes. A pending row SHALL be settled in this order: in one transaction persist decision/decided_at and its `session.approval` audit row → answer the child (`Approve` for allow, `Deny` for deny) and cancel its timeout timer → publish `approval.resolved` → return200 with the settled approval object `{id,tool,title,requestedAt,expiresAt,decision}` (one element of the snapshot's `approvals` array).
