## MODIFIED Requirements

### Requirement: 会话条目菜单与重命名
每个条目 SHALL 有 accessible name 为 `更多操作：<显示标题>` 的图标按钮，它是选择按钮的同级元素（不嵌套），始终在 DOM 中且可聚焦（`≥761px` 且支持悬停的设备上仅以透明度弱化，悬停、聚焦或菜单打开时显现）。默认视图里它打开的菜单项依次为：`重命名`、`置顶任务` 或 `取消置顶`（按该会话 `pinnedAt` 是否为 null）、`归档`、`删除`（危险样式）、`另存为工作空间`（仅当该会话 `temporaryWorkspace` 为 true 时渲染）、`导出记录`；除此之外没有别的项。`归档` 在会话 `status="running"` 时为禁用项（`aria-disabled="true"`，选择不发请求）；其余项对任何状态的会话均可用。归档视图里的菜单见「归档视图」。「更多」按钮与菜单项 SHALL NOT 触发 `≤760px` 导航覆盖层的关闭。

会话列表的动作 SHALL NOT 显示任何轻提示（不出现 `已重命名`、`已更新置顶状态`、`任务已删除` 等文本）：成功以列表自身的变化为反馈；对话框内发起的请求失败时在该对话框内以 `role="alert"` 显示；没有对话框的动作（置顶、归档、恢复、导出）以及对话框已关闭后才到达的失败，SHALL 在列表区顶部以一条 `role="alert"` 显示信封 message（非信封失败为 `请求失败，请稍后重试`），该提示带 accessible name 为 `关闭提示` 的按钮，并在下一次列表动作发起时清除。

- `重命名`：打开对话框，标题 `重命名任务`，含 accessible name `任务名称` 的输入框（初值为服务端 title，null 时为空；打开时焦点在输入框）与按钮 `取消` / `保存`；trim 后为空时 `保存` 禁用；`保存` 或输入框内 Enter 以 trim 后的文本发送一次 `PATCH {title}`，请求中 `保存` 禁用、不重复发送；200 后关闭对话框并把焦点还给打开它的按钮，列表条目与顶栏面包屑以响应视图的标题更新；失败时对话框保持打开并在其内显示提示，再次提交时清除。请求中 `取消`、`关闭`、Escape 与遮罩仍可关闭对话框，请求不取消：其后的 200 照常更新列表与面包屑，失败则走列表区顶部提示（被同一会话更新的重命名请求取代的响应除外，见下）；关闭后再次打开的对话框是全新状态。
- `置顶任务` / `取消置顶`：发送 `PATCH {pinned:true|false}`；200 后以响应视图的 `pinnedAt` 更新列表；失败时列表不变并走列表区顶部提示。
- `归档`：发送 `PATCH {archived:true}`；200 后该条目离开默认视图（进入归档视图）；它是当前选中会话时保持选中，主区按 chat-web「会话页」的归档只读呈现；失败（如 409 `会话正在生成，请稍候`）时列表不变并走列表区顶部提示。
- `删除`：打开确认框，标题 `删除任务`，确认按钮 `删除`（危险样式）与 `取消`。说明文字：会话不用临时空间时为 `确定要删除「<显示标题>」吗？删除后不可恢复。`；用临时空间且已加载的列表（含已归档）里没有别的会话与它同 `workspaceId` 时，在其后追加 `临时空间里的文件会一并删除。`；用临时空间且有别的会话共用时追加 `它与其它会话共用临时空间，文件会保留到最后一个会话被删除。`。`取消` 或 Escape 关闭确认框且不发请求，焦点回到打开它的「更多」按钮。确认发送一次 `DELETE`（无 body），请求中确认按钮忙碌禁用、不重复发送；请求中确认框仍可关闭：取消按钮文案改为 `关闭`，框内显示 `删除请求已发送，关闭窗口不会撤销请求。`；请求不取消，其间再次对同一会话打开的确认框仍处于这一忙碌状态。204 后从列表移除该会话、关闭为该会话打开的确认框与重命名对话框；若响应到达时它是当前选中会话，页面 SHALL 关闭其事件流连接、以 replace 移除 `?session=`（保留其它 search/hash，pathname 为 `/`）并回到欢迎态，不显示错误、不再读取该会话的消息；删除非当前会话不改变 URL 与主区。失败时关闭为该会话打开的确认框、走列表区顶部提示并重新读取会话列表。
- `另存为工作空间` 与 `导出记录`：见同名 Requirement。

以响应视图更新 SHALL 只采用响应中该请求所修改的那个键（重命名取 `title`，置顶取 `pinnedAt`，归档与恢复取 `archivedAt`），不覆盖该条目的其它键；同一会话有多个进行中的同类请求时只采用最后发出的那个请求的响应，被取代的响应不更新也不提示；账号切换或离开会话页之后到达的响应 SHALL 被丢弃（不更新列表、不提示）；删除的响应同样如此（不移除条目、不提示、不导航、不重新读取列表）。

顶栏第二态（有当前会话且标题已知）SHALL 经 spa-shell 的 `useTopbar` `actions` 插槽渲染 accessible name 与 Tooltip 均为 `重命名` 的图标按钮，打开同一重命名对话框作用于当前会话；会话页注入的顶栏按钮次序由有序常量 `CHAT_TOPBAR_ACTIONS` 固定为 `重命名`、`对话内搜索`、`工作空间侧边栏`，页面只从该常量按序构造 `actions`：前两个槽位都产出按钮，第三个只在当前会话的 `workspaceId` 不为 `null` 时产出（`对话内搜索` 归 conversation-search，`工作空间侧边栏` 归 workspace-sidebar）；顶栏 `更多` SHALL NOT 渲染；欢迎态不上报 `actions`。

#### Scenario: 菜单项
- **WHEN** 打开一个绑定正式空间、未置顶、`done` 会话的「更多」菜单；再打开一个 `temporaryWorkspace` 为 true、`running` 会话的菜单
- **THEN** 前者恰五项，依次为 `重命名`、`置顶任务`、`归档`、`删除`、`导出记录`；后者恰六项，依次为 `重命名`、`置顶任务`、`归档`（`aria-disabled="true"`）、`删除`、`另存为工作空间`、`导出记录`；点击禁用的 `归档` 不发请求

#### Scenario: 从条目菜单重命名
- **WHEN** 对当前选中会话打开 `更多操作：<标题>` → `重命名`，把输入改为 `  周报整理  ` 并点击 `保存`
- **THEN** 发出一次 `PATCH` body `{"title":"周报整理"}`；对话框关闭、焦点回到该条目的「更多」按钮；条目与顶栏 heading `我的工作 / 周报整理` 更新；页面没有轻提示，任何位置都不出现文本 `已重命名`；输入全空白时 `保存` 为禁用；输入框内 Enter 等价于 `保存`

#### Scenario: 重命名失败保留对话框
- **WHEN** PATCH 返回 400 信封 `请求格式不正确`
- **THEN** 对话框仍打开，其内 `role="alert"` 文本恰为 `请求格式不正确`，列表标题不变

#### Scenario: 重命名请求中
- **WHEN** 点击 `保存` 而 PATCH 尚未返回，期间再次提交，然后点击 `取消`；随后响应 200 到达
- **THEN** 请求中 `保存` 为禁用、没有第二个 PATCH；响应到达后条目与面包屑更新，没有轻提示
- **WHEN** 同样在请求中关闭对话框，而响应为 400 信封 `请求格式不正确`
- **THEN** 列表标题不变，列表区顶部出现 `role="alert"` 文本 `请求格式不正确`；点击 `关闭提示` 后它消失

#### Scenario: 顶栏重命名入口
- **WHEN** 打开 `/?session=<id>` 且标题已知
- **THEN** banner 内 heading 之后依次有 `重命名`、`对话内搜索`、`工作空间侧边栏` 三个按钮且无 `更多`（该会话绑定了工作空间且项目配置列表为空时；会话未绑定工作空间时只有前两个；非空时 `重命名` 之前另有 `项目配置`，chat-web「会话页」）；点击 `重命名` 打开 `重命名任务` 对话框，输入初值为该会话标题；欢迎态顶栏无这些按钮

#### Scenario: 置顶菜单文案与提示
- **WHEN** 对未置顶会话选择 `置顶任务`，再打开同一条目菜单
- **THEN** 发出 `PATCH {"pinned":true}`，条目移入 `置顶任务`，没有轻提示；再次打开的菜单项文案为 `取消置顶`
- **WHEN** 置顶的 PATCH 返回 502
- **THEN** 列表不变；列表区顶部出现 `role="alert"` 的信封文案；随后发起任一列表动作时该提示消失

#### Scenario: 归档当前会话
- **WHEN** 对当前选中的 `done` 会话选择 `归档`，PATCH 返回 200
- **THEN** 发出 `PATCH {"archived":true}`；该条目从默认视图消失；URL 仍选中它，主区显示 `该会话已归档，恢复后才能继续对话`；没有轻提示

#### Scenario: 迟到的元数据响应
- **WHEN** 对 `running` 会话发出置顶请求，响应返回前会话列表被重新读取且该会话已为 `done`，随后置顶响应（视图中 `status` 仍为 `running`）到达
- **THEN** 条目移入 `置顶任务` 且其状态元素的可访问名以 `已完成` 结尾

#### Scenario: 删除确认文案
- **WHEN** 分别对：绑定正式空间的会话；独占临时空间的会话；与另一个（已归档的）会话共用临时空间的会话 选择 `删除`
- **THEN** 确认框说明依次为 `确定要删除「<标题>」吗？删除后不可恢复。`；`确定要删除「<标题>」吗？删除后不可恢复。临时空间里的文件会一并删除。`；`确定要删除「<标题>」吗？删除后不可恢复。它与其它会话共用临时空间，文件会保留到最后一个会话被删除。`

#### Scenario: 删除当前会话
- **WHEN** 对当前选中且 `running` 的会话选择 `删除` 并点击 `删除`
- **THEN** 发出一次 `DELETE`；请求中确认按钮忙碌禁用；204 后条目消失、URL 的 pathname 为 `/` 且不含 `?session=`（其它 search/hash 保留）、页面为欢迎态且无错误提示，事件流连接已关闭；页面没有轻提示，任何位置都不出现文本 `任务已删除`
- **WHEN** 删除一个非当前选中的会话
- **THEN** 204 后该条目消失，URL 与主区当前会话不变
- **WHEN** 选择 `取消`，或 DELETE 返回 409
- **THEN** 前者不发请求；后者确认框关闭、列表区顶部 `role="alert"` 显示 `会话正在生成，请稍候`，列表被重新读取

#### Scenario: 删除请求中
- **WHEN** 确认删除而 DELETE 尚未返回，点击 `关闭`，再从菜单对同一会话选择 `删除`；随后响应 204 到达
- **THEN** 请求中取消按钮文案为 `关闭`；重新打开的确认框其确认按钮仍忙碌禁用，没有第二个 DELETE；204 后确认框关闭、条目消失
- **WHEN** 删除请求发出时当前会话是它，响应到达前已切到另一会话
- **THEN** 204 后条目消失，URL 与主区停在另一会话
