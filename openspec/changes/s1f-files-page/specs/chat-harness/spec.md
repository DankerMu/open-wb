### Requirement: UI 走查临时空间、撤回与归档
`web/e2e/ui-walk-sessions.spec.ts` SHALL 在既有旅程的全部步骤之后，于两个 project 中各追加以下步骤——作为同一文件里紧随其后的第二个串行旅程，自带登录、退出登录与 error oracle 实例，每个实例的预期 401 次数与既有旅程相同（单个旅程有 30 秒的单测上限，六步含两个真实回合，放不进既有旅程）（实现放在新的 helper 模块 `web/e2e/ui-walk-session-list.ts`，不给已近 800 行的 `ui-walk-sessions.spec.ts` 与 `ui-walk-layout.ts` 加行；真实服务栈、真实 omp、受控上游，不做浏览器路由拦截、不用假 EventSource、不任意 sleep，沿用同一 error oracle）：
1. **临时空间**：在欢迎态确认能力栏按钮为 `任务启动于 未选择`，发送 `WORKBUDDY_WRITE 临时空间走查 <uuid>`。被观察（不被拦截）的 `POST /api/sessions` 请求体解析后不含 `workspaceId` 键，201 响应的 `temporaryWorkspace` 为 true。回合到达固定回复与完成态后：能力栏同一位置为只读文本 `任务启动于 临时空间`；侧栏里该会话恰一次出现在分组 `临时空间` 内；助手消息里名为 `文件变更（1 个）` 的卡片有一行 `写入` 与 `workbuddy-report.html`（只有空间内相对路径）并有 `查看详情 workbuddy-report.html` 按钮，其后有一张 `HTML` 产物卡，点击 `打开网页预览 workbuddy-report.html` 打开工作空间侧边栏（`desktop-light` 为名为 `工作空间侧边栏` 的 `complementary` 区域，`mobile-dark` 为同名对话框；头部标题为 `工作空间`，没有 `在文件页打开`）并以渲染视图选中该文件：一个 `src` 以该页面自己那次 `POST /api/workspaces/<该会话的 workspaceId>/preview-token` 响应的 `base` 开头、`sandbox` 属性恰为 `allow-scripts allow-forms allow-modals` 的 iframe，文档里有标题 `WorkBuddy`；页面没有 `srcdoc` iframe，也没有以文件名为名的对话框；关闭侧边栏后继续（turn-artifacts「产物卡」：临时空间会话照常渲染产物卡；workspace-sidebar「顶栏入口与可用性」：侧边栏不区分正式与临时空间）；经页面的请求上下文，`GET /api/workspaces` 不含该会话的 `workspaceId`，`GET /api/workspaces/<该 id>/tree` 的 `entries` 含 `workbuddy-report.html`。
2. **列表事件**：自本组步骤开头的一次导航起至第 6 步结束，恰观察到一条指向 `/api/sessions/events` 的请求处于打开状态（响应 `content-type` 以 `text/event-stream` 开头）；第 1 步发送后，侧栏该会话的状态元素先读作 `<title> 运行中`、回合结束后读作 `<title> 已完成`，其间走查没有触发任何页面导航或手动刷新。

`mobile-dark` 下侧栏操作经导航覆盖层进行。这些步骤 SHALL 不留下它们创建的会话与临时空间。`web/playwright.config.ts` 的 `testMatch`、projects 与其它取值不变；全部旅程仍 SHALL 在既有 `globalTimeout` 内完成，每个旅程在既有的单测 `timeout` 内完成。转正（`另存为工作空间`）不进走查与冒烟（没有删除工作空间的端点，重复运行会不断留下空间），由服务端测试与整页测试覆盖。
