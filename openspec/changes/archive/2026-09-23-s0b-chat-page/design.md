## Decisions
### Governing invariant and ownership
Only the current page operation for the current client epoch and selected session may commit visible history/errors/list updates, navigate, or open a source. Every page-owned request has an abort signal and an identity guard because transports may ignore abort. Cleanup closes the connector, aborts reads/mutations and fences late success/failure; old current-401 cannot log out a newer account (existing client owner enforces auth).
Use `useMemo(() => createSessionClient(), [createSessionClient])`, as FilesPage. Do not cache across epoch. Connector callbacks synchronous; no async/thenable callback return. Use named types at owner; no concrete ReturnType/Awaited<ReturnType> contracts. If helper splitting is needed, one canonical implementation per operation; no generic lifecycle framework.

### Selection and loading
URL owns selection. Absent session means empty state+composer even when list nonempty; no first-row auto selection. Deep-link GET is authoritative, not list-membership gated (list can be stale). Initial 404 means inaccessible empty state; replace-remove only session query, preserve other search/hash, no source. Other load failures show inline failure; never show prior session history under a new URL. User select/new pushes history; cleanup and current-target guards govern Back and pending navigation. Fetch snapshot before constructing native EventSource; seed initialCursor and let connector own each open/gap recovery. Resolve EventSource at effect time so tests may inject existing fake; no module-global capture or browser fallback.

### Prompt and create transaction
Whitespace-only draft cannot send; preserve raw submitted text through ApiClient, server owns trim/byte validation/title. Busy guard synchronous against double submit; disable composer while submitting/loading an accepted turn or authoritative session running; generation label 生成中. No speculative assistant or user rows on failed acceptance (502 server rollback removes both). A successful 202 may arrive after terminal events: **do not reset status to running or blindly append rows**. Reconcile via current authoritative getMessages and a new connector seeded from that snapshot, closing/fencing the replaced connector before installing the new snapshot. This intentionally costs one snapshot/source replacement per accepted prompt and avoids parallel cursor ledgers; the normal connector open snapshot still closes REST→SSE gaps. Refetch list after accepted prompt/create for server title/order; event/snapshot status updates selected row without fabricating timestamps/title truncation. Refresh failures cannot erase good current history or duplicate send.
For empty selection, one user send owns create→prompt for the returned ID, and updates the URL to that ID. Its own creation navigation must not cancel its pending prompt, while explicit user selection/new navigation, unmount or epoch change must cancel/fence it. Keep ownership explicit and prove StrictMode/double-click and stale-create navigation; no effect that repeats a POST just because React reruns setup. New-session button creates/selects without dispatching a prompt. Creating/loading/submitting affordances must not open concurrent duplicate mutations.

### Error and terminal presentation
409/502 show exact ApiError message; business error stays attached to target message via reducer. Current401 belongs to AuthGuard, not inline alert. Native temporary network errors remain connector-owned reconnect, not failed messages. Terminal connector error shows safe stable request-failure text (ApiError envelope message when available), preserves last data, and explains refresh is required; no hidden retries or invented terminal status. If last server status is running, composer remains locked until a later authoritative load (e.g. full browser refresh) proves otherwise. This explicitly reports loss of synchronization, not a permanently silent generating state. Logout means confirmed successful/current401 auth transition; pending/failed logout leaves existing authenticated page per canonical contract.

### View and conventions
Semantic accessible heading/list/buttons/labeled textarea, alert/status regions; existing inline-style conventions. List server order updatedAt descending, server deterministic ties retained; title fallback 新会话. User and assistant content React text nodes with preserved whitespace, no HTML execution or truncation; step name/detail and running/done/failed shown, no demo todo/duration or stop button. Per-message keys use owner IDs, no index alias. Maintain one shell nav aria-current; session selection uses its own accessible selection state outside shell nav.
