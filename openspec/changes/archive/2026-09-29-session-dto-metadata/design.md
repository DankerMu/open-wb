# Design: session-dto-metadata（#517）

父设计：D11「DTO 键扩展必须同刀」「既有夹具迁移（同刀例外）」、D2「web API 客户端」段；tasks.md 头部「增长例外」5.1 条。行号为 origin/master。

- **Change surface**：
  - server：`server/src/sessions/store.ts`（`SessionView` :40-46、`StepView` :48-57、`MessageView` :59-68、`SESSION_COLUMNS` :216-217（仅 :248 列表、:262 快照、:372 fork 读取使用）、`SessionDbRow`、`create()` :241 返回的字面量、`toSessionView` :619-627）；`server/src/sessions/store-branch.ts`（`MessageDbRow`/`StepDbRow`、`MESSAGE_COLUMNS` :26-27、`STEP_COLUMNS` :28-29、`toMessageView` :37-48、`toStepView` :50-62）；`server/src/sessions/rest.ts`（`PublicSession` :35-41、`PublicStep` :43-50、`PublicMessage` :52-60、`toPublicSession` :266-280、`toPublicHistory` :282-305）。
  - web：`web/src/lib/session-contract.ts`（`ChatSession`/`ChatStep`/`ChatMessage` 类型 :7-32、`parseSession` :98-116、`parseStep` :118-136、`parseMessage` :138-164）；`web/src/lib/api.ts`（`ApiClient` 类型中的 `createSession` 声明与两个新方法声明，只加类型）；`web/src/lib/api-sessions.ts`（`Pick<ApiClient, …>` 列表、`createSession` :80-96、新增两方法）；`web/src/features/chat/page.tsx:466` 调用形状。
  - 测试：新建 `server/test/session-meta-fixtures.ts`、`server/test/session-snapshot-metadata.test.ts`、`web/test/session-meta-fixtures.ts`、`web/test/session-contract-metadata.test.ts`、`web/test/api-sessions-metadata.test.ts`；既有测试按「夹具迁移」只改期望值/调用形状。
- **Must preserve**：
  - 既有五键、消息七键、步骤六键的每条值规则不变（`SESSION_ID`、状态枚举含 `stopped`、有符号消息时间戳、非负 session 时间戳/ordinal、`approvals` 规则、步骤 `output` 字符串），`parent_session_id`/`omp_session_file`/`stream_epoch`/`owner_id`/步骤 `startedAt`/`endedAt` 仍不出公开 DTO。
  - 列表排序、快照 preParsing 同栈捕获 tree + streamCursor、404/401 次序、no-store 等 REST 行为逐字不变。
  - 活跃回合 pending 正文拼接（`store.ts:295`）不变；`thinking` 只读列值，不拼接任何缓冲（缓冲属 3.3）。
  - `copyForkHistory`/`commitFork` 的显式列插入不变（fork 继承与 thinking/changes 拷贝归 4.4）；`MESSAGE_COLUMNS`/`STEP_COLUMNS` 只用于 `store.ts:270/:275` 两处快照 SELECT，`store-branch.ts:165-174` 的 fork INSERT…SELECT 均为显式列，增列不影响任何插入。
  - web `features/chat/stream.ts` 视图模型与 SSE 解码不改：`step.end` 已按 `{messageId,stepId,status,output}` 严格键集解码，带 `changes` 键即非法 payload → 既有重同步（本刀以测试钉住，不改码）。
  - 其余 `ApiClient` 方法、错误信封、401 通知、same-origin/no-store 行为不变；`stopSession` 等既有方法零改动。
- **Must add/change**：
  - server 投影：
    - `create()`（`store.ts:241`）返回的字面量同刀补 `scene: null, workspaceId: null, pinnedAt: null`（新建行三列恒 NULL，4.1 再改）。`SESSION_COLUMNS` 追加 `workspace_id, scene, pinned_at`；`toSessionView` 追加 `scene: row.scene`（TEXT/NULL，CHECK 已限三值）、`workspaceId: row.workspace_id`、`pinnedAt: row.pinned_at === null ? null : Number(row.pinned_at)`；键序 `id,title,status,createdAt,updatedAt,scene,workspaceId,pinnedAt`。
    - `MESSAGE_COLUMNS` 追加 `CAST(thinking AS BLOB) AS thinking`（沿用正文列的 BLOB 解码惯例），`toMessageView` 增 `thinking: decodeNullableText(decoder, row.thinking)`；用户消息不特判（列 NULL 即 null）。
    - `STEP_COLUMNS` 追加 `CAST(s.changes AS BLOB) AS changes`，`toStepView` 增 `changes: row.changes === null ? null : (JSON.parse(decoder.decode(row.changes)) as FileChangeView[])`，`FileChangeView = {path: string; added: number | null; removed: number | null; kind: "edit" | "write"}`（`store.ts` 内声明、不导出，供导出的 `StepView` 使用；`rest.ts` 以 `StepView["changes"]` 引用，不新增导出，不新增校验：写入端 3.4 负责元素合法性；损坏 JSON 抛错即请求 5xx，不静默吞掉）。
    - `rest.ts`：`PublicSession` 八键、`PublicMessage` 增 `thinking: string | null`、`PublicStep` 增 `changes`；`toPublicSession` 逐键拷贝八键（列表、创建、快照、fork 201 均经此函数——实现时确认 list/create 路径也经 `toPublicSession` 或等价逐键映射）；`toPublicHistory` 逐键拷贝 `thinking` 与 `changes`（键序：消息 `id,role,content,thinking,status,createdAt,approvals,steps`，步骤 `id,ordinal,name,detail,output,changes,status`，与 spec 列举一致）。
  - web 契约：
    - `ChatSession` 增 `scene: "office"|"code"|"design"|null`、`workspaceId: string|null`、`pinnedAt: number|null`；`parseSession` 以八键 `hasExactlyKeys` 并校验：`scene` 三值或 null、`workspaceId` 为 `/^[0-9a-f]{32}$/` 或 null、`pinnedAt` 为 `isNonNegativeSafeInteger` 或 null。列表、`createSession`、`patchSession`、快照 `session`、`parseSessionFork` 共用 `parseSession`。
    - `ChatMessage` 增 `thinking: string|null`；`parseMessage` 八键（原七键 + `thinking`）；`role==="user"` 且 `thinking!==null` → 整体拒绝。
    - `ChatStep` 增 `changes: ChatFileChange[]|null`；`parseStep` 七键；`changes` 为 null 或 1..50 元素数组（`[]` 与 >50 拒绝），元素 `hasExactlyKeys(["path","added","removed","kind"])`、`path` 非空字符串、`kind:"edit"` 时 `added`/`removed` 为非负安全整数、`kind:"write"` 时二者恰为 null、其余 `kind` 拒绝。认知复杂度 ≤15（按需拆出 `parseFileChange`/`parseSessionMeta` 私有函数）。
  - web 客户端：
    - `ApiClient.createSession(input?: ChatSessionCreateInput, options?: ApiRequestOptions)`，`ChatSessionCreateInput = {workspaceId?: string; scene?: "office"|"code"|"design"}`；input 为 `undefined` 或无自有键的空对象 → 请求与现状相同（无 body、无 `Content-Type`）；否则 `body: JSON.stringify(input)`（原样、恰含所给键，客户端不校验值）并带 `Content-Type: application/json`（沿用 `prompt`/`forkSession` 发送 JSON 的既有方式）。成功恰 201，`parseSession`。
    - `patchSession(id, patch: {title?: string; scene?: …; pinned?: boolean}, options?)`：`Object.keys(patch).length === 0` → 不发请求、返回 `Promise.reject(new TypeError(...))`；否则 `PATCH /api/sessions/${encodeURIComponent(id)}`、JSON body 原样、成功恰 200、`parseSession` 失败 → `requestFailed(200)`。
    - `deleteSession(id, options?)`：`DELETE` 同路径、无 body；按 `stopSession` 的 `fetchResponse` 模式：`204` → `undefined` 且不读响应体；其它 2xx（含 200）→ `requestFailed(status)`；非 2xx 走既有错误信封/401 解析（与 `stopSession` 非成功分支同一路径）。
    - `page.tsx:466` 改 `.createSession(undefined, { signal: controller.signal })`。
  - 共享夹具常量（同刀迁移例外）：`server/test/session-meta-fixtures.ts` 导出 `NULL_SESSION_META = {scene: null, workspaceId: null, pinnedAt: null} as const`（以及如需要 `NULL_THINKING = {thinking: null}`、`NULL_CHANGES = {changes: null}`，或直接内联 `thinking: null`/`changes: null`——二选一全仓一致）；web `web/test/session-meta-fixtures.ts` 同名常量。既有测试文件只允许三种改动：(a) 在对象字面量**末尾**加一行 `...NULL_SESSION_META,`（或 `thinking: null,`/`changes: null,`，位置与公开键序一致——`session-fork-rest.test.ts:141-155` 以 `JSON.stringify` 比较，对键序敏感）及一行 import；(b) 按值断言的键数组原地改为新键集（会话八键、消息八键 `thinking` 按其排序位插入、步骤七键），或改为引用 `session-meta-fixtures.ts` 导出的 `SESSION_VIEW_KEYS` 的单行替换——已知 `session-fork-rest.test.ts:158`、`session-fork-rest-real.test.ts:88`（`SESSION_KEYS`）、`session-fork.test.ts:117-123`、`session-approval-snapshot.test.ts:32`（`MESSAGE_KEYS`）；(c) 调用形状 `createSession(options)` → `createSession(undefined, options)`（`web/test/api-sessions.test.ts:81/:137`）。`server/test/session-rest.test.ts:58-64` 五键 `toEqual` 整段迁出到 `session-snapshot-metadata.test.ts` 改八键；`session-rest.test.ts:468-474` 为 DB 行 `objectContaining`、无需补键。已知需迁移文件（至少，以 `make typecheck` + `make test` 为准）：server `session-rest.test.ts`、`session-snapshot.test.ts`、`session-store.test.ts`、`session-fork-rest.test.ts`、`session-fork-rest-real.test.ts`、`session-fork.test.ts`、`session-approval-snapshot.test.ts`、`session-store-stopped.test.ts:155-205`、`session-supervisor.test.ts:129-137`；web 任务行所列文件加 `api-turn-control.test.ts:16-22`、`chat-approval-bar.test.tsx:472-480`、`chat-fork-button.test.tsx:55-56`、`chat-stop-button.test.tsx:40-41`、`chat-stream-approvals.test.ts:64,76`、`chat-stream-stopped.test.ts:13-28`。清单外需改的文件同样只允许 (a)–(c) 并在 PR 列出。PR 记录 `session-rest.test.ts` 前后行数（现 777，预计净 +10～+12，≤800）。
