## Context
Current ring and cursor contracts are canonical in chat-stream/chat-sessions after #214. `RingBuffer.push` assigns IDs once; Supervisor records after persistence and before the optional external onEvent. Owner authorization is store.getMessages, not trusted runtimeState. Prior characterization at /tmp/open-wb-issue103-evidence shows inject(payloadAsStream:true) resolves at writeHead, AbortSignal closes its raw response, and real socket abort does too. Native revoke precedes pump drain; onExit is not an all-generation cleanup hook.

## Goals / Non-Goals
Goals: authenticated real SSE delivery with no replay/live gaps, cross-owner leakage, duplicate sequence source or unbounded client queue; disconnect one client without stopping another or the runtime.
Non-goals: browser EventSource/reducer/page (#92/#93/#104), durable event log, retry policy, new epochs/ring semantics, snapshot production (#214), async external sink support (#204), existing claim bookkeeping (#219).

## Governing invariant and sibling surfaces
Each SSE data frame denotes exactly one already-recorded canonical event from the same generation; a connection's replay precedes its live successors without omission/duplication. A sealed snapshot epoch cannot publish later. Auth must complete before raw headers/frames. Audit live/replay/refresh/gap/no-runtime, idle/re-acquire/native drain, external sink failure, HTTP disconnect/error/backpressure and app preClose; preserve REST snapshot, ring min−1, native-before-DB teardown and observer return guards.

## Decisions
1. Supervisor owns subscription registration and synchronous ring read as one non-awaiting operation. Return owner-named receipt/replay/unsubscribe types; transport owns response/timer handles. Subscribers are session-scoped (can connect before a runtime and survive generation replacement); rings remain current-generation-only. No additional ring or data sequence. On publication deliver the retained ID and canonical payload after recording, independently of optional diagnostic observer; preserve onEvent's original return guard, never wrap/drop its return. Client writer failures are contained to that subscriber.
2. Read replay from the existing ring with the current trusted turn-running state, after the route authorizes owner. No ring: cursor-present or running means gap; no cursor plus nonrunning means fresh. Empty Last-Event-ID is a present malformed cursor. Never create a generation to satisfy a read. Register, read and begin initial replay in one synchronous route stack; only bounded write backpressure may defer the remaining replay under decision4, never allowing live delivery to overtake it.
3. Use existing global cookie guard, route no-store, owner getMessages before hijack/writeHead. Raw response explicitly supplies200/text-event-stream UTF8/no-store/keep-alive; Fastify reply-only headers do not survive raw hijack automatically. Frames are id/event/data JSON plus blank line; controls use empty id. Keepalive is comment-only every15000ms and uses injected clock (reuse the existing SessionClock shape if appropriate); no initial fake event, no runtime allocated on GET.
4. No accumulating live-event queue. Retain only the at-most1000-record initial replay array already returned by the ring. During replay, raw.write(false) advances the accepted frame exactly once, pauses writes/heartbeats and resumes the suffix only on drain. A live event arriving while replay is paused ends/unsubscribes that client rather than queueing or overtaking replay. During ordinary live delivery, raw.write(false) immediately unsubscribes, cancels heartbeat and ends the response. Already-accepted bytes may flush; reconnect recovers any undelivered suffix without resending the accepted frame within one connection. Paused and end-pending responses remain owned until close and destroyable at preClose. Write throw/error closes only that client. This permits normal large replay without reconnect churn while bounding live-client buffering.
5. Disconnect/error/finish cleanup is idempotent. Transport owns all open raw responses and removes listeners/timers/subscriptions appropriately. Register preClose cleanup in sessions assembly BEFORE shutdown waits on long requests; close/destroy all live or end-pending responses, then retain existing supervisor→store→DB order. Direct supervisor shutdown clears its subscriptions, without invalidating #214 drain cursors or external observer semantics.

## Risks / Trade-offs
Raw streams bypass normal reply serialization, hence real headers/bytes tests. Ring holds1000 events, not1000bytes; one accepted frame can exceed writable high-water mark, but no further frame is queued after false. No absolute session-byte quota is introduced. A disconnected client must reconnect and may need #214 snapshot on gap. Local acceptance and candidate share OS user; protected fixtures/hashes plus independent CI are the boundary, not an OS enclave claim.

## Migration Plan
Additive route and required production wiring in one PR. Existing REST and core interfaces retain semantics; any new named subscriber DTO originates at its owner. Revert this PR to remove SSE without changing DB. Archive separately after source merge/CI.
