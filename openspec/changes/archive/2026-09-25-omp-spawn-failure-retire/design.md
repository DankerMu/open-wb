## Context
Node v24 `child_process`: a spawn that fails with ENOENT/EACCES/EAGAIN returns a ChildProcess with `pid === undefined`, then on the next tick `onErrorNT → onexit(err)` sets `exitCode` to a negative errno and emits `'error'`, never `'exit'`. Node also emits `'error'` on a *live* child when `kill()` fails or IPC send fails — so `'error'` alone does not mean "never spawned".

Change surface: `SessionRuntime` generation bookkeeping in `server/src/sessions/omp/runtime.ts` — `#spawnFor` (:326-357), `#runRetire` (:497-531), `#awaitChild` (:533-545), `#signal` (:551-556), `liveChild` (:670-676).
Must preserve:
- Live-child retirement timing: close stdin → SIGTERM at 5000 ms if alive → SIGKILL at 8000 ms (pinned by "closes stdin then TERM at 5000 and KILL at 8000 when shutdown races spawn return", `omp-runtime.test.ts:321-361`).
- Failed acquisition semantics: missing-bin / sync-throw / obstructed-dir reject with `AgentUnavailableError` at clock 0, token issued once and revoked once, resume path kept, retry succeeds (`expectFailedAcquisition`, `:747-784`); failed acquisition + shutdown leaves no timers (`:308-319`).
- A child that has a pid and later emits `'error'` (e.g. kill failure) is still treated as alive until it actually exits, so it still receives TERM/KILL.
- Token revoke exactly once per generation; `onExit` callback semantics; `#dropGeneration` ordering.
Must add/change: a generation whose child never obtained a pid has no live child from the moment `spawnImpl` returns; retire of such a generation completes without advancing the injected clock and without awaiting `nativeWait`.
Governing invariant: retire waits on TERM/KILL grace or native exit only for a child that actually obtained a pid and has not yet exited; a never-spawned child never costs grace time and never blocks shutdown, independent of Node's `exitCode` side effect.
Sibling surfaces: every `liveChild()` caller (`#runRetire` :506/:513/:524, `#awaitChild` :538/:544, `#signal` :552); the `'error'` handler at :338-342 (currently sets `spawnFailed` for any error, including errors on live children — must not become a liveness verdict); `#closeStdin` (:547-549, uses `gen.child ?? gen.proc.child`, harmless on a failed child); `OmpProcess.child` (`process.ts:246`) which is set even for pid-less children; `process.ts` `#failStartup` kill check (:642-648) and `#childDead` (:691-697), which also judge liveness by `exitCode`/`signalCode` — unchanged and out of scope; cancel path `stream.onCancel → #abandon → #retire`; supervisor shutdown `slot.runtime.shutdown()`.
Seams under test: public `SessionRuntime.prompt()` / `shutdown()` with the injected fake clock and injected `spawnImpl` in `server/test/omp-runtime.test.ts`.
Required evidence:
- Race: `openWorld({ spawnFailure: "missing-bin", shutdownInSpawn: true })` (harness extended so shutdown is started inside `spawnImpl` before the failure tick) → `runtime.shutdown()` settles with `clock.nowMs === 0`, `clock.pending() === 0`, `kills` empty, token revoked exactly once, prompt rejects `AgentUnavailableError`. Before the fix: shutdown only settles after `clock.advance(5_000)` (RED; implementer must show it).
- Boundary: custom `spawnImpl` returning a pid-less fake child that never emits `'error'` and never sets `exitCode`. `OmpProcess` boot has no other rejection source, so the test must settle boot deterministically — end the fake's stdout (handshake fails as closed transport) or pass a short `handshakeTimeoutMs` — and assert `kills` explicitly (the `process.ts` `#failStartup` SIGKILL at :642-648 may legitimately target the fake; the "no signal" claim is scoped to the runtime's retire `#signal`). Expected: shutdown settles at injected clock 0 with `clock.pending() === 0`, token revoked exactly once. Before the fix this hangs at `await gen.nativeWait.promise` (runtime.ts:527-529) even after advancing past 8000, so the test must use a bounded real-time wait (e.g. race with a short timeout) to report RED instead of hanging the suite.
- Guard: post-handshake `hang-term` child (via `openHangTerm()`), then emit `'error'` on that pid-bearing child while it keeps running (simulated kill/IPC failure) and retire via `shutdown()` → stdin closed, SIGTERM at 5000, SIGKILL at 8000 unless it truly exits. Must be post-handshake: an `'error'` during the handshake routes `#attach → #failIo → #terminateTransport → #failStartup` and SIGKILLs at clock 0 (process.ts:642-648), a different, already-correct path; after the handshake the error reaches `#onTransportError` (runtime.ts:415-428).
- All existing `omp-runtime.test.ts` / `omp-runtime-io.test.ts` cases pass unchanged.
Non-goals: EMFILE/ENFILE (null stdio) variant; `process.ts` spawn/handshake semantics; timing constants; supervisor changes; listener shutdown (#227).
Review focus: the liveness condition is pid-based, not `'error'`-based; no path leaves a live pid-bearing child unsignalled; revoke-once and dropGeneration ordering intact on the new early path; the harness change does not weaken the existing failure-branch assertions (`children` length 0, `kills` empty).
