## Decisions
1. Preserve the existing exported resolveServerConfig(env,entryUrl) seam in server.ts and import-without-main silence. Add the seven settings through one pure shared agent-configuration helper if app defaults require it; app MUST NOT import the production entry at runtime, duplicate parsing/defaults or read process.env. The entry remains the only environment reader and passes validated values into createApp. Existing createApp({db}) callers retain deterministic defaults, rooted via the same source/compiled module identity rule, not cwd. No compatibility aliases or alternate disabled-module assembly.
The public ServerConfig projection stays flat: retain host:string, port:number, dbPath:string, staticRoot:string, repoRoot:string; add ompBin:string, ompStateDir:string, ompIdleMs:number, sandboxRoot:string, modelUpstreamBaseUrl?:string, modelUpstreamApiKey?:string, modelId:string. Missing upstream fields read as undefined (absence or explicit undefined is semantically identical). Parent protected probes and writer tests use these exact field names on the existing resolver; this is not inferred from candidate code.
2. New paths OMP_BIN/OMP_STATE_DIR/SANDBOX_ROOT resolve exactly like existing paths: missing→repo default; explicit empty invalid; relative→entry root; absolute preserved. Upstream missing is legal; either missing means unavailable pair, never a fabricated credential. Explicit empty upstream values fail naming the key, without echoing value. No new URL-shape restriction or trimming. MODEL_ID missing uses deepseek-v4.1-flash; explicit values preserve bytes (no new model-registry validation).
3. User resolved the native timer boundary: OMP_IDLE_MS accepts canonical ASCII decimal integers1..2147483647, default600000; reject larger values with the key named before any IO. Node24.13.1 characterization showed2147483648 becomes1ms with TimeoutOverflowWarning. This explicit range refinement avoids silently changing idle semantics or expanding #101 into chunked runtime scheduling. No trimming, signs, exponent, fraction or leading-zero coercion.
4. createApp always registers auth → HTTP guard → model-proxy → sessions → existing misses/static. One registry instance is passed to both features. Trusted runtime/registry/upstream/event/error dependencies may be injected for real integration tests; they do not bypass module registration. Preserve Fastify return shape and caller DB identity; expose actual session handles only through a minimal typed app-owned surface if required, never re-register routes to obtain handles.
5. SessionSupervisor's callbacks remain synchronous. Default infrastructure observation must not log raw Error/config/credentials or lose shutdown fault retention; injectable test observers preserve current fault evidence. Reuse existing module preClose behavior. No new async logging/telemetry framework and no promise-returning sink contract hidden in this slice.
6. REST-only tests own a lower module seam with a stub supervisor dependency, so migrate their host to an existing canonical standalone auth/guard test pattern, not a production disable flag or alternate REST implementation. Real app assembly tests must still exercise actual registerSessions/real SQLite and prove cookie/bearer precedence; supervisor integration fixtures consume the app's constructed handles instead of duplicate registration. Migrate only affected callers, preserving assertions and cleanup.
7. STARTUP_MODULES has exactly core/db,auth,http,model-proxy,sessions and is tied to actual composition. Verify real route/auth/reconciliation behavior plus dependency registration observation at the module seam; do not accept source-text scans or an isolated constant assertion as proof of actual order. No generic plugin container or extra runtime telemetry merely to test wiring.
## Risks / Trade-offs
Default duplication/cycles→shared pure helper with entry-owned environment; manual test registration→atomic caller migration; automatic reconcile on every app→use migrated openDb handles and preserve stale-row recovery; cookie guard leakage into proxy→real mixed-auth HTTP assertions; secret output→unique sentinel tested in compiled startup success/failure capture without logging configuration. Native timer range is user-approved1..2147483647, not silently assumed.
