## Context
store.getMessages currently reads only SQLite (store.ts195-234); pending belongs to activeTurns by assistant ID (129-145), with2048B/2000ms persistence (370-391,625-653). REST caches the authorized tree in preParsing (rest.ts83-98), so reading a cursor later in the handler could label an older tree with a newer boundary. Supervisor persists/buffers then publishes (333-340); no production seq producer exists. Runtime revoke occurs before pipe drain (runtime.ts396,514-515,560-561); onExit covers only active-turn logical exits, not idle generations. RingBuffer is the only sequence authority and already supplies the approved min−1 replay semantics.

## Goals / Non-Goals
Goals: exact current history plus an atomic stream boundary; one sequence/retention owner; deterministic filtering of overlapping queued events; generation-safe release after residual publication; preserve204 synchronous-sink ownership.
Non-goals: SSE endpoint/subscribers/backpressure/keepalive (103), web connector/UI (92/93/104), per-event SQLite writes, changing durability/flush policy, migrations, distributed writers to the same database, arbitrary malicious observer side effects. The supported atomicity domain is this app's single synchronous DatabaseSync/store/Supervisor owner, not independently mutating external DB connections.

## Decisions
1. **Read-only complete history.** Update getMessages in place: decode the durable body once, append only that assistant's still-owned pending strings in order, preserve all row/status/step projections. Do not flush, arm/cancel timers, reset byte budgets, mark progress, mutate pending or expose buffer fields. Fault-retained pending data remains visible as current process-owned content, not a durability claim; after repair/flush it must appear once, never twice. Persisted bytes remain testable through direct SQLite queries. This explicitly replaces the old persisted-only read clause, not the2048B/2s persistence guarantee.
2. **Explicit boundary DTO.** Top-level streamCursor is exactly {epoch:number,seq:number|null}, canonical nonnegative safe integers. Numeric seq is the current generation's last recorded event, initially0. Null means all events of that epoch are covered/closed: no more events of that epoch can publish. Initial/no-runtime epoch0, fully retired generations and process-restarted persisted epochs use null. Do not use MAX_SAFE sentinels, invented next epochs, or retain unbounded completed-generation metadata just to remember a tail. A healthy runtime between turns remains numeric, even when session status is done.
3. **Single sequence authority.** Add a read-only RingBuffer sequence getter (initial0); push remains the only increment. Supervisor creates the ring after the existing epoch bump for each acquisition, before events, and records every successfully persisted/buffered canonical event before calling the optional external observer, including when no observer is configured. The existing external return reaches204's guard unchanged. Capture the exact generation context for each pump; never label late events using a mutable newer slot epoch. Reads do not allocate a fake event or consume seq. No replay API or unused SSE subscription scaffold is added here;103 will consume this same owned ring, not create a parallel counter/buffer.
4. **Generation ownership and sealing.** Track native revocation separately from dispatch/pump publication ownership. Acquisition/dispatch may be pending before a pump exists; that reservation prevents sealing before the first queued frames can publish. Native revoke marks the captured generation retired but retains its ring while dispatch resolution or any of its pumps can still publish. Final pump/dispatch release disposes a revoked ring only for the same generation. Idle/between-turn exits with no publication work release immediately. Do not await a pump from inside its own retirement; retain the slot/context until publication cleanup can release it, and guard deletion/release against a replacement slot/generation. Shutdown must still finish native/pump work before store close. Healthy same-generation next turns continue the sequence. Failed acquisition may advance epoch with zero events, then seals it.
5. **Atomic REST capture.** Extend the required SessionSupervisorPort with synchronous streamCursor(sessionId), backed by the already-authorized session's persisted epoch and current owned generation. This accessor is trusted bookkeeping, not authorization. The existing owner-scoped getMessages null check remains first. In the same synchronous preParsing stack, capture the complete tree and cursor into the request-owned cached snapshot; the handler only projects that snapshot. No await, external observer, body parsing or later cursor read may split the pair. Unknown/foreign IDs produce the same404 without querying/publishing another owner's boundary. Only the new declared streamCursor exposes epoch; owner/resume/token/step timing fields remain private. Test stub ports must implement the new required method explicitly; no optional fallback or legacy DTO mode.
6. **Downstream reconciliation contract.** On initial load or gap, buffer incoming events while fetching the complete snapshot. Replace history, then discard event epochs below snapshot.epoch; for equal epoch discard all when seq=null, otherwise discard seq<=snapshot.seq; apply equal-epoch successors or higher-epoch events in original order. Apply this to turn.start/step/text/end/error, not just text, so an old replayed turn.start cannot erase the snapshot. A higher epoch starts its sequence at1. Superseded loads/session changes must not install stale responses (93). Repeated gap while loading requires another authoritative reload before queued events are trusted; bounded overflow triggers resynchronization rather than silent loss (103/93 concrete transport work). A gap control frame has empty id and no sequence. No browser implementation is claimed in214; an independent reference reducer validates the concrete overlap example.

## Risks / Trade-offs
- Complete views contain non-durable bytes -> document process-kill loss remains bounded only by existing writable-store flush policy; never claim GET persisted them.
- Slot retirement previously deleted state before a pump necessarily settled -> identity-bound deferred release must not deadlock or leak. The existing unrelated claim-release race is tracked separately; do not silently fold it into this change.
- No new epoch per turn -> current running status is not sufficient to choose numeric vs sealed; use generation ownership.
- Native token revocation is earlier than publication completion -> keep both states explicit; no timer-delay heuristic.
- API shape changes -> migrate all current server test ports/DTO expectations and downstream issue/spec contracts atomically; web callers do not exist yet.

## Migration and Rollback
No DB migration. Deploy source and its DTO consumers together; rollback the feature commit restores the previous REST contract and ring ownership. Pending memory follows existing shutdown semantics; no fallback implementation remains. Source PR and separate archive PR each require independent CI before103.
