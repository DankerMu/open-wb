# Design: api-sessions-split（#471）

父设计：「模块拆分（size-guard）」。行号均为 origin/master（16f9728）的 `web/src/lib/api.ts`。

- **Change surface**：`web/src/lib/api.ts`（749 行）→ 新 `web/src/lib/api-sessions.ts`。
- **Must preserve**：`api.ts` 导出集合逐字不变——`Principal`/`ServiceInfo`/`LoginCredentials`（18-33）、`ApiClient`（114-141，声明文本含会话四签名 133-140 原样保留）、`ApiClientOptions`（143-145）、`REQUEST_FAILED_MESSAGE`（147）、`ApiError`（151-161）、`createApiClient`（516）；不新增任何 `export`。四方法的路径、HTTP 方法、body、`credentials:"same-origin"`、`cache:"no-store"`、signal 透传、`expectedStatus`（200/201/200/202）与 `requestFailed(<status>)` 参数逐字不变；`onUnauthorized` 以闭包原引用传入工厂（401 通知路径 `parseJsonResponse`→`notifyUnauthorized` 385-394/445-479 不动）；返回对象属性枚举次序不变（会话四方法仍在最前）。
- **既有导入方（全部不改）**：`web/src/features/settings/page.tsx:2`、`chat/{errors.ts:1,types.ts:1,page.tsx:3,ownership.ts:1}`、`auth/{quick-login.tsx:2,provider.tsx:21}`、`files/{errors.ts:1,preview.tsx:9,tree.tsx:2,page.tsx:3}`；测试 `web/test/{api.test.ts,api-files.test.ts,api-info-logout.test.ts,api-sessions.test.ts,auth-session-client.test.tsx,topbar.test.tsx,support.ts,chat-page-lifecycle-support.tsx}`（均只经 `../src/lib/api.js` 取公开导出）。
- **Must add/change**（搬迁清单；搬迁块逐字，缩进不变（原文在 `createApiClient` → `return {` 下为 4 格，工厂 `createSessionMethods` → `return {` 同为两层嵌套 4 格；`sessionEndpoint` 两边均为顶层），故普通 `--color-moved=dimmed-zebra` 即可识别整块移动）：
  - `api-sessions.ts` ← `sessionEndpoint`（345-347）、`listSessions`/`createSession`/`getMessages`/`prompt` 四个方法（518-584）；`parseSession`/`parseSessionList`/`parseMessageSnapshot`/`parsePromptAccepted` 的值导入（原 12-15）随之迁入。
  - 新增胶水（唯一允许的非搬迁代码）：非导出类型 `SessionTransport = { request(path, options, onUnauthorized, expectedStatus?): Promise<unknown>; requestOptions(signal?): RequestInit; getRequestOptions(signal?): RequestInit; requestFailed(status): ApiError }`；唯一导出 `createSessionMethods(onUnauthorized: ApiClientOptions["onUnauthorized"], { getRequestOptions, request, requestFailed, requestOptions }: SessionTransport): Pick<ApiClient, "listSessions" | "createSession" | "getMessages" | "prompt">`，函数体为 `return { <四方法原文> };`。方法参数类型由 `Pick` 返回类型上下文推断，故无需导出 `ApiRequestOptions`（110-112）。只注入四方法实际用到的四个辅助，不预注入 `fetchResponse`/`parseJsonResponse`/`isSuccessfulStatus`（biome `noUnusedVariables`）。
  - `api.ts`：删 345-348、518-585；7-16 的 `session-contract.js` 导入改为 `import type { ChatMessageSnapshot, ChatPromptAccepted, ChatSession, ChatSessionList }`；加 `import { createSessionMethods } from "./api-sessions.js"`；返回对象首项为 `...createSessionMethods(onUnauthorized, { getRequestOptions, request, requestFailed, requestOptions }),`（biome 折为 6 行）。
  - 依赖方向（有向无环）：值导入只有 `api.ts → api-sessions.ts`、`api-sessions.ts → session-contract.ts`；`api-sessions.ts → api.ts` 只有 `import type { ApiClient, ApiClientOptions, ApiError }`（三者本已导出，**`api.ts` 零处新增 export**）。
  - 行数（一次性证据，已在草稿镜像中以 biome 格式化实测）：`api.ts` 749 − 4 − 68 − 10 + 6（`import type` 四类型折 6 行）+ 1（`api-sessions.js` 导入）+ 6（展开项折 6 行）+ 1（展开项后空行）= 681，上限 ≤ 700，为 7.1（`ApiClient` 四签名约 20 行 + 注入参数扩展）留出 ≥100 行；`api-sessions.ts` ≈ 98 行。
- **Governing invariant**：对同一 fetch 序列，`createApiClient(opts)` 产出的请求、返回值、`ApiError`（status/code/message）与 `onUnauthorized` 调用完全一致。
- **Sibling surfaces**：`session-contract.ts`/`api-json.ts`（DTO 与共享校验，零改动）；非会话方法与 `previewRequest`/`logoutRequest`（留 `api.ts`，零改动）。**必然破坏的既有测试：无**——测试只用 `createApiClient`/类型公开导出；允许的既有测试编辑：无（`web/test/**` 零 diff）。同名 `web/test/api-sessions.test.ts` 已存在且经 `api.js` 覆盖四方法全部成功/拒绝分支，新文件覆盖率在草稿镜像实测 100%。
- **Seams under test**：既有 web vitest 套件原样（`createApiClient` + 注入 `fetch` 桩，见 `web/test/support.ts`）；无新增测试，全部为 guards, always green（无 red-first）。
- **Required evidence**：`git diff --stat origin/master -- web/test web/src/features web/src/lib/session-contract.ts server Makefile .github` 为空；`npm test --workspace web` 全绿且为 53 文件 / 1017 例（与 master 相同）；`bash scripts/size-guard.sh` 0、`wc -l web/src/lib/api.ts` ≤ 700；`grep -n 'from "./api.js"' web/src/lib/api-sessions.ts` 恰一行且以 `import type` 开头；`make lint`、`make typecheck`、`make anti-drift`（knip 零新增、jscpd 不升高）、`npm run build --workspace web` 0；`git diff --color-moved=dimmed-zebra -- web/src/lib` 只见搬迁块、import 行与上述胶水。
- **7.1 注意（carry-forward）**：`stopSession` 的 202 严格 `{}`/204 无 body 需 `fetchResponse`/`isSuccessfulStatus`/`parseJsonResponse`，届时扩 `SessionTransport` 注入，仍不得从 `api.js` 值导入。
- **Non-goals**：见 proposal。
- **Review focus**：方法体逐字；展开位于首项且无同名键覆盖；`api.ts` 导出集合与 `ApiClient` 声明文本不变；`api-sessions.ts` 对 `api.js` 仅 type-only；无新测试/新行为。
