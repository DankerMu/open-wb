## MODIFIED Requirements

### Requirement: REST prompt 受理与补偿
The prompt route SHALL accept only application/json and an object with exactly message:string. It SHALL trim the string once and require nonempty text of at most32768 UTF-8 bytes. Invalid shape, media, malformed JSON or oversized parser envelope SHALL return400 bad_request; decoded valid escape-heavy text SHALL NOT be rejected merely because its wire JSON exceeds32768 bytes. The existing bounded parser envelope remains distinct from the semantic message limit. A trimmed text that starts with `/` SHALL NOT be rejected for that reason: Requirement「Slash 命令白名单与命令目录」 decides whether it reaches omp as a command or as plain text.
The route SHALL use store.acceptPrompt(sessionId,principal.id,text) with the trimmed original text for the atomic admission (persisted user content and the title rule are unchanged) and then await supervisor.prompt(sessionId, toWireText(text, listSkills(agentDir))) where `toWireText`/`listSkills` are those of Requirement「Slash 命令白名单与命令目录」 (identity for every text that does not start with `/` and for whitelisted commands; a leading U+0020 otherwise) and `agentDir` is the registerSessionRoutes dependency of Requirement「会话 REST」. The owned SessionSupervisorPort SHALL expose prompt(sessionId:string,text:string):Promise<void>; resolution means dispatch accepted, not turn finished. Successful admission SHALL return202 {userMessageId,assistantMessageId} from that exact store admission. Running sessions SHALL return409 session_busy without added rows or dispatch; so SHALL a session whose supervisor control claim is held by an in-progress regenerate, fork or stop — the claim check and admission SHALL run without an intervening await; idle/done/failed/stopped SHALL be eligible.
Supervisor rejection SHALL compensate the unprogressed accepted pair through store.rollbackPrompt before returning the canonical error. HttpError agent_unavailable SHALL produce502, HttpError session_busy SHALL produce409, HttpError agent_capacity SHALL produce503; unknown failures SHALL remain generic5xx. Compensation failure SHALL propagate as generic5xx, not be masked as502/409/503. The supervisor SHALL NOT reject after publishing/persisting progress; post-dispatch failures belong to supervisor lifecycle. No retries or real runtime/SSE implementation are part of this boundary.

#### Scenario: Accepted prompt and concurrent busy
- **WHEN** a valid prompt is admitted while the stub supervisor is held pending
- **THEN** the real store has one user-done and one empty assistant-running message, with trimmed text and title; a concurrent second prompt returns409 without changing rows
- **WHEN** the pending supervisor resolves
- **THEN** the first request returns202 with precisely those two IDs, without waiting for terminal turn completion
- **WHEN** a valid prompt arrives while a regenerate, fork or stop holds that session's control claim
- **THEN** 409 session_busy is returned with no added rows and no dispatch

#### Scenario: Input boundaries
- **WHEN** message is empty after trim, has a wrong type, is in an array/null/extra-key object, or exceeds32768 decoded UTF-8 bytes, or the request has wrong media/malformed JSON/oversized envelope
- **THEN** 400 bad_request/no-store occurs without admission or dispatch
- **WHEN** trimmed text is exactly32768 UTF-8 bytes, including multibyte and JSON-escaped content, and does not start with `/`
- **THEN** 202 is possible and the same trimmed text reaches storage and supervisor

#### Scenario: Slash text reaches storage as typed and omp as decided
- **WHEN** the owner prompts `/todo`, `/todo append 买菜`, `/skill:weekly-report 写周报`, `  /session delete`, `/TODO`, `/skill:nope` and `/etc/hosts 是什么` on idle sessions with a stub supervisor, the app created through createApp with `weekly-report/SKILL.md` (name and description present) installed under `<OMP_STATE_DIR>/home/.omp/agent/skills`
- **THEN** every request returns202, the persisted user content is the trimmed original (`/session delete`, `/TODO`, …), the stub supervisor received `/todo`, `/todo append 买菜` and `/skill:weekly-report 写周报` unchanged and ` /session delete`, ` /TODO`, ` /skill:nope` and ` /etc/hosts 是什么` (one leading U+0020) for the rest, and the title of a fresh session is the 18-codepoint prefix of the original text

#### Scenario: Failed dispatch restores prior state
- **WHEN** the stub supervisor rejects with canonical agent_unavailable, session_busy or agent_capacity after a new admission from idle/done/failed/stopped
- **THEN** 502, 409 or 503 respectively is returned, prior title/status/updatedAt/history is preserved and the admitted pair removed; a later prompt can succeed
- **WHEN** admission itself rejects
- **THEN** the supervisor is not called and another active turn is not rolled back

#### Scenario: Unknown and compensation failures
- **WHEN** the supervisor throws an untyped error, including a forged status/code shape
- **THEN** its unprogressed admission is compensated and the response is generic5xx without leaking raw error data
- **WHEN** rollback itself fails
- **THEN** generic5xx is returned without falsely reporting restored state or masking the storage failure as agent_unavailable

#### Scenario: Terminal sessions can prompt again
- **WHEN** the real store completes an accepted turn as done, failed or stopped, and the owner sends another valid prompt
- **THEN** the next prompt returns202 with new IDs, retaining previous history and the established title

### Requirement: Session module registration and teardown
registerSessions SHALL construct the store/supervisor from caller-owned DB, shared tokens, runtime options, the workspace store's owner-scoped `rootOf` (the same workspace store createApp builds; sessions SHALL NOT construct a second workspace store or compute workspace roots itself) and the omp agent directory `agentDir` (createApp passes `ompAgentDir(stateDir)` exported by `sessions/omp/process.ts`, the `<OMP_STATE_DIR>/home/.omp/agent` that omp resolves as its default agent directory under the spawn's `HOME` — omp-runtime「OMP_STATE_DIR 托管布局」; sessions SHALL NOT compute it a second way), pass the store the `core/audit` emit bound to that same DB (the workspace-store precedent) for approval-settlement audit rows, wire store flush notifications into supervisor ownership, reconcile stale running sessions/messages/steps (settling their pending approvals as reconcileOnStartup defines) before exposing REST, and return its store/supervisor handles. It SHALL register a preClose hook that waits for all supervisor runtime/pump cleanup before closing the store, never closing the caller DB. Optional event observation SHALL publish actual numeric-ID events; this change SHALL NOT claim SSE/replay or global startup assembly. The supervisor SHALL expose a public `retire(sessionId)` used by session deletion: it SHALL first await that session's in-flight event pump, if one exists (a turn whose terminal state was persisted just before retire thus still publishes its terminal event to the current subscribers before the generation is sealed), then run the existing bounded retire sequence of that session's live generation (stdin close and signal escalation, token revocation, process-cap release, generation sealing), await native exit, drop the session's slot and event ring, and end every SSE subscriber of that session without publishing a further event; for a session without a live generation it SHALL only drop ring/subscriber state and resolve. retire SHALL NOT write any SQLite row.

#### Scenario: Reconcile before route acceptance
- **WHEN** the module is registered on a real app with stale running rows
- **THEN** all three running row categories become failed before a request is admitted, terminal rows and caller data remain unchanged except the approval settlement defined by reconcileOnStartup (each pending approval of a failed message reads `deny` with `decided_at` and one `session.approval` audit row), and a new prompt can be accepted

#### Scenario: Shutdown ordering and isolation
- **WHEN** app.close runs with active sessions or a task/storage failure
- **THEN** new supervisor prompts are rejected, all children/tokens and pumps settle before store close, every approval still pending on a turn finalized by shutdown reads `deny` with one audit row, failures are propagated honestly and the caller DB remains usable

#### Scenario: Public retire for deletion
- **WHEN** retire(sessionId) is called for an idle session with a live real-fake child and two open SSE subscribers, and separately for a session with no live generation
- **THEN** the child exits, its token no longer authenticates at the model proxy, the process cap is released, both subscriber responses end without another event, no SQLite row changes, and a later prompt on that still-existing session acquires a new generation with `stream_epoch` plus one; the second call resolves without spawning, writing or bumping the epoch

### Requirement: Slash 命令白名单与命令目录
`server/src/sessions/slash-commands.ts` SHALL export the builtin whitelist `BUILTIN_COMMANDS` in this fixed order: `compact` (label `整理上下文`, description `压缩较长对话的上下文，保留要点`, hint `可选：想保留的重点`) and `todo` (label `任务清单`, description `查看或修改助手的任务清单`, hint `可选：append <任务>`); no other omp builtin SHALL be whitelisted by this change (`retry` is deliberately excluded: turn-control's regenerate already covers it and its `agentInvoked:true` receipt would add a second local-command completion mode). It SHALL export `listSkills(agentDir)`: synchronously enumerate the entries of `<agentDir>/skills` whose name does not start with `.`, keep at most the first 256 of them in code-point order of their SKILL.md path (further entries are ignored without any filesystem access), and read `<entry>/SKILL.md` for each kept entry without branching on the entry type (a plain file simply fails the read). A symlink is followed only inside the skills directory — a deliberate host restriction; omp itself follows any symlinked directory (`discovery/helpers.ts:428-431`): the host resolves the real path of `<entry>/SKILL.md` and skips the entry unless that real path lies inside the real path of `<agentDir>/skills` — both real paths SHALL come from the kernel (`realpathSync.native`), not from Node's JS `realpathSync`, which stops resolving at a FIFO or socket and folds `..` lexically, so its result can name a different file than the one the kernel opens; and both SHALL be kept as the raw bytes the kernel returned (`{ encoding: "buffer" }`): the containment check compares bytes and the open is given the same bytes, because decoding a path to a string replaces every ill-formed UTF-8 sequence with U+FFFD and re-encoding it names a different path — then opens the resolved path with `O_NOFOLLOW`, so file content outside `skills/` never reaches the catalogue through a link; the read SHALL be bounded and non-blocking as defence in depth — under omp-runtime「OMP_STATE_DIR 托管布局」 the directory is no longer writable by the omp uid, but whatever an operator installs there is still read by the server process: SKILL.md is opened with `O_NONBLOCK | O_NOCTTY` (a terminal device placed there cannot become the server's controlling terminal), and only a regular file of at most 262144 bytes is read — a FIFO, device, directory or larger file is skipped like an unreadable one; normalise `\r\n?` to `\n` and read only the leading frontmatter block — the content starts with `---` and the block ends before the first later line starting with `---`; an unclosed block is no frontmatter — taking, without a YAML library, the top-level (unindented) `key: value` lines for `name`, `description` and `enabled`: a value is trimmed and loses one pair of surrounding quotes; a value that is exactly a block-scalar indicator (`>` or `|`, optionally followed by `+` or `-`) takes the following more-indented lines, each trimmed, joined with one U+0020 (`>`) or `\n` (`|`); `name` defaults to the entry name when missing or empty. An entry is skipped when SKILL.md is missing or unreadable, when `description` is missing or empty, or when the unquoted `enabled` value is `false` (omp's own drop rules for a user-level skill: `discovery/builtin.ts:295-300`, `discovery/helpers.ts:397-403`), and — a host rule; omp does not validate names — when `name` does not match `^[^\s/]+$` (such a name cannot be selected through `/skill:<name>`, whose name ends at the first U+0020). Entries sharing a `name` collapse to the one whose SKILL.md path is smallest in code-point order (omp is first-wins over the same order, `extensibility/skills.ts:220-221`). Any failure to enumerate `skills` (absent, not a directory, unreadable) yields `[]`, as omp's scan does (`discovery/helpers.ts:384-392`); the result is sorted by `name` in code-point order and is recomputed on every call (no cache). It SHALL export `classifyPrompt(text, skills)` for already-trimmed text: text not starting with `/` → `{kind:"text"}`; otherwise the name is the characters after `/` up to the first whitespace or `:`; a name equal to a `BUILTIN_COMMANDS` name → `{kind:"builtin", name}`, except `todo` with the subcommand `import` or `export`, which is `{kind:"text"}`: the subcommand is taken as omp takes it (`slash-commands/helpers/parse.ts:22-36,58-64`) — the text after the name's terminating whitespace or `:` is trimmed, cut at its first whitespace and lower-cased — because omp resolves the path argument of these two subcommands with `resolveToCwd`, which honours absolute paths, `~` and `..` (`tools/path-utils.ts:565-579`), reads or writes that file with no tool frame, no step row and no `files.changed`, and echoes parse errors of an imported file as the reply; the host does not parse or validate the path, it simply does not whitelist the two subcommands, so the text reaches the model escaped like any other non-whitelisted `/` text; text starting with `/skill:` whose skill name — the characters up to the first U+0020, exactly omp's split (`extensibility/skills.ts:456-459`), so a newline is part of the name — equals an installed skill `name` → `{kind:"skill", name}`; every other `/`-prefixed text (different case, non-whitelisted builtin, unknown skill, a skill name broken by a newline, pasted paths) → `{kind:"text"}`. It SHALL export `toWireText(text, skills)`: `builtin`/`skill` → the text unchanged; `text` starting with `/` → one U+0020 followed by the text; anything else unchanged. Arguments of whitelisted commands (`/todo append 买菜`, `/compact:focus 保留结论`, `/skill:<name> 写周报`) SHALL pass through unchanged. A `/skill:<installed>` token in the middle of a prompt is `text` for the host and is left to omp (which executes the skill exactly as in its TUI).
`GET /api/commands` (`server/src/sessions/rest-commands.ts`, registered by registerSessions next to the session routes) SHALL require the cookie guard (401 with no-store otherwise, decided before the body/query check: an unauthenticated request carrying either is 401), carry Cache-Control:no-store, accept no body and no query string (an authenticated request with either SHALL return400 bad_request) and return200 `{commands:[{name,label,description,hint,source}]}`: the two builtins first in whitelist order with `name` equal to the builtin name and `source:"builtin"`, then every installed skill with `name` `skill:<skill name>`, `label` the skill name, `description` the frontmatter description as stored (possibly English), `hint` `可选参数` and `source:"skill"`; `hint` SHALL be a string or null; the route SHALL NOT be a content-parser owner and SHALL NOT touch any session, process or SQLite row.
**Branch alignment** (used by regenerate and fork instead of a plain equality on stored content). The *wire candidates* of a stored user content `c` are `c` itself and, when `c` starts with `/`, one U+0020 followed by `c` (the escaped form; a message persisted before the prompt route escaped was sent verbatim). Candidates depend only on the stored text — alignment never classifies history by the current skill set, so installing or removing a skill later does not move it. Regenerate SHALL return400 bad_request, with no spawn, no frame and no row change and after the 409 busy check, when `classifyPrompt` of the stored last user message yields `builtin` or `skill` (such a turn left no omp `user` entry); otherwise it SHALL require the text of the last branch entry to be a wire candidate of the stored last user message (any other outcome, including an empty list → 502 agent_unavailable with no row change, as before; only this pair is compared, earlier entries are not read). Fork SHALL return400 the same way when the chosen `messageId`'s content classifies `builtin` or `skill`; otherwise, with the source's stored `user` messages U1…Un in id order and the branch entries E1…Em in list order, it SHALL align them first-fit from the front: Ui is aligned to the current Ej when `Ej.text` is a wire candidate of `Ui.content`, consuming both; a Ui that does not match the current Ej is skipped and consumes no entry (it left no omp `user` entry: a whitelisted builtin, a skill invocation — leading or mid-prompt, which omp stores as a `custom` message — or any other local-only turn); an entry whose `entryId` or `text` is not a string matches nothing. Fork SHALL use the entry aligned to the chosen message (no aligned entry → 502 agent_unavailable and no new session row, as before). Fork's `draft` SHALL be the stored content of the chosen user message (identical to the branch text for every message that does not start with `/`; never carries the escape space).
