## Goals / Non-Goals
Goals: four routes, exact public payloads, cookie authentication, owner filtering, strict prompt validation, 202 admission and 400/404/409/502 branches without lost prior state.
Non-goals: real Supervisor/omp/SSE, startup registration/reconciliation, runtime request IDs, proxy token assembly, schema/config/threshold changes, new create-body product contract.
## Decisions
1. Export registerSessionRoutes and SessionSupervisorPort from rest.ts. The port is prompt(sessionId:string,text:string):Promise<void>; resolve means dispatch/admission succeeded, not turn completion. It reports canonical HttpError(session_busy|agent_unavailable); #100 translates actual runtime failures into these errors. No feature-to-http import and no runtime-specific error dependency.
2. Existing root guard remains mandatory. All matched-route replies set no-store at onRequest, including errors. For id-scoped routes use the existing owner-scoped store.getMessages(sessionId,principal.id) null check after authentication and before body parsing (route preParsing follows the root guard). Unknown and foreign IDs are indistinguishable 404, without supervisor calls or writes. Reuse that authorized result for the history response rather than loading it twice; acceptPrompt independently rechecks owner/busy before mutation. runtimeState remains trusted-supervisor-only and is never a REST authorization accessor. Authentication remains first (401 even for malformed bodies).
3. Prompt accepts only JSON with exactly one own property message, a string. Trim once; require nonempty and Buffer.byteLength(trimmed,'utf8') <=32768. Store and supervisor receive that same trimmed text. Reject arrays/null/extra keys/wrong types and unsupported media. Retain the bounded Fastify parser envelope (default 1MiB), rather than wrongly limiting wire JSON to32768: escape-heavy valid text must fit. Malformed/oversized parser failures use the existing exact-route owner mapping.
4. Call store.acceptPrompt synchronously before awaiting supervisor.prompt, retaining its two IDs for the202 response. This reserves the session across concurrent awaits. On supervisor rejection, compensate this admission via rollbackPrompt then rethrow the original typed/unknown error; compensation exceptions must propagate as generic5xx, never be hidden by a friendly502. Store admission failure must not invoke the supervisor or compensate another turn. A rejecting supervisor must not have published/persisted progress; after dispatch resolution later failures belong to #100. Unknown errors remain generic5xx, not silently502. No retries.
5. POST create returns201, GET list200; delegate ordering to store. History projects the exact public step keys id/ordinal/name/detail/status, omitting internal startedAt/endedAt as well as owner/runtime metadata. Do not change store's richer internal view.
## Must preserve / change
Preserve existing auth/public exemptions, sibling parsers/no-store scope, canonical error messages/statuses, store transactions and compensation semantics. Add only the four routes and owned injectable port.
Governing invariant: only the authenticated owner can observe or admit a session turn; rejected pre-dispatch admission leaves prior persisted session/history intact.
Sibling surfaces: root guard, parser owner mapping, owner-scoped SessionStore getMessages/acceptPrompt/rollbackPrompt, public history projection, concurrent requests and typed/unknown error paths.
Seams: real Fastify HTTP/inject, real SQLite store and auth, stub supervisor only. No mocked system under test.
## Risks / Trade-offs
- Supervisor rejection after progress cannot be safely compensated: port forbids it; store refuses destructive rollback. Real lifecycle proof belongs to #100.
- Long escaped JSON can exceed message bytes: separate parser envelope from decoded UTF-8 semantic limit.
- Existing store metadata corruption handling (#190) remains out of scope; do not weaken unknown-error semantics.
- No root registration yet: paired tests and parent HTTP harness register this module explicitly, #100/#101 assemble production.
- Prompt ownership precheck loads the existing owner-scoped history view: this preserves the frozen store contract without a new API; optimization of that read is outside this slice.
## Migration / rollback
No database migration. Revert this atomic module/test change before production assembly if its contract fails. Preserve reference inputs and original RED tests; qualify wrong candidates only in disposable compiled copies.
