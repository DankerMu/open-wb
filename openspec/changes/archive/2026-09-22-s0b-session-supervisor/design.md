## Context
REST already owns acceptPrompt and pre-progress rollback. SessionRuntime.prompt returns a buffered AsyncIterable, but its exact requestId is private and send completion has no public signal. Frames may precede ACK; requestId cannot be guessed. Runtime has792lines and store800; thresholds remain unchanged. References: parent design D2–D6, runtime.ts147–193/337–434, events.ts, archived #83/#96/#99; actual pinned RPC oracle resource/oh-my-pi/docs/rpc.md (#141 tracks the dead issue link).
## Goals / Non-Goals
Compose actual fake-process turns into exact stored/public events and provide a thin registration boundary. No SSE/ring buffer, real omp/model proxy assembly, app.ts/server.ts config/startup changes, retry policy or #190 metadata rewrite. S0b same-uid security limitation remains; no credential-isolation release claim.
## Decisions
1. Keep prompt(text) as the single runtime API. Return an AsyncIterable carrying `dispatched: Promise<{requestId:string;sessionFile:string}>`, resolving once the prompt write succeeds after handshake, not on an ACK/first frame/terminal event. Pre-dispatch acquisition/write/cancellation/shutdown failure rejects it and the iterator without unhandled rejection when existing consumers only iterate. Extract existing FrameStream into one canonical omp/prompt-stream.ts; preserve queue, terminal, drain/cancellation and old caller behavior, never duplicate or raise the line cap.
2. SessionSupervisor implements the unchanged REST port. Constructor shape: `new SessionSupervisor({store,tokens,runtime,onError,onEvent?})`; runtime is an object containing bin,sandboxRoot,stateDir,modelId and existing optional idleMs/spawnImpl/clock/handshakeTimeoutMs. Optional `onEvent(sessionId,epoch,event:ChatEvent<number>)` is the observation sink; required `onError(error:Error)` is the error owner. Public prompt/shutdown plus handleFlushError(store notification) are real lifecycle surfaces, not future stubs.
3. A slot binds one session runtime and a pending pump. Obtain trusted runtimeState to bind owner/resume/active assistant. Guard duplicate supervisor admission. Await dispatch receipt before consuming/persisting any queued frames; persist validated sessionFile before resolving the REST port. Pre-progress failures retire/discard that runtime before rejecting; translate only known runtime busy/unavailable/protocol classes to canonical HttpError, keep DB/untyped faults generic. Do not compensate in Supervisor: REST owns it.
4. Each runtime receives a token adapter over the shared registry: every issue(sessionId) first bumps store epoch, then issues the token, recording that generation's epoch. This observes first/idle/crash re-spawns and failed creation attempts without guessing native identity or duplicating crypto. Reused live generation does not bump. Generation metadata is intentionally independent of REST compensation. The adapter retains the original fault from either epoch write or registry issuance before rethrowing; receipt rejection prefers that acquisition-specific original fault over runtime's sanitized AgentUnavailableError, clearing provenance for the next acquisition. Existing runtime sanitizeError remains unchanged. Runtime remains sole revoke owner. Serialize same-session runtime replacement until the previous runtime's native retirement and pump settle; other sessions remain independent. Never issue a replacement token while a retired instance can still revoke that session's token.
5. After receipt/sessionFile, initialize pure event state with exact requestId and consume the entire iterator in a contained background task. Map toolCallId to startStep-returned numeric IDs with zero-based per-turn ordinals. Persist step changes before their publication, append text into the store's existing buffer, finishTurn before publishing turn.end. Error precedes failed turn.end. A clean iterable end without mapper terminal is runtime-validated local-only completion: finish done and publish one turn.end, never wait for nonexistent agent_end. No ACK guessing or second RPC classifier.
6. Iterator failure after dispatch goes through applyFailure exactly once, settles residual content/steps failed and discards/retires runtime; next prompt resumes from persisted file. A mapper-produced terminal prevents duplicate terminal settlement; late events do not mutate another turn. Upstream stopReason:error may retain healthy runtime. Native idle/between-turn exit is handled by the runtime's existing re-acquisition, with epoch adapter on the next generation.
7. onError owns infrastructure/store/observer/cleanup failures only, not modeled crash/upstream/protocol turn failures already successfully settled through public error+turn.end. A modeled turn failure by itself must not poison shutdown. Contain infrastructure failures, retire the runtime, notify onError once per originating failure and retain faults for explicit shutdown/recovery reporting; do not publish a terminal commit that failed or auto-loop retries. Background onFlushError and synchronous threshold/step/terminal faults use this path. All shutdown tasks settle; no unhandled promise. If onError throws, retain that error rather than leaking a detached rejection. Caller can repair storage and explicitly retry store finish/close; no false success is claimed.
8. `registerSessions(app,{db,tokens,runtime,onError,onEvent?})` constructs store with the supervisor flush-error receiver, calls reconcileOnStartup before registering REST and returns `{store,supervisor}`. Install a preClose hook that awaits all supervisor runtime/pump settlement before attempting store.close even if supervisor reports errors; aggregate rather than mask cleanup failures. DB stays caller-owned. shutdown closes admission, awaits all runtimes/pumps even if one fails and reports collected failures; callers must not close DB before it settles. #101 wires this module into createApp; #102 verifies full runtime→listener→DB order. Optional event observation is real publication without SSE; #103 will attach its required recording sink before traffic.
## Risks / Trade-offs
- Receipt/early-frame race→buffer remains in existing stream until receipt; never persist before successful dispatch gate. Consumer cancellation must settle both channels and preserve old retirement behavior.
- Native-exit/queued-frame ordering→drain iterator, do not synthesize failure immediately in onExit and discard residual frames.
- Filesystem/env safety→reuse OmpProcess unchanged; no direct supervisor path creation, raw credential logging or inherited environment.
- DB fault after command write→retire before REST rejection if no progress consumed; post-acceptance failures remain lifecycle errors, never rollback progressed rows.
- Optional observer absence means no current SSE consumer, not a fake buffer; replay/retention is explicitly outside100.
- Fake child extension is exactly crash-after-deltas: emit the normal first two text deltas (`Hello `, `from `), then exit before2048B/2000ms flush. Keep the existing zero-delta crash scenario unchanged.

Add module and atomic runtime seam; existing iterable callers remain valid and tested. No startup wiring until101. Revert this source slice before wiring for rollback; no data/schema migration. Do not remove prior accepted source/tests/receipts.
