## Decisions
1. One shared createSqliteTextDecoder(db):TextDecoder helper in core/db/index.ts; update its existing module API comment. Query known free-text fields as CAST(column AS BLOB) under the existing column aliases. Internal row types become Uint8Array (nullable where appropriate); use the configured decoder before public return or read-derived mutation. No second decoder configuration or per-consumer fallback.
2. Resolve current PRAGMA encoding once per read/admission operation, not per row. Reuse a bounded set of non-streaming TextDecoder instances keyed by the three SQLite encoding labels, not by DatabaseSync object identity. Fresh evidence (reopen-identity-fact.log) proves the same DatabaseSync object can close/open a replacement file with a different encoding, so a permanent per-object encoding cache is unsafe. Decoder uses ignoreBOM:true and non-fatal/default replacement behavior; every decode is non-streaming/stateless. Do not retain text/history/DB handles or silently assume UTF8 on read failure. The one operation-level metadata read is necessary to respect native reopen semantics; json_quote+JSON.parse is a measured correct alternative but adds avoidable serialization work.
3. SessionStore coverage is complete, not just getMessages: list/getMessages title; user/assistant content; step name/detail; runtimeState omp_session_file; acceptPrompt's previousTitle and reused title. Decode before title UPDATE and before retaining previousTitle, preserving TEXT storage type and exact suffix on both success and compensation. Nullable title/resume remain null, empty strings remain empty. IDs/statuses/roles and time/epoch handling stay unchanged.
4. Existing STEP_COLUMNS.replaceAll prefix synthesis cannot blindly prefix CAST expressions. Use explicit qualified projections for the joined step query and remove obsolete prefix synthesis, without adding a generic SQL builder.
5. Audit title gets the same lossless read path. audit.detail stays on JSON.stringify→TEXT→JSON.parse: measured NUL strings inside JSON survive, because no literal NUL enters the column. Keep actor/admin filtering, cursor/limit handling, ordering, immutable-event triggers and emit behavior unchanged.
6. All production changes are atomic across these readers. No normal-vs-NUL implementation split, input special case, compatibility alias, or old decoder kept alongside the new one.
## Invariant and sibling surfaces
Governing invariant: declared free-text fields read through the supported APIs, and those values reused in later writes, preserve their complete value regardless of embedded U+0000 or database text encoding.
Must preserve: public store/audit signatures except the new internal shared core helper; existing string/null DTOs, TEXT column storage, Unicode title-prefix rule, owner filtering, admission/rollback and flush/finish/close semantics; existing migration receipts and connection/file encoding.
Sibling surfaces: all SessionStore view builders, admission title SELECT/UPDATE/snapshot, runtimeState, audit query/title/detail serialization, null/empty/BOM cases, per-connection encoding isolation and file reopen.
Schema-restricted identifiers/enums and existing JSON serialization remain unchanged; no new broad DB-validation policy.
## Verification design
Existing APIs are already callable, so real regression RED on baseline is sufficient; no artificial inert A2 is needed. A tests-only stage adds public-boundary regressions and records intended assertion failures, then parent freezes those tests before source-only B. No mocking SessionStore/core audit/core DB.

Three DB encodings are compatibility cases, not three copies of every same-path test. Interleave differently encoded connections and exercise native close/open of the same DatabaseSync object against a replacement database encoding; neither a process-global nor stale per-object encoding assumption is valid.
