Change surface: `server/src/sessions/omp/process.ts` (sudo argv + spawn precondition), `server/src/core/process-path.ts` (shared setpriv check), `server/src/agent-config.ts` (config precondition), argv/config tests, `server/test/linux/uid-isolation.test.ts`, `.github/scripts/ci-uid-isolation.sh`, `scripts/test-ci-harness.sh`, `docs/adr/0010-dedicated-omp-uid.md`.

Must preserve: direct-spawn argv/env/cwd/stdio/shell byte-identical; sudo options before `--` unchanged (`-n -u user --preserve-env=… [TMPDIR=…]`); no credential in argv; `assertSafeSudoPath` behaviour; existing uid-isolation probe assertions; CI job structure, `all-checks-passed`; real omp `make smoke` under sudo; `/usr/bin/env` preflight rule; `ci-compiled-server.sh` and `ci.yml` unchanged.

Governing invariant: in sudo mode, termination of the sudo process terminates the omp process (kernel pdeathsig), so retirement never leaves the omp process itself running under ompUser. Scope: omp only — tool subprocesses omp spawned (e.g. bash) can still outlive it, same as direct mode (residual, not a regression).

Design decisions:
- Fixed absolute `/usr/bin/setpriv` (util-linux; present on Ubuntu/Debian and the VPS). No PATH lookup.
- Precondition at config and spawn boundary, mirroring `assertSafeSudoPath` (issue AC 3). macOS dev/CI has no `/usr/bin/setpriv`: existing ompUser tests (injected sudo capture, config-reaches-runtime assembly, invalid-user compiled-entry cases) SHALL keep passing on macOS and Linux through test seams, never by skipping or by weakening the production default: in-process tests may inject the access function; compiled-entry child tests (e.g. `server/test/server-startup-order.test.ts:~508-557` with `OMP_USER=omp`) replace `fs.accessSync` inside the existing `--import` spawn-capture hook (`captureSpawnHook`, ~:637-654, already uses `syncBuiltinESMExports`). The shared helper SHALL therefore call `accessSync` via a named `node:fs` import so that replacement takes effect. No env or config key may override the launcher path (no production knob). ADR-0010:13 has macOS dev run same-uid without OMP_USER, so no supported config is broken.
- setpriv execs omp in place (same pid); sudo's SIGTERM relay still reaches omp (measured).
- sudoers `<bin> *`: the previous rule (path without args) already allowed any args, so the trailing `*` does not widen authorization; the fixed launcher prefix cannot be altered and setpriv stops option parsing at its own `--`. `*` requires ≥1 trailing arg; omp always has `--mode rpc …`. The prefix is hygiene, not a security boundary (the app can already run arbitrary code as ompUser via omp's tools; CI's `/usr/bin/env` rule is equivalent); the omp→app boundary is unaffected.
- CI rule-matching check uses a check-only user because the hosted runner's preinstalled `runner ALL=(ALL) NOPASSWD:ALL` masks argument matching for the runner; the same generator produces both rule sets so the check covers the real text.

Residual risks (documented in ADR): `sudo -l` cannot prove SETENV / `TMPDIR=` command-line assignment on the runner (masked by the preinstalled ALL rule); sudo SIGKILLed between fork and setpriv's prctl (tiny window, e.g. shutdown racing spawn at `runtime.ts:~334`) still orphans omp; `log_output` or tty `use_pty` interpose a sudo monitor so pdeathsig binds to the monitor, not the killed sudo.

Sibling surfaces: `assertSafeSudoPath` (`server/src/core/process-path.ts`); `test-ci-harness.sh` fake sudo (`:715`) executes `ci-uid-isolation.sh` and returns 0 for unknown calls — it MUST emulate `sudo -l -U <user> -u omp <cmd>` by reading the generated `$sudoers_src` (allow only launcher + trailing arg as written there, else nonzero), so the deny assertions pass and a generator launcher-drop mutation is caught; harness fake `getent` returning 2 for the check user needs no change; harness contract generator lines around `:92` (`for command in ("$fake_rule", "$real_rule", …)`); `ci-uid-isolation.sh` `owned_pids`/`reap_owned` (`:80-87`, `:207-208`).

Seams under test: injected spawnImpl capture (argv exact); config/spawn precondition with a missing launcher; native sudo + setpriv on the Linux CI runner; `sudo -l -U` rule check; compiled server + real omp under sudo (`make smoke`).
