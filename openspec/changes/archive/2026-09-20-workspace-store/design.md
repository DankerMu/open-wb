## Context
Change surface: server/src/workspaces/store.ts and paired tests; no existing store. Canonical references: migrations/031_workspaces.sql, auth/session.ts:89-118 owned transaction discipline, core/sandbox/resolve.ts + dirs.ts, core/audit.emit, demo:3618.
Governing invariant: return success only after workspace row, owned/adopted directory, and audit commit; failure never deletes adopted data or grants another owner's root.

## Goals / Non-Goals
Goals: owner-filtered ordered list, canonical name/dir validation, one synchronous owned transaction, lazy roots, safe adoption and failure compensation, real rootOf.
Non-goals: HTTP status/cache/parser/routers, schema or auth changes, file/dirs endpoints, quotas, new async callbacks, crash recovery, external-writer/TOCTOU hardening.

## Decisions
1. API returns array from list(ownerId), workspace object {id,name,dir,root,createdAt} from create, and absolute root|null from rootOf. Principal is structural id-only. SELECT always scopes owner_id; foreign/missing workspace returns null before FS work. list orders created_at ASC,id ASC and never creates directories.
2. name is trimmed then checked for 1..64 Unicode scalar values (SQLite length) and ASCII controls U+0000..001F/U+007F. Reject ill-formed UTF-16 (isolated high/low surrogates) as bad_request before mutation: SQLite UTF-8 cannot preserve those inputs. Preserve valid Unicode unchanged, including supplementary characters and literal U+FFFD; do not normalize or silently replace characters. Explicit dir must be nonempty1..64 ASCII letters/digits/_/- or U+4E00..9FA5, no trimming/fallback. Missing/undefined dir derives from trimmed name with the exact demo non-u /[^\w\u4e00-\u9fa5-]/g replacement, then same validation. Emoji gives two hyphens; a 64-codepoint non-BMP name can succeed with explicit valid dir. Do not invent rejection of display name '.' if its derived '-' is valid.
3. Validate before mutation. ID from cryptographic16bytes→32lowercasehex; createdAt=Date.now(). Do not add public clock/ID/retry APIs. Sort tests can seed legal fixed rows; clock may be controlled at test boundary.
4. SANDBOX_ROOT is a trusted deployment-preprovisioned absolute directory; store may normalize a relative config to absolute but does not create the deployment base. Account roots are lazy. Empty list and absent/foreign rootOf must not materialize roots. Trusted DB owner ids are not automatically safe path segments: reject empty, '.', '..', NUL, slash/backslash as generic invalid state without changing auth schema or exposing input in errors.
5. Reuse canonical resolve(base, ownerId+'/'+dir, read) and owner-root equivalent to reject existing symlink components; dirs.ts deliberately accepts directory symlinks and is not a policy gate. Adopt only ordinary directories, not symlinks or files. Apply same root computation/boundary policy to returned roots, not just creation. Unsafe persisted owner/path state is generic failure, not conflict or an unaudited sandbox_denied; client name/dir domain failures are bad_request.
6. BEGIN occurs before ownership catch (existing caller transaction stays active/unmodified if BEGIN fails). Plain INSERT exactlyone row precedes all ensureSharedDir calls; then owner root, workspace root, canonical workspace.create emit, COMMIT. Success only after COMMIT. emit option uses typeof core/audit.emit, i.e. (db,event)=>number; pass this exact db so real event participates in the owned transaction. ensureSharedDir is the existing synchronous helper dependency, not an async backend.
7. Only workspace INSERT's owner/name or owner/dir UNIQUE violation maps to canonical conflict; distinguish NodeSQLite errcode2067 from primarykey1555, FK/CHECK/trigger/audit failures. Do not catch the whole transaction as conflict or retry random ID collisions. Verify a real UNIQUE conflict reaches no directory/audit action.
8. Before invoking directory creation record which of owner/workspace paths do not exist, under stable-FS assumption. Even a helper that creates then throws (e.g. chmod failure) must be compensated. On failure attempt DB rollback if owned/still active, then remove only missing-before paths that were created as ordinary empty directories, in reverse order with rmdir (never recursive rm). Missing paths need no removal; pre-existing roots are never cleanup candidates.
9. If BEGIN succeeded and a later step fails, attempt ROLLBACK only while db.isTransaction; catch and retain any rollback error instead of immediately rethrowing the auth/session helper's AggregateError. Still attempt every eligible reverse-order empty-directory removal, catching cleanup errors independently. If any compensation fails, throw one AggregateError with errors [original, rollbackError?, ...cleanupErrors] and cause original; otherwise rethrow the original error unchanged (or canonical INSERT conflict). A failed ROLLBACK may leave the owned transaction active with uncommitted workspace/audit rows visible: report that residual state, do not assert row absence. Nonempty, adopted, symlink or file paths are never recursively deleted; unexpected cleanup targets yield a cleanup error rather than being removed.
10. Audit event: kind workspace.create, actorId principal.id, workspaceId generated id, title '创建工作空间 '+trimmedName, detail:{root}. Canonical emitter real integration verifies row and event rollback together.

## Sibling surfaces / evidence
Schema's 32hex IDs, binary owner uniqueness, signedINTEGER created_at and Unicode name length remain unchanged; list accepts existing signed dates. Existing directories retain bytes/mode; newly created owner+workspace use2770 via helper.
Auth/session owned transaction and AggregateError conventions; core/sandbox facade expects sync string|null rootOf and binds audit separately; no feature→feature imports. webapi requires five workspace fields and signedcreatedAt.
Tests: real in-memory migrated DB, temporary pre-provisioned base, real ordinary/symlink/file paths. Stub/inject only declared dependencies to produce deterministic partial-create/audit failures; use SQLite authorizer for genuine COMMIT/ROLLBACK failure and existing caller transaction. No mocked store/DB/resolver.
Main compiled smoke invokes actual store with canonical helper+emit on real DB/FS, validates success/event/list/owner isolation/adoption and post-insert audit failure rollback.

## Risks / Trade-offs
Filesystem compensation is not atomic with SQLite or crashes; stable trusted base/no concurrent path replacement is inherited scope, not a universal guarantee. Never silently report cleanup success when rmdir fails.
No new shared transaction abstraction or helper policy changes; reuse established control flow without cross-feature import. Exact event fields validated, no source-text or incidental function-reference tests.
Rollback/release: revert atomic feature PR; no migration, persisted-format change or production route wiring in this slice.
