# Design: session-metadata-patch（#524）

父设计：D2「会话元数据 REST」PATCH 决定、「重命名与 `rollbackPrompt`」、「模块拆分」；http-service-skeleton「统一错误信封」归属集（1.3 已落，`server/src/http/errors.ts:59` 含 `"PATCH /api/sessions/:id"`）。行号为 origin/master（e2114bc）。

- **Change surface**：`server/src/sessions/rest-metadata.ts`（全文 89 行，`registerSessionCreateRoute` → `registerSessionMetadataRoutes`，新增 PATCH）；`server/src/sessions/store-metadata.ts`（全文 74 行，新增 `patchSession`）；`server/src/sessions/store.ts:42`/`:157-191`（`SessionView` 加 `export`；`SessionStore` 接口增 `noteTitleWrite`）、`:193`/`:236`/`:649`（`SessionDbRow`、`SESSION_COLUMNS`、`toSessionView` 加 `export`）、`:216-232`（Turn 增 `titleTouched`）、`:409-444`（`rollbackPrompt`）、`:663-681`（`openTurn` 初始化标志）；`server/src/sessions/rest.ts:167-170`（注册调用改名并传 `store`）；`server/test/session-metadata-rest.test.ts`（追加）；新建 `server/test/session-title-rollback.test.ts`。
- **Must preserve**：
  - `POST /api/sessions` 的全部行为（#523 证据）逐字不变；`rest-metadata.ts` 不 import `rest.ts`（`rest.ts` → `rest-metadata.ts` 单向）。
  - 未发生标题 PATCH 的受理补偿：未命名会话补偿后标题回到 NULL；已有标题的会话补偿后标题不变；status/`updated_at` 仍恢复为受理前值；epoch/sessionFile 不变（既有 `session-supervisor-admission.test.ts` 等全绿）。
  - 受理、回合结算、对账不写 `workspace_id`/`scene`/`pinned_at`（现状即如此，本刀不改这些路径）。
  - 其余会话路由、cookie guard（401 先于解析）、no-store、错误码表不变；`supervisor.ts`（799 行）、`index.ts`、`session-rest-helpers.ts` 不改。
  - 既有测试文件零改动（`session-metadata-rest.test.ts` 是 4.1 新建文件，本刀在其末尾追加 `describe`，不改既有用例）。
- **Must add/change**：
  - `rest-metadata.ts`：
    - 依赖 `{ metadata: SessionMetadataStore; workspaceRootOf: WorkspaceRootOf; store: Pick<SessionStore, "getMessages" | "noteTitleWrite"> }`（`SessionStore` 仅 type import 自 `store.ts`）；POST 注册保持原位与原选项。
    - `app.patch<{ Params: { id: string } }>("/api/sessions/:id", { bodyLimit: 16 * 1024, onRequest: <no-store hook>, preParsing: <owner 预检> }, handler)`。16 KiB 与 POST 共用同一常量（改名为 `SESSION_METADATA_BODY_LIMIT` 或等价）。
    - preParsing：`principal = createPrincipal(request)`（null → `unauthorized`，与 guard 一致）；`dependencies.store.getMessages(request.params.id, principal.id) === null` → `throw new HttpError("not_found")`；否则 `done(null, payload)`。与 `rest.ts` `requireOwnedSession` 同一语义（chat-sessions「会话 REST」「Id-scoped authorization SHALL use the existing owner-scoped store.getMessages … null result before parsing」），但不 import `rest.ts`；结果不缓存、不取 stream cursor。
    - handler：`parsePatchBody(request.body)` → `metadata.patchSession(principal.id, id, patch)`；返回 null（UPDATE 0 行，并发删除）→ `not_found`；成功后**若 `patch.title !== undefined`，在同一同步段内**（`patchSession` 返回与调用之间无 `await`）调用 `dependencies.store.noteTitleWrite(id)`，再 `reply.code(200).send(view)`。
    - `parsePatchBody(body)`：非 plain object（数组、`null`、原始值、`undefined`——即无 body——与 text/plain 产出的字符串；SHALL NOT 对字符串 `JSON.parse`）→ 400；键集为空或 ⊄ `{title, scene, pinned}`（含 `workspaceId`、`status`）→ 400；`title` 在场：非字符串 → 400，`trimmed = title.trim()`，`[...trimmed].length` 不在 1..80 → 400，存 `trimmed`；`scene` 在场：不是三值之一（含 `null`）→ 400（复用既有 `requireScene`）；`pinned` 在场：非布尔 → 400。先全部校验、后写入：任一非法不调用 store。400 一律 `throw new HttpError("bad_request")`。认知复杂度 ≤15（按字段拆函数）。
  - `store-metadata.ts`：
    - `patchSession(ownerId, sessionId, patch: SessionPatch): SessionView | null`，`SessionPatch = { title?: string; scene?: SessionScene; pinned?: boolean }`（至少一键，由路由保证）：以常量 SQL 片段拼出 SET 子句——`title = ?`、`scene = ?`、`pinned === true` → `pinned_at = COALESCE(pinned_at, ?)`（参数为 `Date.now()`）、`pinned === false` → `pinned_at = NULL`——执行**单条** `UPDATE chat_sessions SET … WHERE id = ? AND owner_id = ?`（片段均为源码常量，值全部走参数）；`changes === 0` → 返回 null；`changes` 非 0/1 → 抛错（`requireChanges` 语义）；随后 `SELECT ${SESSION_COLUMNS} FROM chat_sessions WHERE id = ?` 经 `toSessionView(row, createSqliteTextDecoder(db))` 返回八键视图。不改 `updated_at`/`status`/`workspace_id`/`omp_session_file`/`stream_epoch`、不碰消息/步骤行、不 `emit`、不调用 supervisor。单条 UPDATE 自身原子，无需显式事务。
  - `store.ts`：
    - Turn 增 `titleTouched: boolean`，`openTurn` 初始化为 false（受理与 regenerate 两条路径）。
    - `SessionStore.noteTitleWrite(sessionId: string): void`：`activeSessions.get(sessionId)` → `activeTurns.get(id)`，存在则 `titleTouched = true`；无在途受理时为 no-op；不查库、不抛错（store 关闭后亦为 no-op：关闭时 `activeTurns` 为空或调用方已不再受理请求）。
    - `rollbackPrompt`：`const restoreTitle = turn.previousTitle === null && !turn.titleTouched`；恢复语句改为 `UPDATE chat_sessions SET status = ?, updated_at = ?, title = CASE WHEN ? THEN NULL ELSE title END WHERE id = ?`（参数 `restoreTitle ? 1 : 0`，或等价的两条分支语句）；不写 `workspace_id`/`scene`/`pinned_at`。删除受理对、`requireChanges`、`releaseTurn` 不变。
    - `SessionView`、`SessionDbRow`、`SESSION_COLUMNS`、`toSessionView` 加 `export`（无其它改动）。`bash scripts/size-guard.sh`：`store.ts` 须 ≤800（现 768）。
  - `rest.ts:167-170`：`registerSessionMetadataRoutes(app, { metadata: dependencies.metadata, workspaceRootOf: dependencies.workspaceRootOf, store: dependencies.store })`。
- **并发推理（Concurrency pack）**：Node 单线程 + 同步 SQLite。受理（`acceptPrompt` 同步事务 + `openTurn`）、PATCH（UPDATE + `noteTitleWrite` 同步段）与补偿（`rollbackPrompt` 同步事务）互不交错：PATCH 在受理前提交 → 受理见非 NULL 标题、不写前缀、补偿保留当前标题；PATCH 在受理后、补偿前提交 → 标志置位、补偿保留；补偿后才 PATCH → 无在途 Turn，no-op。仅写 `scene`/`pinned` 的 PATCH 不置位（补偿照常把本次前缀恢复为 NULL，`scene`/`pinned_at` 保持 PATCH 值）。
- **Sibling surfaces**：web `patchSession`（5.1，`web/src/lib/api-sessions.ts`）已按八键解析 200，无需改；`GET /api/sessions` 与快照经 `toSessionView` 自动反映新列值；`http/errors.ts` 已含 PATCH 身份；SSE 不发元数据事件（侧栏刷新属 7.x）。
- **残余**：
  - `store-metadata` 仍不感知 SessionStore 的 `closed`（同 4.1 记录）。
  - 父 delta 追补句「reconciliation SHALL NOT change `workspace_id`、`scene` or `pinned_at`」无直接用例：`reconcileOnStartup` 的 UPDATE 只写 status 列（结构性保证；创建由 #523 证据、结算由证据 2、补偿由证据 8 覆盖）。
  - 控制占用（regenerate/fork/stop）期间的 PATCH 不设专门用例：路由不调用 supervisor、不读占用状态（结构性保证，证据 1 断言 spawn 数不变），running 用例覆盖在途回合。
- **Required evidence**（`session-metadata-rest.test.ts` 追加用例沿用 4.1 的 production `createApp`（`openBareSession(createRealFakeRuntime().runtime)`）+ `app.inject()` + 真实 SQLite；running 与补偿用例用 `session-supervisor-helpers.ts` 的受控 runtime。「行不变」= 以 SQL 读 `chat_sessions` 该行全部列（`title`、`status`、`created_at`、`updated_at`、`workspace_id`、`scene`、`pinned_at`、`omp_session_file`、`stream_epoch`）前后深相等，且该会话 `chat_messages` 行数不变。RED：实现前 PATCH 命中 `app.all("/api/*")` catch-all（`server/src/app.ts:177`，typed 404、无 no-store；匿名 401 亦无 no-store），故证据 1、2、3、4、5、6（no-store 断言）、7、8a、8c、8d、8e 在实现前红；8b（无 PATCH）为 characterization 守卫；记录实现前实际运行结果，与本划分不符处在 PR 说明）：
  1. `done` 会话（真实 fake 跑完一轮）依次 PATCH `{title:"  季度 汇报  "}`、`{scene:"design"}`、`{pinned:true}`、再 `{pinned:true}`、再 `{pinned:false}` → 各 200 + no-store，body 恰八键（键序 `id,title,status,createdAt,updatedAt,scene,workspaceId,pinnedAt`）：`title="季度 汇报"`；`scene="design"`；首次 `pinnedAt` 落在请求前后 `Date.now()` 区间内且等于 SQL `pinned_at`，第二次同值；取消后 null。全程 `updatedAt`、`status`、`omp_session_file`、`stream_epoch`、`workspace_id` 与消息行不变；另建一个更新的会话，PATCH 前后 `GET /api/sessions` 两会话相对顺序不变；`audit_events` 行数不变；spawn 调用数不变。
  2. running：`openHeldPromptSession()` 后 PATCH `{title:"新名",scene:"office",pinned:true}` → 200，视图三字段一次反映、`status="running"`；`completeHeldTurn` 后等待会话结束 → `status="done"`、标题仍 `新名`、`scene`/`pinned_at` 保持。
  3. 标题边界：恰 80 码点且含辅助平面字符（如 `"😀".repeat(40) + "a".repeat(40)`，UTF-16 长 120）→ 200 原样存储；首尾带空白、trim 后 80 码点 → 200 存 trim 后文本；81 码点、`""`、`"   "`、`123` → 400 `bad_request`，行不变。
  4. 非法 body：`{}`、`{pinned:"yes"}`、`{scene:null}`、`{scene:"chat"}`、`{status:"done"}`、`{title:"a",extra:1}`、`{title:"ok",scene:"bad"}`（合法字段 + 非法字段 → 整体 400、标题不变）、`[]`、`null`、`"x"`（JSON 字符串根）、无 body（无 Content-Type）→ 均 400 `bad_request` + no-store，行不变。
  5. 经 production `createApp` 的 parser 失败：malformed JSON、空 body 带 `application/json`、`text/plain`（含内容像 JSON 的 `{"title":"x"}`）、`application/octet-stream`、超 16 KiB（如 `{"title":"x","pad":"<16 KiB+>"}`）→ 400 `bad_request` + no-store，行不变；16 KiB 以内含填充空白的合法 body → 200（边界）。
  6. 鉴权：匿名以合法 body 与 malformed body → 401 + `cache-control: no-store`；第二账号对第一账号会话、第一账号对 `UNKNOWN_SESSION_ID`，各以合法 body 与 malformed JSON body → 四次 404 `not_found`，每次均带 `cache-control: no-store`，且状态码、`cache-control`、`content-type`、`content-length` 与 body 两两逐字节相等（不比较 `date` 等时变头）；目标会话行不变。另（store 层，同文件）：以 SQL 删除一个会话行后调用 `metadata.patchSession(owner, id, {title:"x"})` → 返回 null（UPDATE 0 行；路由把 null 映射为 404）。
  7. 绑定不可改：建 W、W2（`POST /api/workspaces`），以 `{workspaceId:W.id}` 创建会话；PATCH `{workspaceId:W2.id}`、`{title:"x",workspaceId:null}` → 400，行不变；随后对该会话发 prompt，spawn 调用记录的 `cwd` 经 realpath 等于 W 的根。
  8. `session-title-rollback.test.ts`（受控 runtime：`createControlledRuntime` 的 configure 里以 `holdNextPromptWrite(child)` 挂起 prompt 帧写入，`onCommand("prompt")` 回 `{id, type:"response", command:"prompt", success:false}`；测试在挂起期间发 PATCH，再 `release()`——派发收到失败回执（`server/src/sessions/omp/runtime.ts:509`）→ `AgentUnavailableError` → `rest.ts:196` `rollbackPrompt` → prompt 502；失败须发生在任何 delta/step 进度之前（子进程退出亦可，`runtime.ts:599`）。每例断言 prompt 502 `AGENT_UNAVAILABLE_ENVELOPE`、该会话无消息行、`status`/`updated_at` 等于受理前值，且 `scene`/`pinned_at` 等于受理前（或挂起期间 PATCH 后）的值——为使「不变」可区分，8b/8c/8d 的会话在受理前先置非 NULL 的 `scene` 与 `pinned_at`（统一在受理前 PATCH `{scene:"office",pinned:true}`））：
     a. 未命名会话受理 `prompt`（文本 >18 码点）→ 挂起期间 PATCH `{title:"季度汇报"}` 200 → 放行失败 → 标题 `季度汇报`，`scene`/`pinned_at` 不变。
     b. 未命名会话受理 → 不 PATCH → 放行失败 → 标题 NULL。
     c. 会话先 PATCH `{title:"季度汇报"}`，再受理 → 放行失败 → 标题 `季度汇报`。
     d. 会话先 PATCH `{title:"旧名"}`，受理后挂起期间 PATCH `{title:"新名"}` → 放行失败 → 标题 `新名`（旧实现恢复为 `旧名`）。
     e. 未命名会话受理 → 挂起期间只 PATCH `{scene:"code",pinned:true}` → 放行失败 → 标题 NULL，`scene="code"`、`pinned_at` 为 PATCH 时刻。
  9. 回归：既有测试文件零改动全绿；`npm test --workspace server`（覆盖率 ≥80%）、`make lint`、`make typecheck`、`make anti-drift`（knip 零新增）、`bash scripts/size-guard.sh` 退出 0；PR 记录 `store.ts`、`rest-metadata.ts`、`session-metadata-rest.test.ts` 前后行数。
