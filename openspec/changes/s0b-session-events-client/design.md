## Reducer / View Contract
- Export applyChatEvent and chatStateFromSnapshot, with ChatState declared at the view owner. Import named ChatMessage/ChatStep/ChatStreamCursor from their current DTO owner; never infer concrete contracts through ReturnType.
- ChatState holds session status and ordered message views. Message views project id/role/content/status/steps and an inline error (string|null); step views project id/name/detail/status. Do not fabricate timestamps or ordinals absent from SSE. Snapshot conversion is pure and preserves full content and order.
- Wire ChatEvent is the six-event tagged union from server/src/sessions/events.ts, with numeric messageId/stepId; step.end includes detail; error.messageId is required. No server source import.
- turn.start creates an absent assistant view or resets the matching assistant body/steps/error to empty/running; preserve unrelated and user messages. Other valid message-targeted events can materialize an absent assistant (lone synthetic turn.end and pre-start failure are real producer paths). Never rewrite a user message sharing an invalid target ID.
- text.delta appends exactly; step.start adds one running step keyed within its message (duplicate start does not duplicate an existing step); step.end updates an existing step's status AND detail, and ignores an unknown step lacking start metadata.
- error marks its assistant failed and records the exact message; session stays running until turn.end so the composer cannot unlock early. turn.end sets message/session status and settles remaining running steps to the same terminal status, matching store.finishOwnedTurn. A terminal with no preceding start/error is valid.
- Unknown event types return the original state. Reduction never mutates input; copy only changed branches; preserve error until reset/new snapshot or a successful terminal for that message.

## Connector Contract / Ownership
- connectSessionEvents(sessionId, {EventSourceCtor, initialCursor, loadSnapshot, onSnapshot, onEvent, onGap?, onError}) returns an idempotent {close()} handle. Constructor is required/injected; URL is /api/sessions/<encodedId>/events with withCredentials:true.
- loadSnapshot(signal:AbortSignal) returns Promise<ChatMessageSnapshot> from the caller's current account-bound ApiClient. onSnapshot installs the full view synchronously; onEvent consumes one typed data event synchronously. onGap is an optional synchronous notification for actual replay.gap only. onError receives terminal recovery/protocol-consumer failure; it is not a data-event error handler.
- Register listeners for each named data event plus replay.gap/open/error, not only onmessage. Parse JSON payload-only and canonical safe-integer lastEventId epoch:seq (data seq>=1). Unknown types are ignored. Known malformed payload/id must trigger resynchronization rather than silent content loss or an uncaught parse error.
- A named business error is a MessageEvent with string data; a native transport error is not. CONNECTING transport errors leave chat state untouched and let native reconnect run. CLOSED transport errors terminate this handle and report connection failure; do not guess 401 from a native EventSource error. Auth/page owner closes on unmount, session switch and logout in #104; no global auth listener here.
- Every open starts a snapshot recovery, including first open and reconnect. This closes the observed completed-between-REST-and-subscribe hole without server changes or custom reconnect timers/headers. replay.gap notifies onGap and starts a newer recovery.
- A recovery owns a generation token and AbortController. Set recovering before invoking external callbacks; abort/invalidate any older load. Queue data while loading/installing/draining. Install only the still-current result for this session while not closed; mismatched session or a regressive snapshot is a terminal error, not a cross-session/older-view install.
- Cursor rule: drop older epoch; in equal epoch drop all if seq:null, otherwise seq<=boundary; accept greater epoch/same-epoch successors in arrival order. Apply to ALL data types, including turn.start. Advance the delivered watermark to suppress duplicate reconnect frames; a sealed epoch remains sealed until a greater epoch.
- Snapshot installation and queued draining are synchronous, fenced around caller callbacks. Reentrant delivery appends behind already queued events; close/gap/overflow during callbacks invalidates the old drain before more events/install effects. Never await an onSnapshot/onEvent callback; returned thenables are consumer contract violations: contain rejection, close and report rather than proceeding as if installed.
- Pending queue is capped at1000 data events (count limit, not a byte-budget claim). Overflow invalidates the current load, discards its queue and immediately requests a newer snapshot, retaining the triggering event for post-snapshot filtering. Repeated gap similarly supersedes, never resumes a partial old queue.
- loadSnapshot rejection or synchronous/thenable consumer callback failure closes the source, aborts load, discards queued data and reports once through onError; preserve original API errors. Contain a failing onError notification like the existing API unauthorized notifier. No added retry/backoff policy, polling or silent failure continuation.
- close removes listeners, closes native source once, aborts recovery and invalidates promises even if a loader ignores AbortSignal; later resolution/rejection/events cannot install or notify.
