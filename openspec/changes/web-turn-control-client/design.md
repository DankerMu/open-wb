# Design: web-turn-control-client（#472）

父设计：D6「事件与快照契约同刀」（`stopped` 枚举 web-parse-before-server-emit）。行号均为 origin/master（bb1f1aa）。

- **Change surface**：`web/src/lib/session-contract.ts`、`web/src/lib/api-sessions.ts`、`web/src/features/chat/stream.ts`、`web/src/features/chat/status-label.ts`；`web/src/lib/api.ts` 仅类型成员 + 注入（proposal 偏离 1）。
- **Must preserve**：
  - `api.ts` 导出集合与既有 `ApiClient` 成员（111-137）逐字不变，零新增 `export`；`createSessionMethods` 仍在返回对象首位展开（511-516）；`request`（474-490）、`parseJsonResponse`（438-472）、`fetchResponse`（430-436）、`notifyUnauthorized`（378-387）零改动——新方法的信封/401/request_failed 全经它们。
  - `api-sessions.ts` 对 `./api.js` 仍只有 `import type`（:1）；既有四方法体（29-96）逐字不变。
  - `session-contract.ts`：会话 DTO 键集 `{id,title,status,createdAt,updatedAt}`（:72）与消息键集 `{id,role,content,status,createdAt,steps}`（:112，`approvals` 归 5.3）不变；未知枚举（如 `pending`/`queued`）仍整体拒绝。
  - `stream.ts`：`step.end` 解码仍只接受 `done|failed`（655-671；#455 不放宽 server `step.end.status`，被停止回合的 running 步骤由 `turn.end` 结算）；`DATA_EVENTS`（67-74）、游标过滤与恢复逻辑零改动；`endTurn`（191-206）对 `done`/`failed` 的输出逐值不变。
- **Must add/change**：
  - `session-contract.ts`：`ChatSessionStatus`（:3）加 `stopped`、`ChatDeliveryStatus`（:5）加 `stopped`，`isSessionStatus`/`isDeliveryStatus`（59-69）随之；私有 `type ChatApproval = {id,tool,title,requestedAt,expiresAt,decision: "allow"|"deny"|"timeout"|null}` 与私有 `parseApproval`（六键严格；`id`/`requestedAt`/`expiresAt` 有符号安全整数、`tool`/`title` 字符串）；导出 `ChatRegenerateAccepted`、`ChatSessionFork`、`ChatSettledApproval`（`ChatApproval & {decision: 非 null}`）与 `isStopAccepted(v)`（`hasExactlyKeys(v, [])`）、`parseRegenerateAccepted`、`parseSessionFork`（`session` 经 `parseSession`，`draft` 任意字符串）、`parseSettledApproval`（`parseApproval` 后 `decision === null` 判非法）。
  - `api-sessions.ts`：`SessionTransport` 增 `fetchResponse(path, init)`、`isSuccessfulStatus(status)`、`parseJsonResponse(response, signal, onUnauthorized)`；返回 `Pick` 扩为八方法。`stopSession`：`fetchResponse(POST, 无 body/无 Content-Type)` → 204 直接 `"idle"`（不读 body）；非 202 的 2xx → `requestFailed(status)`；否则 `parseJsonResponse`（非 2xx 在此抛信封/401 通知）→ `isStopAccepted` 失败 `requestFailed(202)`，成功 `"stopping"`（`logoutRequest` 492-507 同形先例）。`regenerateSession`：`request(POST 无 body, 202)`；`forkSession`：`request(POST JSON {messageId}, 201)`；`decideApproval`：`request(POST JSON {decision}, 200)`，路径 `/api/sessions/${encodeURIComponent(id)}/approvals/${encodeURIComponent(String(approvalId))}`；三者 JSON 请求头 `Content-Type: application/json`，与 prompt 同。
  - `api.ts`：`import type` 加 `ChatRegenerateAccepted`/`ChatSessionFork`/`ChatSettledApproval`；`ApiClient` 加四成员（签名见 issue Key interfaces，返回类型用上述三名与 `"stopping" | "idle"`）；注入展开加 `fetchResponse`/`isSuccessfulStatus`/`parseJsonResponse`。
  - `stream.ts`：`ChatTerminalStatus`（:34）拆为 `ChatStepEndStatus = "done"|"failed"` 与 `ChatTurnEndStatus = ChatStepEndStatus|"stopped"`，`step.end` 用前者、`turn.end` 用后者；`isTerminalStatus`（693-695）拆为两守卫；`endTurn` 的 error 取 `status === "failed" ? message.error : null`。**决策**：`stopped` 清空 error（同 done）而非保留——会话页 `stopped` 助手消息「no error text」（父 chat-web 会话页），且 #455 归约器对被中断回合只发 `turn.end stopped`、从不先发 `error`，故生产不可观测；用一条运行时断言钉住。
  - `status-label.ts`：加 `stopped: "已停止"`；注释改为「步骤徽章复用 running/done/failed/stopped 四项」。
  - 行数（草稿镜像经 `biome format` 实测）：`api.ts` 681 + 3（import type）+ 16（四成员）+ 3（注入）= 703；`api-sessions.ts` 98 → ~204；`session-contract.ts` 183 → ~258；`stream.ts` 717 → ~722；`status-label.ts` 9 → 10；均 ≤800（`constraints.yaml` `size_limits.max_file_lines`，`scripts/size-guard.sh` `MAX=800` 平铺、无按路径下调；#471 的「≤700」是其自设余量目标），`api.ts` 余 97 行。
- **Governing invariant**：server 可能发出的每个 `stopped`（会话列表、快照三层 status、`turn.end`、fork 响应里的 `session`）web 都接受并逐值保留；其余未知值仍整体拒绝；新方法的非 2xx 一律保留信封 status/code/message。
- **Sibling surfaces**：
  - 查表呈现（零源码改动，行为随之）：`session-nav.tsx:32-46`、`conversation-view.tsx:30-42` 对 `stopped` 显示 `已停止`，class `chat-session-dot-stopped`/`chat-step-status-stopped` 暂无样式（7.2 #477）；`page.tsx:699` 锁定判 `=== "running"`，`stopped` 自然解锁；`page.tsx:663-680` 列表状态同步透传 `stopped`。
  - 错误分流：`features/files/{tree.tsx:596,page.tsx:376}` 按 409 分支仅限工作空间操作，不受影响；7.x 调用方须按 `error.code` 区分 `approval_settled`/`session_busy`（carry-forward），本刀只保证 code 透出。
  - server：`stopped` 发出方（#455/#473/#488/#475）与 approvals 投影（#476）本刀零改动。
  - **必然破坏的既有测试：无**。已在草稿镜像跑既有 53 文件 / 1017 例：`tsc --noEmit` 0，除镜像缺仓外文件（ENOENT）外全绿。逐项核对：`api-sessions.test.ts:201-210` 状态接受表与 `:291`/`:308` 未知枚举拒绝（`pending`/`queued`）不受影响；`chat-stream.test.ts:300` `["done","failed"]` 循环不变；`chat-composer.test.tsx:150-184`（C4）四态表非穷举；无测试以 `stopped` 作非法样例；无静态测试读四个目标文件。**允许的既有测试编辑：无**（`web/test/**` 既有文件零 diff，含 `chat-stream-support.ts`——其 `runningSession`/`chatSnapshot` 选项类型 38-56 仍窄，新测试以展开覆盖或自建快照构造 `stopped`，不得拓宽该文件、不得 `as never`）。
- **Seams under test**：`createApiClient()` + `vi.stubGlobal("fetch", …)`，辅助取 `web/test/support.ts` 的 `jsonResponse`/`captureApiError`/`expectRequestFailure`/`unauthorizedResponseCases`（先例 `web/test/api-sessions.test.ts`）；204 用 `new Response(null,{status:204})` 并 `vi.spyOn(response,"json")`/`"text"` 断言未调用；归约用 `chatStateFromSnapshot`/`applyChatEvent`；连接器用 `web/test/chat-stream-support.ts` 的 `connectChat` + `FakeEventSource.emitOpen/emitData` + `context.loads[0].resolve(...)`（先例 `chat-stream-recovery.test.ts`）；文案直接导入 `SESSION_STATUS_LABEL`。
- **Required evidence**（`api-turn-control.test.ts`、`chat-stream-stopped.test.ts`）：
  - 四方法请求：会话 id `sess/%#?+ 中`、`approvalId` 7 → 路径 `…/sess%2F%25%23%3F%2B%20%E4%B8%AD/stop|regenerate|fork|approvals/7`；`toHaveBeenCalledWith` 恰为 `{method:"POST",credentials:"same-origin",signal}`（stop/regenerate 无 body 无 headers）、fork 加 `headers` + `body:'{"messageId":-3}'`、approvals 加 `body:'{"decision":"allow"}'`（`deny` 同）。
  - stop：202 `{}` → `"stopping"`；204 → `"idle"` 且 `json`/`text` 未被调用；202 `{"x":1}`、202 `[]`、202 非 JSON、200 `{}` → `request_failed`（status 202/202/202/200）。
  - regenerate 202 `{assistantMessageId:-9007199254740991}` 原值；缺键、多键、`1.5`、`2**53` → request_failed(202)。fork 201 `{session:<status "stopped">, draft:""}` 与 `draft:"  原文\n"` 逐值返回；`draft` 非字符串、多键、缺 `draft`（仅 `{session}`）、缺 `session`（仅 `{draft:""}`）、`session` 多键或未知 status → request_failed(201)。approvals 200 六键 `decision` 为 `allow`/`deny`/`timeout` 逐值；`decision:null`、未知 decision、缺/多键、非安全整数 id → request_failed(200)。
  - 快照/列表：会话 status `stopped` 的 `listSessions`；`getMessages` 中会话、assistant 消息与其步骤 status 均为 `stopped` → `toEqual` 原样；步骤 status `cancelled` → 整体 request_failed。
  - 信封：regenerate/prompt 503 `agent_capacity`、approvals 409 `approval_settled`、regenerate/fork 409 `session_busy` 与 400 `bad_request`、stop 503 → `ApiError` status/code/message 原样；`unauthorizedResponseCases()` 三种 401 对 stop 与 approvals 各触发 `onUnauthorized` 一次且拒绝为 401。
  - 归约：running assistant（含 running `bash` 步骤 output `"o"`、另一 done 步骤）+ `turn.end{messageId,status:"stopped"}` → 会话/消息/`bash` 步骤 `stopped`、`bash` output `"o"`、done 步骤不变、`error: null`，user 消息与 done 步骤对象同一引用、输入未被修改；对不含该 assistant 的状态单独施加 `turn.end(stopped)` → 补建 `stopped` assistant、会话 `stopped`；先 `error{message:"x"}` 后 `turn.end(stopped)` → `error: null`。
  - 连接器：快照游标 1:5 安装后 `text.delta`(1:5) 丢弃、`text.delta`(1:6) 与 `turn.end stopped`(1:7) 依序进入 `events`，最终状态 `stopped`；`step.end{status:"stopped"}` 与 `turn.end{status:"cancelled"}` 分别在各自独立的连接上触发新的快照加载（resync，`loads` 增 1）且不进入 `events`。
  - 文案：`SESSION_STATUS_LABEL.stopped === "已停止"` 且 `Object.keys` 恰为五态（tsc 穷举由 `Record<ChatSession["status"],string>` 保证）。
  - 红/绿：四方法、`stopped` 快照/列表/fork 解析、连接器交付 `turn.end stopped`、`SESSION_STATUS_LABEL.stopped`、error→stopped 清空为**运行时红先**；主归约场景（running assistant + `turn.end stopped`）在 master 运行时已透传 status，**仅 `tsc` 红**（测试字面量 `status:"stopped"` 不可赋值），PR 记录 `make typecheck` 红输出。**guards, always green**：`step.end stopped` 与未知 `turn.end` status 触发 resync、未知枚举拒绝、done/failed 归约不变、既有 1017 例。
- **Non-goals**：见 proposal。
- **Review focus**：stop 的 204 不读 body 且非 202 的 2xx 拒绝；`api-sessions.ts` 仍只 `import type` 自 `api.js`、`api.ts` 零新增 export；`step.end` 未被放宽；fork 的 `session` 复用 `parseSession`；spec delta 未越界到 `approvals`/呈现/chat-stream。
