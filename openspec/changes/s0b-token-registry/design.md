## Goals / non-goals
One in-memory registry instance holds at most one live token per session and one session per live token. O(1) lookup and session revocation; no scan over all credentials. No persistence/TTL/refresh protocol/quotas/user validation, no proxy/runtime edits, no upstream-key handling or printing token material. Cross-process isolation remains process/runtime work, not promised here.
## API and state
Export class TokenRegistry, default constructor with no required dependencies. issue(sessionId:string):string; lookup(token:string):string|null; revoke(sessionId:string):void. Session IDs are trusted opaque caller identifiers, not parsed/normalized here. Methods structurally fit both existing ports; tests use those interfaces as actual typed consumers. Keep token→session and session→token maps private and instance-local; no public enumeration, diagnostics or global singleton.
lookup is an exact case-sensitive opaque-string match. Unknown, empty, malformed, altered-case or revoked strings returnnull, not an exception. revoke of an unknown/already-revoked session is harmless. Revoking/rotating one session cannot affect another or a separate registry instance. A fresh registry contains no prior bindings.
## Issuance and failure ownership
Each issue calls node:crypto randomBytes(32) and encodes lowercasehex. Prepare the new candidate before mutating either index. If entropy generation throws, propagate without publishing a token or invalidating an existing binding; no Math.random/counter/time/session-ID fallback. If the candidate already belongs to any current binding (including that session's old token), throw a generic non-secret error and leave all bindings unchanged. No implicit retry loop. Otherwise retire only the prior token for this session and publish both directions synchronously before returning.
Uniqueness is enforced among live bindings, and rotation cannot return the currently live token. No unbounded historical-token tombstone set: previously revoked random values are not retained forever;256-bit CSPRNG entropy provides practical non-reuse. The required1000-token empirical uniqueness test is not a proof of cryptographic unpredictability; source review pins the actual CSPRNG call and failure tests prove no fallback.
Private index updates use ordinary synchronous Maps; no awaits or callback re-entry inside a commit. Catastrophic allocation failure is outside the recovery contract. Invalid/malicious replacement of Node crypto is not production configuration; focused fault tests may mock the dependency, never the registry. No public random-provider abstraction is needed.
