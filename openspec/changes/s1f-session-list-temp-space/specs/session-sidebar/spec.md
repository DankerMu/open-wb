## ADDED Requirements

### Requirement: 会话 DTO 严格解析
web 的会话解析 SHALL 要求会话对象恰含十一键 `{id,title,status,createdAt,updatedAt,scene,workspaceId,pinnedAt,archivedAt,pendingApproval,temporaryWorkspace}`（`hasExactlyKeys`），并逐键校验：`status` ∈ `idle|running|done|failed|stopped`；`scene` ∈ `office|code|design|null`；`workspaceId` 为 32 位小写十六进制字符串或 null；`pinnedAt` 与 `archivedAt` 为非负安全整数或 null；`pendingApproval` 与 `temporaryWorkspace` 为布尔；`workspaceId` 为 null 而 `temporaryWorkspace` 为 true 的对象不合法。缺键、多余键或任一值不合法 SHALL 使该响应按既有规则视为无效成功响应（不部分采用）。该规则 SHALL 统一作用于 `GET /api/sessions` 列表项、`POST /api/sessions` 与 `PATCH /api/sessions/:id` 响应、消息快照的 `session`、fork 与 undo 响应的 `session`。API 客户端的 `patchSession(id, patch)`（`PATCH`，JSON body，成功 200 返回解析后的会话；`patch` 的键为 `title`、`scene`、`pinned`、`archived` 的非空子集）、`deleteSession(id)`（`DELETE`，无 body，成功恰为 204）与 `createSession(input?, options?)`（可选 input `{workspaceId?, scene?}`）沿用既有 same-origin、AbortSignal、错误信封与 401 通知机制，路径 id 编码。键集的服务端一侧见 session-metadata「会话视图扩展键」；二者 SHALL 同一个改动落地。

#### Scenario: 十一键接受与其它键集拒绝
- **WHEN** `GET /api/sessions` 分别返回：合法十一键会话；缺 `archivedAt` 的十键会话；旧的八键会话；多一个 `parentSessionId` 的十二键会话；`pendingApproval:"yes"` 的会话；`workspaceId:null` 且 `temporaryWorkspace:true` 的会话
- **THEN** 第一种被接受并渲染；其余五种都使列表读取呈现既有的无效响应失败，不渲染任何部分列表

#### Scenario: 客户端方法
- **WHEN** 调用 `patchSession(id,{archived:true})`、`patchSession(id,{pinned:true})`、`deleteSession(id)`、`createSession({scene:"code"})` 与无参 `createSession()`
- **THEN** 请求分别为 `PATCH /api/sessions/<id>` body `{"archived":true}`、同路径 body `{"pinned":true}`、`DELETE /api/sessions/<id>` 无 body、`POST /api/sessions` body `{"scene":"code"}` 且 `Content-Type: application/json`、`POST /api/sessions` 无 body；`deleteSession` 对 200 视为无效响应

### Requirement: 会话状态标记
每个条目 SHALL 有一个 `role="status"` 的状态元素，accessible name 为 `<显示标题> <状态文案>`，状态文案按以下优先级取一：`pendingApproval` 为 true → `等待确认`；否则 `status="running"` → `运行中`；`failed` → `失败`；`done` → `已完成`；`stopped` → `已停止`；`idle` → `未开始`。**可见标记只有三种**：`等待确认` 为一个醒目的提示点，`运行中` 为一个转动的指示（`prefers-reduced-motion: reduce` 下不转动），`失败` 为错误色标记；`已完成`、`已停止`、`未开始` SHALL NOT 有任何可见标记，其状态文案只以视觉隐藏的文本存在。三种可见标记 SHALL 彼此可由 `data-status-mark` 属性区分（`waiting` | `running` | `failed`），无可见标记的条目不带该属性。标记是装饰性的（`aria-hidden`），不可聚焦、不可点击。条目 SHALL NOT 显示未读标记。状态的新鲜度由 session-list-push 的列表事件保证。

#### Scenario: 六种状态的呈现
- **WHEN** 列表含 `pendingApproval` 为 true 的 `running` 会话、另一个 `running` 会话、`failed`、`done`、`stopped`、`idle` 会话各一个
- **THEN** 六个状态元素的可访问名依次以 `等待确认`、`运行中`、`失败`、`已完成`、`已停止`、`未开始` 结尾；前三者分别带 `data-status-mark` 为 `waiting`、`running`、`failed` 的可见标记，后三者没有带该属性的元素

#### Scenario: 待决确认结算后回到运行中
- **WHEN** 一次列表读取里某会话 `pendingApproval` 为 true，下一次读取里为 false 且 `status` 仍为 `running`
- **THEN** 其标记由 `waiting` 变为 `running`，可访问名由以 `等待确认` 结尾变为以 `运行中` 结尾

### Requirement: 标题搜索
列表区 SHALL 有一个 accessible name 与 placeholder 均为 `搜索任务` 的搜索框。查询去掉首尾空白后非空时，当前视图（默认视图或归档视图）SHALL 只保留显示标题（服务端 title，null 时为 `新会话`）含该查询的会话——大小写不敏感的子串匹配——并忽略分组的折叠状态（保留下来的条目所在分组一律展开显示，折叠的存储值不被改写）；空分组不渲染；无匹配时显示 `没有匹配的任务`。查询为空（或只有空白）时恢复未过滤的视图与原有折叠状态。搜索 SHALL 纯前端在已加载的列表上计算，不发任何请求，不搜索消息内容。默认视图的搜索结果 SHALL NOT 含已归档的会话；进入归档视图后同一搜索框只在已归档的会话里搜。查询是会话页内存状态：切换会话、切换默认视图与归档视图、折叠再展开侧栏时保留，刷新或离开会话页清空，不写 storage。搜索只影响侧栏条目，不改变当前选中会话及其主区内容。

#### Scenario: 过滤与恢复
- **WHEN** 默认视图有 `周报整理`（W1 分组，已折叠）、`Weekly Sync`、`新会话`（title 为 null）三个会话与一个已归档的 `周报存档`，依次输入 `周报`、` WEEK `、`新会`、`不存在`，再清空
- **THEN** 依次只显示 `周报整理`（其分组展开显示）；只显示 `Weekly Sync`；只显示 `新会话`；显示 `没有匹配的任务`；清空后三个会话都在且 `W1` 回到折叠；`周报存档` 始终不出现；全程没有网络请求

#### Scenario: 归档视图里搜索
- **WHEN** 进入归档视图后输入 `周报`
- **THEN** 只显示 `周报存档`，不显示未归档的 `周报整理`

#### Scenario: 不影响主区
- **WHEN** 选中 `Weekly Sync` 后输入一个不匹配它的查询
- **THEN** 侧栏不显示它，主区仍是它的线程，URL 不变

### Requirement: 归档视图
列表区底部（分组列表之后）SHALL 有一个 accessible name 为 `已归档` 的入口按钮，任何时候都渲染（含没有已归档会话时）。点击后列表区切换为归档视图：`新建会话`、搜索框保留，`分组方式` 与分组列表被替换为标题 `已归档`、一个 accessible name 为 `返回会话列表` 的按钮与全部 `archivedAt` 非 null 的会话的平铺列表（服务端顺序，不分组、不显示置顶区）；没有已归档会话（或搜索无匹配）时显示 `没有匹配的任务`。`返回会话列表` 回到默认视图并把焦点放回 `已归档` 入口。归档视图是会话页内存状态，刷新后回到默认视图。

归档视图里的条目与默认视图同形（选择按钮、状态元素、「更多」按钮），其菜单恰两项：`恢复`（发送 `PATCH {archived:false}`；200 后该条目离开归档视图、按其置顶与分组规则回到默认视图；失败走列表区顶部提示）与 `删除`（与默认视图相同的确认与删除流程）。选择一个已归档的会话 SHALL 与选择普通会话一样更新 `?session=<id>`，主区按 chat-web「会话页」的归档只读呈现；直接打开 `/?session=<已归档 id>` 同样只读呈现，侧栏停在默认视图。已归档的会话 SHALL NOT 出现在默认视图的任何分组（含 `置顶任务`）里。

#### Scenario: 查看、恢复
- **WHEN** 账号有一个已归档且置顶的会话 `旧项目`，点击 `已归档`，再对它选择 `恢复`（200）
- **THEN** 进入归档视图后可见标题 `已归档`、`返回会话列表` 与条目 `旧项目`，其菜单恰为 `恢复`、`删除`；默认视图的 `置顶任务` 里没有它；恢复时发出 `PATCH {"archived":false}`，其后归档视图显示 `没有匹配的任务`；点击 `返回会话列表` 后它在 `置顶任务` 里，焦点在 `已归档` 入口

#### Scenario: 在归档视图删除
- **WHEN** 在归档视图对一个独占临时空间的已归档会话选择 `删除` 并确认，DELETE 返回 204
- **THEN** 确认框说明含 `临时空间里的文件会一并删除。`；204 后条目消失

#### Scenario: 打开已归档的会话
- **WHEN** 在归档视图选择 `旧项目`
- **THEN** URL 为 `?session=<其 id>`；主区显示其消息与 `该会话已归档，恢复后才能继续对话`，没有输入框

### Requirement: 导出记录
菜单项 `导出记录` SHALL 在前端生成一个 Markdown 文件并触发浏览器下载，不调用任何新的服务端端点：数据取自该会话的消息快照——它是当前选中会话且历史已加载时用页面持有的视图，否则读取一次 `GET /api/sessions/:id/messages`。文件内容由一个纯函数生成，逐字节为：
- 标题块：一行 `# <显示标题>`；
- 按消息顺序，每条消息一段，段由若干「块」组成：第一块是标题行（用户消息为 `## 用户`，助手消息为 `## 助手`）；正文非空时第二块是正文原文（用户消息的原文、助手正文的原文），正文为空串时没有这一块；助手消息有步骤时最后一块是步骤列表，按步骤顺序每个步骤一行 `- <步骤名>（<状态文案>）`，状态文案为 `运行中` / `已完成` / `失败` / `已停止`；
- 全文是标题块与各段的各块按序排列，相邻两块之间恰一个空行（即以 `\n\n` 连接），文件以单个换行结尾。因此正文为空而有步骤的助手消息是 `## 助手\n\n- …`，正文为空且没有步骤的助手消息只有 `## 助手` 一行。

导出 SHALL NOT 含思考内容、步骤的 detail 与 output、审批记录、文件变更与产物、任务清单。零消息的会话导出只有标题行。下载文件名为显示标题去掉 `/`、`\`、控制字符与首尾空白后加 `.md`，结果为空时为 `会话.md`；MIME 类型 `text/markdown;charset=utf-8`。读取快照失败时不下载，走列表区顶部提示。导出对任何状态的会话可用，不改变任何服务端状态。

#### Scenario: 导出内容
- **WHEN** 会话标题为 `季度/汇报`，消息为 用户 `帮我写提纲`、助手（正文 `好的。`，thinking `先想想`，步骤 `write`（done，detail 与 output 非空）与 `bash`（failed））、用户 `谢谢`，对它选择 `导出记录`
- **THEN** 下载的文件名为 `季度汇报.md`，内容逐字节为 `# 季度/汇报\n\n## 用户\n\n帮我写提纲\n\n## 助手\n\n好的。\n\n- write（已完成）\n- bash（失败）\n\n## 用户\n\n谢谢\n`；其中没有 `先想想`，也没有步骤的 detail 与 output

#### Scenario: 空正文的助手消息
- **WHEN** 会话标题为 `空回合`，消息为 用户 `跑一下`、助手（正文为空串，步骤 `bash`（done））、用户 `再来`、助手（正文为空串、没有步骤、状态 `stopped`）
- **THEN** 导出内容逐字节为 `# 空回合\n\n## 用户\n\n跑一下\n\n## 助手\n\n- bash（已完成）\n\n## 用户\n\n再来\n\n## 助手\n`

#### Scenario: 非当前会话与失败
- **WHEN** 对一个未选中的会话选择 `导出记录`；另一例其快照读取返回 502
- **THEN** 前者恰发出一次 `GET /api/sessions/<id>/messages` 后下载；后者不下载，列表区顶部 `role="alert"` 显示信封文案；两例都没有别的请求

### Requirement: 另存为工作空间对话框
菜单项 `另存为工作空间`（只在 `temporaryWorkspace` 为 true 的会话上）SHALL 打开对话框，标题 `另存为工作空间`，说明 `临时空间会原地变成正式工作空间，文件不移动；之后它出现在文件页，删除会话不再删除这些文件。`，含 accessible name `工作空间名称` 的输入框（初值为空；打开时焦点在输入框）与按钮 `取消` / `保存`。trim 后为空或超过 64 个字符时 `保存` 禁用。`保存` 或输入框内 Enter 以 trim 后的名字调用一次 `promoteWorkspace(<该会话的 workspaceId>, name)`（temporary-workspaces「转正」），请求中 `保存` 禁用、不重复发送。200 后关闭对话框、焦点还给打开它的按钮，并重新读取会话列表与工作空间列表：该会话（及共用同一空间的其它会话）移入以新名字为名的分组，它们的菜单不再有 `另存为工作空间`，当前会话能力栏的只读标签变为 `任务启动于 <新名字>`。失败时对话框保持打开并在其内以 `role="alert"` 显示信封 message（如 409 `同名资源已存在`）。请求中关闭对话框不取消请求：其后的 200 照常触发重新读取，失败走列表区顶部提示。会话运行中也可使用。不显示轻提示。

#### Scenario: 转正后移入新分组
- **WHEN** 对 `临时空间` 分组里的会话选择 `另存为工作空间`，输入 `  调研资料  ` 并点击 `保存`，promote 返回 200，随后的列表读取显示该会话 `temporaryWorkspace` 为 false、工作空间列表含 `调研资料`
- **THEN** 恰发出一次 `POST /api/workspaces/<该 workspaceId>/promote`，body 为 `{"name":"调研资料"}`；对话框关闭；该会话位于名为 `调研资料` 的分组、不在 `临时空间`；其菜单没有 `另存为工作空间`；没有轻提示

#### Scenario: 同名冲突留在对话框
- **WHEN** promote 返回 409 `conflict`
- **THEN** 对话框仍打开，其内 `role="alert"` 文本为 `同名资源已存在`；列表不变；修改名字再次 `保存` 时该提示清除

#### Scenario: 只在临时空间的会话上出现
- **WHEN** 打开绑定正式空间的会话与 `workspaceId` 为 null 的存量会话的菜单
- **THEN** 两者都没有 `另存为工作空间`

### Requirement: 分组侧栏
侧栏列表区（spa-shell「路由 IA 与侧栏」，`nav` accessible name `会话列表`）SHALL 自上而下渲染：既有的 `新建会话` 按钮（名称与行为不变）、搜索框（「标题搜索」）、`分组方式` 切换、分组列表、`已归档` 入口（「归档视图」）。`筛选任务` 按钮及其弹层 SHALL NOT 渲染。默认视图只含未归档的会话（`archivedAt` 为 null）；每个会话恰一个条目。

**置顶区**：`pinnedAt` 非 null 的会话归入名为 `置顶任务` 的分组，它始终排在最前，不受分组方式影响。

**分组方式** SHALL 有两种，默认 `按工作空间`：
- `按工作空间`：未置顶的会话按工作空间分组。`workspaceId` 在已读取空间列表中的会话归入以空间名为名的分组，分组顺序为 `GET /api/workspaces` 的返回顺序；`temporaryWorkspace` 为 true 或 `workspaceId` 为 null 的会话归入名为 `临时空间` 的分组（存量的未绑定会话与临时空间的会话同组），排在各工作空间分组之后；其余（`workspaceId` 非 null、`temporaryWorkspace` 为 false、但不在已读取空间列表中）归入末位的 `未知空间` 分组。「已读取空间列表」为会话页最近一次成功读取的结果：首次读取完成之前与最近一次读取失败之后没有已读取列表（这类会话全部归 `未知空间`）；重新读取进行中沿用上一次成功读取的列表。
- `按时间`：未置顶的会话按 `updatedAt` 的本地日历日分为 `今天`（与当前时间同一本地日历日，或更晚）、`近 7 天`（今天之前的 1 至 6 个日历日）、`更早`（其余），依此次序。当前时间取列表渲染时刻，不设定时器。

`分组方式` SHALL 是一个 accessible name 为 `分组方式` 的按钮，打开含两个 `role="menuitemradio"` 项 `按工作空间` / `按时间` 的菜单，当前项 `aria-checked="true"`；选择后菜单关闭、列表立即按新方式分组、焦点回到该按钮，不发请求。

每个分组 SHALL 为带 accessible name（即其标签）的 `role="group"`，其标签行是一个按钮，以 `aria-expanded` 表示展开与否；点击切换折叠，折叠的分组不渲染其条目。空分组不渲染。各分组内条目 SHALL 保持服务端列表顺序（`updatedAt` 降序、id 升序）。分组方式与折叠状态 SHALL 记在浏览器本地：`localStorage` 键 `workbuddy-session-grouping`（`workspace` | `time`；缺失或非法按 `workspace`）与 `workbuddy-session-collapsed`（JSON 字符串数组，元素为分组键：`pinned`、`temporary`、`unknown`、`today`、`week`、`earlier` 或工作空间 id；缺失或解析失败按空数组）；读取或写入失败 SHALL 静默并保留内存状态。二者在刷新、切换会话、折叠再展开侧栏、关闭再打开导航覆盖层后保持。

会话列表已读取而默认视图没有任何条目时（含账号尚无会话、全部已归档、搜索无匹配）SHALL 只渲染文本 `没有匹配的任务`，不渲染分组；会话列表读取中或读取失败时沿用 chat-web 既有的 `正在读取会话` 与错误提示，不渲染该文本。条目 SHALL 含选择按钮（accessible name 为显示标题，标题回退 `新会话`，选中时 `aria-current="true"`）、状态元素（「会话状态标记」）与行尾的「更多」按钮（「会话条目菜单与重命名」），除此之外不显示时间、空间名、摘要或未读标记。分组标签按钮、`分组方式`、搜索框与「更多」菜单 SHALL NOT 触发 `≤760px` 导航覆盖层的关闭；选择会话与 `新建会话` 照常关闭它。工作空间名只取自 `GET /api/workspaces`，前端不渲染空间根路径与临时空间的目录名。列表不使用 assistant-ui 运行时的 thread-list 适配器。

会话页 SHALL 在每次读取会话列表时并行读取 `GET /api/workspaces`；两个请求互不等待：会话列表到达即渲染，工作空间读取失败在列表区只影响归组，不产生列表区的错误提示，也不改变会话列表的读取结果。

#### Scenario: 按工作空间分组
- **WHEN** 列表含：已置顶且绑定 W1 的 A、未置顶绑定 W1 的 B、未置顶绑定 W2 的 C、`temporaryWorkspace` 为 true 的 D、`workspaceId` 为 null 的 E、已归档的 F（服务端顺序 F、E、D、C、B、A），空间列表顺序为 W2、W1

## MODIFIED Requirements

### Requirement: 会话条目菜单与重命名
每个条目 SHALL 有 accessible name 为 `更多操作：<显示标题>` 的图标按钮，它是选择按钮的同级元素（不嵌套），始终在 DOM 中且可聚焦（`≥761px` 且支持悬停的设备上仅以透明度弱化，悬停、聚焦或菜单打开时显现）。默认视图里它打开的菜单项依次为：`重命名`、`置顶任务` 或 `取消置顶`（按该会话 `pinnedAt` 是否为 null）、`归档`、`删除`（危险样式）、`另存为工作空间`（仅当该会话 `temporaryWorkspace` 为 true 时渲染）、`导出记录`；除此之外没有别的项。`归档` 在会话 `status="running"` 时为禁用项（`aria-disabled="true"`，选择不发请求）；其余项对任何状态的会话均可用。归档视图里的菜单见「归档视图」。「更多」按钮与菜单项 SHALL NOT 触发 `≤760px` 导航覆盖层的关闭。

会话列表的动作 SHALL NOT 显示任何轻提示（不出现 `已重命名`、`已更新置顶状态`、`任务已删除` 等文本）：成功以列表自身的变化为反馈；对话框内发起的请求失败时在该对话框内以 `role="alert"` 显示；没有对话框的动作（置顶、归档、恢复、导出）以及对话框已关闭后才到达的失败，SHALL 在列表区顶部以一条 `role="alert"` 显示信封 message（非信封失败为 `请求失败，请稍后重试`），该提示带 accessible name 为 `关闭提示` 的按钮，并在下一次列表动作发起时清除。

- `重命名`：打开对话框，标题 `重命名任务`，含 accessible name `任务名称` 的输入框（初值为服务端 title，null 时为空；打开时焦点在输入框）与按钮 `取消` / `保存`；trim 后为空时 `保存` 禁用；`保存` 或输入框内 Enter 以 trim 后的文本发送一次 `PATCH {title}`，请求中 `保存` 禁用、不重复发送；200 后关闭对话框并把焦点还给打开它的按钮，列表条目与顶栏面包屑以响应视图的标题更新；失败时对话框保持打开并在其内显示提示，再次提交时清除。请求中 `取消`、Escape 与遮罩仍可关闭对话框，请求不取消：其后的 200 照常更新列表与面包屑，失败则走列表区顶部提示（被同一会话更新的重命名请求取代的响应除外，见下）；关闭后再次打开的对话框是全新状态。
- `置顶任务` / `取消置顶`：发送 `PATCH {pinned:true|false}`；200 后以响应视图的 `pinnedAt` 更新列表；失败时列表不变并走列表区顶部提示。
- `归档`：发送 `PATCH {archived:true}`；200 后该条目离开默认视图（进入归档视图）；它是当前选中会话时保持选中，主区按 chat-web「会话页」的归档只读呈现；失败（如 409 `会话正在生成，请稍候`）时列表不变并走列表区顶部提示。
- `删除`：打开确认框，标题 `删除任务`，确认按钮 `删除`（危险样式）与 `取消`。说明文字：会话不用临时空间时为 `确定要删除「<显示标题>」吗？删除后不可恢复。`；用临时空间且已加载的列表（含已归档）里没有别的会话与它同 `workspaceId` 时，在其后追加 `临时空间里的文件会一并删除。`；用临时空间且有别的会话共用时追加 `它与其它会话共用临时空间，文件会保留到最后一个会话被删除。`。`取消` 或 Escape 关闭确认框且不发请求，焦点回到打开它的「更多」按钮。确认发送一次 `DELETE`（无 body），请求中确认按钮忙碌禁用、不重复发送；请求中确认框仍可关闭：取消按钮文案改为 `关闭`，框内显示 `删除请求已发送，关闭窗口不会撤销请求。`；请求不取消，其间再次对同一会话打开的确认框仍处于这一忙碌状态。204 后从列表移除该会话、关闭为该会话打开的确认框与重命名对话框；若响应到达时它是当前选中会话，页面 SHALL 关闭其事件流连接、以 replace 移除 `?session=`（保留其它 search/hash，pathname 为 `/`）并回到欢迎态，不显示错误、不再读取该会话的消息；删除非当前会话不改变 URL 与主区。失败时关闭为该会话打开的确认框、走列表区顶部提示并重新读取会话列表。
- `另存为工作空间` 与 `导出记录`：见同名 Requirement。

以响应视图更新 SHALL 只采用响应中该请求所修改的那个键（重命名取 `title`，置顶取 `pinnedAt`，归档与恢复取 `archivedAt`），不覆盖该条目的其它键；同一会话有多个进行中的同类请求时只采用最后发出的那个请求的响应，被取代的响应不更新也不提示；账号切换或离开会话页之后到达的响应 SHALL 被丢弃（不更新列表、不提示）；删除的响应同样如此（不移除条目、不提示、不导航、不重新读取列表）。

顶栏第二态（有当前会话且标题已知）SHALL 经 spa-shell 的 `useTopbar` `actions` 插槽渲染 accessible name 与 Tooltip 均为 `重命名` 的图标按钮，打开同一重命名对话框作用于当前会话；会话页注入的顶栏按钮次序由有序常量 `CHAT_TOPBAR_ACTIONS` 固定为 `重命名`、`对话内搜索`、`产物面板`，页面只从该常量按序构造 `actions`；顶栏 `更多` SHALL NOT 渲染；欢迎态不上报 `actions`。

### Requirement: composer footer 工作空间选择
工作空间选择 SHALL 位于 composer 能力栏的最左侧（权限、上传与专家控件 SHALL NOT 渲染，也不摆禁用占位）。

欢迎态下它是一个选择器：触发按钮的可见文本与 accessible name 为 `任务启动于 <空间名>`，未选择时为 `任务启动于 未选择`（默认）。点击按钮 SHALL 打开弹层，内含：accessible name 与 placeholder 为 `搜索工作空间` 的搜索输入框；选项 `未选择`；以及会话页已读取的该账号工作空间列表中的每个空间（按 `GET /api/workspaces` 的返回顺序；打开弹层不另发请求），显示空间名与 ADR-0011 逻辑路径 `<account>/<dir>`（`account` 取当前 Principal；不渲染空间根路径）。输入框按空间名做大小写不敏感子串过滤（查询先去掉首尾空白；`未选择` 始终保留），无匹配时显示 `没有匹配的工作空间`；每次打开弹层查询为空。当前选中项 SHALL 以 `aria-pressed="true"` 标示。选择任一项 SHALL 关闭弹层、更新按钮文本并把焦点还给按钮；`新建工作空间` 与 `挂载目录到当前空间` SHALL NOT 渲染。没有可用的空间列表时弹层按最近一次读取的状态呈现：读取在途（首次读取，或失败后的重新读取）显示 `正在读取工作空间`；读取失败显示 `role="alert"` 的信封 message 或 `请求失败，请稍后重试`；两种情况下仍可选 `未选择`。选中空间为会话页内存状态（选中会话后再回到欢迎态保留；刷新或离开会话页复位为未选择），作用于其后由欢迎态首次发送发起的创建请求（`workspaceId`）；侧栏 `新建会话` 不发创建请求（见「欢迎页场景胶囊与场景化快捷任务」），也不改变已选空间。选中的空间不在当前已读取的列表中时（列表被重新读取后它已不存在、读取失败或换了账号）按钮显示 `任务启动于 未选择` 且创建请求不带 `workspaceId`——按钮文本与请求体始终一致。按钮显示 `任务启动于 未选择` 时发出的创建请求不带 `workspaceId`，服务端为这个新会话创建临时空间（temporary-workspaces「临时空间的创建」）；临时空间 SHALL NOT 出现在选择器的选项里。composer 锁定期间按钮禁用，已打开的弹层随之关闭且解锁后不自动重开。

选中会话后（会话开始后工作空间即锁定）同一位置 SHALL 是只读标签而不是按钮，文本同样以 `任务启动于` 开头：会话 `temporaryWorkspace` 为 true 时为 `任务启动于 临时空间`；`workspaceId` 为 null（存量的未绑定会话）时为 `任务启动于 未绑定`；`workspaceId` 对应的空间在已读取的空间列表里时为 `任务启动于 <空间名>`；`workspaceId` 非空、`temporaryWorkspace` 为 false 但在已读取的列表里找不到（列表读取中、读取失败或空间已删除）时为 `任务启动于 已绑定空间`。它不可点击、不打开弹层、不发请求，页面不提供更换已有会话工作空间的入口。

#### Scenario: 会话开始后只读
- **WHEN** 打开一个绑定空间 `项目A` 的会话；另一次打开一个 `workspaceId` 为 null 的会话；再一次打开一个 `workspaceId` 非空、`temporaryWorkspace` 为 false、但空间列表读取失败或该空间已不在列表里的会话；再一次打开一个 `temporaryWorkspace` 为 true 的会话
- **THEN** 四者的能力栏分别显示只读文本 `任务启动于 项目A`、`任务启动于 未绑定`、`任务启动于 已绑定空间`、`任务启动于 临时空间`；都没有工作空间选择按钮，点击该文本不打开弹层、不发请求

#### Scenario: 未选择空间发送得到临时空间会话
- **WHEN** 欢迎态按钮显示 `任务启动于 未选择` 时输入并发送，`POST /api/sessions` 返回 `temporaryWorkspace` 为 true 的会话
- **THEN** 创建请求的 body 为 `{"scene":"office"}`（不含 `workspaceId`）；会话被选中后能力栏同一位置为只读文本 `任务启动于 临时空间`；新会话出现在侧栏的 `临时空间` 分组内；选择器的选项里没有任何临时空间

## REMOVED Requirements

### Requirement: 会话 DTO 八键严格解析
**Reason**: 会话视图由八键扩为十一键（`archivedAt`、`pendingApproval`、`temporaryWorkspace`），原名与原键集都不再成立。
**Migration**: 由本规格新增的「会话 DTO 严格解析」取代；`patchSession` / `deleteSession` / `createSession` 的客户端约定原样并入该条。web 解析与服务端三键同一个改动落地，不设兼容窗口。

### Requirement: 分区侧栏
**Reason**: 列表区整体重建：原条文的「置顶 > 空间 > 任务」三分区互斥归属、带计数的 `任务 (n)` / `空间 (n)` 分区与子组、`筛选任务` 按钮、分区不可折叠都不再成立（owner 2026-10-06 决定改为置顶区 + 可折叠分组，可切换按工作空间 / 按时间）；原有三个场景的主题随之消失，不能在原名下改写。
**Migration**: 由本规格新增的「分组侧栏」取代；`新建会话` 按钮、`nav` 的 accessible name `会话列表`、条目的选择按钮与标题回退 `新会话`、与 `GET /api/workspaces` 的并行读取、`未知空间` 与 `没有匹配的任务` 的规则原样并入该条。原场景「三分区互斥归属」由「按工作空间分组」取代，「空状态与未知空间」拆为「空状态」「未知空间与读取失败」，「置顶与取消置顶后的移动」在「分组侧栏」下以同名场景保留（取消置顶后回到所属的工作空间分组或时间分组，不再有 `任务` 分区与计数）。`web/src/features/chat/session-groups.ts` 的三分区归组函数改为按分组方式归组，依赖分区标签 `任务 (n)` / `空间 (n)` 的测试与走查断言改为断言新分组名。

### Requirement: 状态与时间筛选
