## Goals / non-goals
Pure deterministic per-prompt mapping, caller-visible immutable results, failure memory, terminal-once and tool identity. No persistence, process/stream lifecycle, transport chunking, extension UI replies (already OmpProcess), SSE/replay, browser reducer or cross-service imports.
## API and identities
Export createEventState({messageId,promptRequestId}) and applyFrame(state,frame)→{state,events}; export applyFailure(state,message) with the same result shape for a trusted supervisor-observed abnormal exit/iterator failure. messageId is the accepted numeric assistant ID; promptRequestId is the exact nonempty RPC request ID, supplied by the caller, never learned from an arbitrary ACK. State types may remain inferred/internal unless genuinely consumed.
Export one discriminated ChatEvent<StepId extends string|number = number> union, using {type,data} envelopes: turn.start{messageId}, text.delta{messageId,delta}, step.start{messageId,stepId,name,detail}, step.end{messageId,stepId,status,detail}, turn.end{messageId,status}, error{messageId,message}. applyFrame emits ChatEvent<string>[] with stepId=toolCallId. #100 persists step.start, binds toolCallId→numeric DB id and substitutes only stepId to publish ChatEvent<number>; no raw toolCallId is a DB key. This is an internal normalization result, not directly an SSE frame. Replay.gap belongs #91/#103 and is not emitted here.
State is one accepted prompt: accepted messageId/requestId, started flag, ended flag, remembered failure, active/finished tool-call entries with names and initial details. A new prompt gets fresh state; terminal state never restarts from a late agent_start. No module globals, mutable aliasing, input mutations, IO, clock or random calls. Readonly input frames are decoded JSON-like records; no support for circular/class/function/BigInt object graphs. Ignored frames return unchanged state and no events; output objects must not let caller edits alter retained state.
## Frame transitions
- agent_start: first before terminal marks started and emits turn.start; duplicates/maintenance restarts do not reset accumulated failure or re-emit start. Valid text/tool work requires started; terminal/failure may close an accepted prompt before agent_start.
- message_update: only assistantMessageEvent.type=text_delta with string delta emits exact delta for bound messageId; thinking/toolcall updates and malformed shapes are ignored. If message.role is present and non-assistant, ignore; role may be absent in minimal RPC examples.
- tool_execution_start: require nonempty string toolCallId/toolName, first occurrence creates running entry and emits step.start. Duplicate starts do not overwrite or allocate another step. Correlation keys such as __proto__ are ordinary data, not object prototype access.
- tool_execution_end: only a known still-running toolCallId ends once; matching saved name is authoritative, unrelated/unknown/duplicate ends ignored. status failed iff isError===true, otherwise done. Tool failure alone does not fail the assistant turn (model may recover). Detail is the result's compact JSON summary; missing result uses the saved initial detail. No extra events for tool_execution_update.
- message_end: emits nothing. Only message.role=assistant and stopReason error/aborted remembers failure; retain the first observed failure through later successful messages, agent_start and nonterminal agent_end. Use nonempty string errorMessage when supplied, otherwise stable generic 'Agent execution failed'. User/tool message ends do not poison state.
- agent_end with isTerminal===false: no terminal and no state reset. Otherwise (including omitted field) emit done, or remembered error then failed, and mark ended. Repeated terminal/later frames are no-ops.
- response with command=prompt, success===false and id exactly promptRequestId: immediate error then failed, using nonempty string error or fallback. Other IDs/commands, all success ACKs (including agentInvoked:false), prompt_result and unrelated frames are filtered without changing state. Issue83 explicitly filters ACKs; #100 uses runtime's local-only completion outcome to settle store separately, not by treating ACK as agent_end.
- applyFailure before terminal: exactly error then turn.end failed, mark ended; empty supplied message uses generic fallback. After terminal it is a no-op. Runtime converts actual exit/transport errors to this input; no fake process-exit RPC frame is invented.
## Summary and resource rules
Tool start detail is JSON.stringify(args) compact output (missing args→empty string), truncated to at most120 Unicode codepoints, no ellipsis. JSON escapes preserve single-line output; escape actual U+2028/U+2029 if present. End detail uses the same rule for result. Do not split astral codepoints or copy all codepoints just to take120. Input logical frame size is already bounded by decoder; no new frame parser/dependency or bespoke serializer. Text deltas remain verbatim, not accumulated into an ever-growing answer in mapper state.
