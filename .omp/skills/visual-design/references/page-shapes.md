# Page shapes

Choose the page shape from the user's primary outcome, not from the visual style. A shape defines information priority, structural starting point, typical states, and evaluation emphasis.

## Brand landing

**Primary outcome:** turn attention into understanding, interest, and trust.

**Skeleton:** value proposition → product evidence → differentiated capability or narrative → proof → decision path. Do not default mechanically to hero → three cards → CTA when the brief calls for another story.

**Priorities:** product intent, visual/brand expression, credibility, conversion path.

**Typical failures:** generic SaaS template, vague promise, invented proof, product UI hidden behind decoration, dead CTA.

## Product console

**Primary outcome:** help a user safely complete a recurring or consequential task.

**Skeleton:** app shell → task context → primary working region → supporting status/details → persistent or contextual actions.

**Priorities:** clear primary task, information architecture, interaction readiness, permissions, recovery.

**Typical failures:** card wall, excessive whitespace, status without action, hidden filters, disconnected detail panel, destructive action without consequences.

## Data dashboard

**Primary outcome:** help a user judge current state, change, cause, and next action.

**Skeleton:** context/time window → key status or anomalies → diagnostic trend/comparison → contributing detail → investigation/action path.

**Priorities:** information architecture, data provenance, hierarchy, semantic visualization, diagnostic path.

**Typical failures:** KPI wallpaper, decorative charts, missing units/time windows/sources, every metric equal, no path from anomaly to cause.

## Conversational or agentic interface

**Primary outcome:** let a user express intent, collaborate during execution, judge evidence, and recover control.

**Skeleton:** intent/context entry → understanding/clarification → execution status → decision checkpoints → evidence-backed result → correction/continuation.

**Priorities:** interaction readiness, trust/domain fit, responsibility boundary, process transparency, recovery.

**Typical failures:** chat box as the entire product, invisible execution state, confirmation after the risky action, answer without evidence, no undo or correction.

Load `agentic-interaction.md`.

## Content or editorial page

**Primary outcome:** help a reader locate, understand, retain, and apply information.

**Skeleton:** title/context → navigable outline → progressively structured content → evidence/examples → next reading or action.

**Priorities:** scanability, hierarchy, typography, citations, reading rhythm.

**Typical failures:** weak headings, giant uninterrupted prose, low contrast, decorative cards fragmenting the argument, unsupported claims.

## Mobile flow

**Primary outcome:** complete a sequence of touch tasks with limited attention and screen space.

**Skeleton:** platform frame → current task → immediate feedback → clear next action → persistent navigation only when the product requires it.

**Priorities:** interaction readiness, touch targets, platform conventions, progressive disclosure, keyboard/safe-area behavior.

**Typical failures:** desktop UI scaled down, unreachable actions, tiny controls, fake device chrome covering content, state lost between screens.

## Deck or presentation

**Primary outcome:** carry an audience through a sequence of ideas toward understanding or a decision.

**Skeleton:** narrative arc with one idea per slide; vary compositions deliberately while preserving a system.

**Priorities:** product intent, information architecture, visual expression, legibility at distance, navigation and print behavior.

**Typical failures:** document pages on slides, body text below readable size, repeated card grids, six unrelated mini-posters, no decision ask.

## Structural variant rule

Generate variants only when information priority has materially different valid strategies. For each variant state:

- primary user and moment;
- primary region;
- secondary region;
- action placement;
- density;
- tradeoff.

Recommend one. Do not present mere color themes as information-architecture variants.
