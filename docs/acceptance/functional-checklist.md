# 功能验收清单

界面验收的签收对象。每行是一条能在 1 分钟内判定的功能项：照「操作」做，看到「期望」就算过。
它取代按 demo 逐组件比对的 `docs/acceptance/demo-parity-checklist.md`（后者保留为历史记录，不再更新）。

## 运行方式

- 对着一个由调用方启动的真实服务逐项操作：先按 `AGENTS.md` 的命令面把服务跑起来并登录，再按节从上到下走。
- 不依赖截图对比，也不对照 demo 的行号、像素或样式表；判定依据只有「期望」列写的用户可见行为。
- 亮色与暗色主题、桌面与窄屏的差异，只在某一行的「期望」明确写到时才需要分别操作。

## 行格式

每节一张四列表：`ID`、`操作`、`期望`、`结论`。格式由 `web/test/functional-checklist.test.ts` 机械检查。

- `ID`：页面前缀 + `-` + 两位以上序号，如 `SH-01`；前缀写在节标题的括号里，同一节的行都用该节前缀，`ID` 在全文件唯一。
  新增行取该节下一个序号；删除行后序号不回收。
- `操作`、`期望`：写用户可见的行为（点哪里、输入什么、看到什么）。不写 demo 行号引用、不写带单位的像素值、
  不写以点号或井号开头的 CSS 选择器。
  - 凡是点号或井号紧跟字母的记号都被拒，所以 `.env`、`#fff`、`#readme` 这类写法不能出现，改用文字描述
    （如「点开头的环境文件」「页内锚点」）。
  - `/settings`、`/files#readme`、`#643`、`0.5`、`notes.md`、`*.md` 不受限：点号或井号前是 ASCII 字母、数字、星号或斜杠，或其后是数字。
  - 点号或井号紧跟在中文字符、全角标点或括号之后同样被拒，所以中文主干的文件名（如 `笔记.md`）不能照字面写：
    改用 ASCII 文件名（`notes.md`）、`*.md`，或用文字描述（「名为笔记的 Markdown 文件」）。
  - 视口宽度只写数字、不带单位（如「宽度 390」），因为「数字加 px」会被拒。
  - 单元格内需要竖线时写成 `\|`。
- `结论`：只取三种值之一——`待签`、`通过`、`不通过：<说明>`（全角冒号，说明不能为空）。
- 新增一节：标题写成「名称（前缀）」，前缀为两个以上大写字母且不与其它节重复；节内放同样表头的一张表。

## 签收规则

人工执行，review-only，没有机械门禁。

- 交付或改变用户可见功能的 issue，在同一个 PR 里新增或更新对应行，并把结论写为 `待签`。
- 只有仓库所有者本人可以把结论改为 `通过` 或 `不通过`；agent 不得代签。
- 一个 change 的 Epic 在其新增行仍有 `待签` 时不关闭。
- `不通过` 的行须在说明里关联一个修复 issue；修复合入后由仓库所有者重新判定。
