# omp 经 app-server 模型代理访问模型网关，环境零凭证

不变量 4 禁止模型网关密钥进入 omp 子进程可读环境（omp 的 bash 工具可读 env）。决定：app-server
提供 OpenAI 兼容的本地模型代理端点，omp 的 provider baseURL 指向它，环境里只有会话标识；真密钥由
app-server 注入转发，每会话计量/限额/审计**可以**落在代理层（截至 2026-10-03 尚未实现，见文末补充）。会话标识必须是每会话随机生成的
不可猜测 token、仅对该会话有效——它就是该会话在代理处的配额凭证（omp bash 可 curl 本地端口，
可猜测标识意味着跨租户盗用配额）。内网单机下多一跳可忽略。kb-service 的
嵌入/重排调用不走此代理（其凭证本就允许持有，直连网关，避免摄取批量流量耦合 app-server）。

## Considered Options
- 每会话限时 token：少一跳，但依赖网关签发能力（未知），且 token 仍入 omp 环境。
- 共享密钥进环境：直接违反不变量 4，弃。

## 2026-10-03 补充（#800）：会话 token 对获批的 bash 可读——接受并登记

正文已写明「omp bash 可读 env、可 curl 本地端口」；本补充登记读到 token 之后能做什么，以及 owner 接受它的决定。

- **事实**：`WORKBUDDY_MODEL_TOKEN` 在 omp 子进程的环境里（托管 `models.yml` 以变量名引用它，宿主不能不传），omp 把自己的环境原样带给
  bash 工具的子进程（官方 omp v18.0.10 实测：bash 工具进程的 env 含该变量）。任何获批的 bash 命令——以及批准一次 `task` 之后子代理的
  bash——都能读到它，并在回合之外直接调用宿主的模型代理。
- **可达范围**：
  - 只有一条路由 `POST /v1/chat/completions`（`server/src/model-proxy/index.ts`）；够不到上游真密钥（宿主侧注入），也够不到 cookie 鉴权的其它路由。
  - 代理只校验 token 是否有效，不按会话限定请求；请求体原样转发，`model` 不受约束，可请求上游账号开放的任意模型。
  - token 每个进程 generation 一枚，退役即吊销（`server/src/sessions/tokens.ts`）；可用窗口是该 generation 的存活期。
- **与正文的出入**：正文原写「每会话计量/限额/审计顺带落在代理层」。代理层目前**没有**计量、限额、限速或按会话的审计；该句已改为「可以落在代理层（尚未实现）」。
- **决定（owner，2026-10-03）：接受。** 部署在受信局域网；被读走的 token 能做的事不超过该会话本来就能让模型做的事（经同一代理、同一上游账号），
  多出来的只是「不经宿主回合记录」与「可换 `model`」。不清理 bash 子进程的环境（v18.0.10 没有对应设置，且关不掉同 uid 下经 `/proc` 读取的路径），
  不在代理层校验 `model`（model-proxy 规格规定请求体字节原样转发、不做语义解析）。
- **重开条件**：部署模型变为不受信多租户或公网可达；或上游按量计费的配额成为需要按会话强制的约束——届时在代理层实现按会话的计量/限额，
  并校验 `model`。

## 2026-10-14 补充（#909）：代理带回上游失败的净化摘要；首字节期限；慢失败不重试

- **5xx 不再丢细节**：此前代理把上游 ≥500 与一切连接失败都折成自己的 502 `agent_unavailable`、丢弃正文，omp 与用户看不到真实原因。现在 ≥500（504、524 除外）回 502 `{"error":{"message":"模型服务返回 HTTP <s>：<节选>","type":"wb_upstream","param":"status.<s>"}}`，节选是上游正文的净化节选（去控制字符与 omp 的转储路径行，去上游密钥与 base URL 的 userinfo、路径、查询串，去 `Bearer …`、`sk-…`，至多 1000 码点）；快的连接失败回 502 `connect.<原因码>`。两者 omp 照常重试。净化只用代理自己的 apiKey 与 base URL；节选到了 sessions 之后的完整净化（含服务器路径）在 #909 后续组。
- **首字节期限**：发出上游请求后 120 s 内没有响应头，回 424 `no_response`；收到响应头之后不计时。
- **慢失败不重试**（owner 2026-10-14）：10 s 建连期限到期回 424 `no_connect`（此前是可重试的 502）；上游答 504 / 524 回 424 `gateway_<s>`，不带上游正文。这几种回合在一次等待之内结束。
- **实测**（官方 omp v18.0.10 经代理，注入短期限）：三种 424 都只有 1 次上游请求（建连卡住时 1 个连接、0 次请求）、没有 `auto_retry_start`；回合在期限或上游应答之后约 2–3 s（omp 开销）以 `failed` 结束——首字节注入 3 s 时 5.1–5.2 s，建连注入 1 s 时 3.8–4.0 s，上游 2 s 后答 504 时 4.1–4.2 s（各两次运行）。生产缺省下推算：不回响应头约 122 s，建连卡住约 13 s，上游答 504 / 524 后约 2 s。
- **与 omp 版本绑定**：424 与 `no_connect`、`no_response`、`gateway_<s>` 是按 v18.0.10 的三层重试与会话层文本分类器选的（design D6、D7）。升级 omp 时重跑 `server/test/omp-official-upstream-failure.test.ts`：任何一例出现 `auto_retry_start` 或上游请求数大于 1，就要重议信封，不得换状态码或记号名绕过。

## 2026-10-21 补充（s1d-model-registry）：上游凭证按模型存进数据库

- **密钥落 DB**：上游不再只有一对 `MODEL_UPSTREAM_*` 环境变量。每个模型自带 base URL 与密钥，存在 SQLite 的 `models` 表（迁移 046）；环境变量只在表为空时作首次种子。DB 文件是 `0600`（入口的 `preparePrivateDbFiles`，ADR-0010 的专用 uid 下 omp 读不到），与此前「进程环境里的密钥」同级：都是 app-server 进程可读、omp 子进程不可读。密钥明文存放——备份 DB 即备份密钥；加密需要密钥管理，暂不做（YAGNI，重开条件：部署要求静态加密或轮换提醒）。
- **读取面收窄**：store 的行视图不带密钥，只有 `routeOf` 与 `secrets` 两个读返回密钥材料，只供进程内注册表快照使用；管理端点的视图只给 `hasApiKey` 与去掉 userinfo 的地址，审计 detail 不含地址与密钥，发布失败的记录只有 `event` 一个键。
- **按模型净化**：代理按请求的 `model` 查快照里该模型的上游转发；5xx 节选的密钥集是快照里全部已登记上游的密钥与地址各部分，再加本请求所用上游自己的一份（在途期间被换掉或删除的旧值仍被去掉）。
- **会话侧密钥集改接注册表**：sessions 的净化闭包（`app.ts` `upstreamRedactor`）不再只认环境变量里的单一上游，而是在每次净化时现取注册表快照的 `secrets()`——管理员经界面登记的密钥在上游 401 回显时不会原文落进 `chat_messages`。
- **探活：宿主主动发出带密钥的请求**（model-registry「探活」，`server/src/models/probe.ts`）。这是代理之外唯一一处由 app-server 自己向上游发带密钥的请求，边界：只在管理员点下 `POST /api/models/probe?id=` 时发；只发往该模型登记的 base URL（`GET <去掉结尾斜杠>/models`，`Bearer <该模型的密钥>`）；不跟随重定向、不重试；建连 10 s、整体 15 s；非 2xx 正文至多读 16 KiB；写回的摘要经 `upstreamExcerpt` 净化——密钥集为全部已登记上游加所探上游自身的密钥与地址各部分——且 ≤200 码点；审计 detail 只有 `{modelId, status}`，响应、审计、stdout/stderr 不含密钥。
- **接受的风险（owner 2026-10-22 确认接受）**：
  - `PUT` 只改地址、不给密钥时保留已存密钥（model-registry「修改保留密钥与清空上游」），探活随即把该密钥发往新地址——任一管理员（或被劫持的管理员会话）可借此取出 API 从不回显的密钥。
  - 管理员可让服务端向任意地址（含内网）发 GET，并读回 ≤200 码点的净化摘要。
  - 理由：管理员是受信角色，部署在受信局域网。**重开条件**：要求改地址时必须重新给出密钥；或需要限制出站目标（白名单 / 禁内网段）。
