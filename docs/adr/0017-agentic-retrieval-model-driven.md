# agentic 检索的环由 omp 模型驱动，kb 模块只提供单轮检索

ADR-0016 把知识库交给 RAGFlow，同时留了一个问题给 S2b：agentic 环（改写 → 召回 → 充分性判定 → 不足再查）放在 app-server
还是用 RAGFlow 自带的能力。owner 在 2026-11-07 的 S2b grill 中拍板：**环的决策交给会话里的 omp 模型**。`kb_search` host tool
每次调用，只让 app-server `kb` 模块执行一次「单轮检索」（RAGFlow 混合检索，可选重排）；改写检索式、判断证据够不够、要不要再查，
都由模型自己决定，并以多次调用 `kb_search` 的形式表达出来。中心页的「检索测试」跑的是同一个单轮检索，没有环。

## Considered Options

- **app-server `kb` 模块编排**：步骤确定，能一一对上 demo 检索卡的「评估证据是否充分 / 第 2 轮检索」，过滤与审计都在一处。
  不选的原因：改写和充分性判定要么用写死的启发式规则（demo 用的是相似度 ≥0.34 且命中至少 2 条），要么在宿主里再加一个 LLM 调用环。
  而会话里已经有一个会调用工具的模型，再造一个环等于重复建设。
- **RAGFlow 自带的能力（chat assistant / 画布）**：它返回的是生成好的回答而不是原始切片，宿主很难守住 CONTEXT.md 不变量 2
  （只有命中切片和出处进上下文），按可见范围过滤也要绕路。
- **两种都做**（检索测试用宿主环，会话用模型自驱）：同一逻辑会有两套实现，违反 AGENTS.md 的 Code Canonicality。

## Consequences

- glossary「agentic 检索」改为「模型驱动的多轮 `kb_search`」，新增「单轮检索」。PLAN / IMPLEMENTATION_PLAN 里 S2b 的
  Verify「agentic 二轮在构造的不充分场景下真实触发」移到 S2c，由真实 omp 会话证明。
- 轮数不再确定。上限、工具说明如何引导模型「证据不足就改写后再查」，以及 F-CHAT-4 检索卡怎么从 `kb_search` 调用序列里重建步骤
  （每次调用算一轮；「充分性判定」没有宿主侧的来源），这些都在 S2c 定。不变量 2 不受影响：每轮返回的仍然只有切片和出处。
- 检索参数（阈值、权重）按库保存，会话里每一轮检索都按它执行，模型不能逐次调整。
